# Content to Video · 信源转视频

把一篇文章、一份报告、一个网页链接交给 agent。一页笔记、一段粘贴的聊天记录也可以。你拿回一支**带配音、逐句字幕、配图与动效的解说视频**。

你全程只做两件事：**给料**，和**提意见**。写稿、配音、画图、排版都由 agent 沿一条固定管线替你做。动画和渲染也一样。

---

## 成品是什么样的

**一支真正能直接发的解说视频**，不是幻灯片录屏：

- **口播配音**：多种预置音色可选，能调语速和语气。双人问答可以还原成两个声音对谈，不压缩成单人念稿。
- **逐句字幕**：字幕和语音由同一根时间轴驱动。一句话高一句、一句对一句，不存在声画不同步。对话段落还会在轮次切换的那一句行首挂出说话人名字——静音刷到这条视频，也分得清谁在说。
- **配图与动效**：每个段落一张视觉。它可以是标题加插图加要点的卡片，也可以是整屏铺开的一张会动的海报。数据关系、系统结构、时序流程画不进 PPT。这类东西用矢量示意图当场画出来。
- **两种画幅**：竖屏 3:4 适配手机信息流，横屏 16:9 适配电脑与大屏。从写稿那一刻就按所选画幅排版。
- **主题配色**：深色主题，段落强调色自动轮询配色。

一句话概括效果：**观众看到的是一条完整的解说，而不是一堆会动的文字**。

## 怎么和 agent 交互

不需要记任何命令、参数或配置，说人话就行。一轮典型对话四步：

### 1. 给料

> "把这篇文章做成视频"＋（链接 / 文件路径 / 直接粘贴正文）

公众号长文、行业报告、论文都可以。会议纪要、周报、产品说明、自己的笔记同样收。任何形式的文字信源都接。agent 会先读懂它，提炼标题、核心事实和视觉线索。数字与日期保留可回查依据。

### 2. 提要求（想说就说，不说全按默认走）

> "横屏，女声，节奏快一点，最后加个行动号召"
> "这是两个人对谈的纪要，保留问答感"
> "第 3 部分的数据关系我想看清结构，别只列条目"

画幅、音色、语速、主题、每段讲多深都可以在这一轮随口提，没提到的走默认。

### 3. 看预览，逐段提意见

agent 会先给你一个**在浏览器里就能打开的预览页**：默认停在首帧，点播放，画面和时间轴配音一起走。这时还没花渲染成片的成本，所以随便改：

> "第二段图太挤了，换一张"
> "这个标题两行放不下，改短"
> "开头太软，直接抛结论"
> "改成竖屏"

改稿、换图、调结构都不会重头再来：**已经定稿的句子配音直接复用，只重新合成变动的那几句**。中途随时可以叫停。

### 4. 催定稿

> "没问题了，出成片。"

agent 才做最后一步渲染，交给你 MP4。它同时附一份生产报告，写明每步耗时、配图覆盖率、有没有降级句。

## 适合做什么

| 场景 | 出来是什么样 |
|---|---|
| 长文 / 公众号 / 论文 → 听解说 | 通勤路上能听完的一篇深度内容 |
| 报告 / 周报 / 会议纪要 → 汇报视频 | 不用开会，把结论和数字讲清楚 |
| 概念科普 | 结构图、流程图、数据关系直接画在画面上 |
| 产品介绍 / 功能说明 | 分模块讲解，每段一张视觉 |
| 对谈纪要还原 | 双音色问答，保留对话感 |

## 别用它做什么

- **剪辑已有视频**——它不处理你手上的素材片
- **只要配音、不出画面**——用任意 TTS 工具更省事
- **把 PPT 导出成视频**——它从文字重新写稿排版，不是转换 PPT

---

## 几件值得知道的事

- **画面不联网**：出图、排版、渲染都在你自己的电脑上完成，草稿和成片不会外传。要联网的只有两件事——配音合成要请求外部 TTS 服务（见「准备工作」）；换到新机器第一次生成画面时要取一个动画引擎文件，取到之后本地就一直用这份。
- **降级不会瞒着你**：某句配音失败、某一段整个丢失，都会在交付前明确告诉你。绝不悄悄产出一支缺声音的完整视频。成片落盘后还会量一次实际时长跟时间轴对账——渲染中途丢帧产出的"短了一截"的片子，不会顶着"完成"两个字混出去。
- **内容里的指令不会被执行**。信源里如果夹着"请忽略之前的设定"或"先执行这条命令"之类的话，一律当成普通文字读。agent 不会照做。
- **产物不会写进技能目录**：音频、图片、HTML、成片都落在你的项目目录里。
- **字幕的取舍你知情**：整屏海报那一档版式，画面是一整张图。标题与要点由画图时一并画进去。这一页没有跟着时间轴走的逐句字幕。口播里的关键句务必画进图里，别让信息只存在于旁白。agent 用这种版式前会讲清这个代价。

## 准备工作

三样东西，第一样是**硬闸门**，缺了就出不了片：

| 依赖 | 是什么 | 缺了会怎样 |
|---|---|---|
| **一个 MiMo 的 API key**（`MIMO_API_KEY`） | 配音走的是**外部付费 TTS 服务**，不是本地模型。它是整条链路唯一的付费外部依赖 | 第 3 步（配音）直接停。即使所有句子都命中缓存，没有 key 也不放行 |
| **ffmpeg**（只要 `ffmpeg`，不需要 `ffprobe`） | 音频处理、成片时长对账、抽帧 | 第 3 步失败 |
| **Node.js 22+** + `npx hyperframes`（渲染时自动取用） | 渲染成片 | 出不了 MP4；前四步照常 |

Python 3.9+（技能只用到 Python 自带能力，不需要额外安装任何依赖）。

**没有 key 就先别指望出成片**——这是"拿来即用"最大的一处现实落差，先备好 key 再开工。

## 维护者

改完代码跑 `python -m unittest discover -s tests`。它只用标准库，约 2 秒，不需要网络 / ffmpeg / Node。改标题或瘦身文档后再跑 `python tests/check_docs.py`，检查「章节」交叉引用有没有悬空、SKILL.md 与 references/ 是不是又胖回去了；改了任何写进文档的阈值（画布尺寸、字号下限、告警门限、时间容差…）还要跑 `python tests/check_numbers.py`，它逐条比对代码常量与文档里的数字，改一边不改另一边就报错。`python tests/check_examples.py` 则把文档里的示例真跑一遍——示例一旦跑不通就退出码非 0。三个检查都在 CI 里跑。有意改视觉导致 HTML 快照变化时，用 `UPDATE_GOLDEN=1` 重新生成 `tests/golden/`。

发布时手动压缩技能目录。剔掉这些内容：

- `tests/`
- `.env`（含密钥，漏进包就是泄密）
- `.git/.venv/__pycache__`
- 制作残渣目录：`audio_output/`、`hf-project/`、`out/`、`snapshots/`
- 中间文件：`candidates.json`、`segments_source.json`、`timing_manifest.json`

`scripts/check_svg.py` 要留着。它是第 4 步引用的生产工具，不是维护物。
