# 第 3 步 · 惯性档：让速度可见

`beats` 决定这一页演什么 → `references/motion.md`「一、该不该动」；落位曲线怎么选 →
同份的「曲线的行程预算」；落位之后怎么留白 → `references/hold.md`。
**这一份只管一拍之内：物体怎么发力、怎么在途中变形、怎么落地。**

## 一、对标：缺的是速度域，不是又一条位置曲线

本仓库的补间全部写在**位置域**：`y: 40 → 0`、`scale: 1.06 → 1`、`d: A → B`。
这些判据已经很细——首帧位移要 ≥4px、`expo.out` 得配够长的路、两轴异缓动才走出弧、
入场按读序错峰、落位用受控弹簧收住、收拢之后留静止窗口再 2% 慢推。可成片里物体
仍像是**被程序挪过去的**：观众看得到"它到了"，看不到"它怎么到的"。

2026 年前沿 MG 与动画十二原则里，被反复点名的恰好都是**速度域**的三件事：

| # | 原则 | 一句话 | 本仓库此前 |
|---|---|---|---|
| 1 | Anticipation 预备 | 主运动之前朝反方向蓄一下力 | 无；入场一律从起点直接冲 |
| 2 | Squash & Stretch | 形变跟着瞬时速度走，且面积守恒 | 无；`scale` 只做起止值，全程等比 |
| 3 | Follow-through 跟随 | 主体落位后，形变晚半拍才收干净 | 半条：`spring` 管位移过冲，不管形状 |

三者不是三条新补间，是**同一个速度包络的三种读法**。分开写就是三条各自调
`duration` 的补间——`look.md`「三条换版式时会坏的」里点名过这类"手抄同步"：
抄错一条只表现为"看着有点乱"，门禁一条都红不了。

## 二、速度一直是一阶量，只是没被消费

`_ease.curve` 早已把钉固 GSAP 的缓动逐点实采下来；`motion.md` 的行程预算表量的是
"行程 2% 时 / 50% 时 / 走完 90% 用了多久"，`_hold._ease_slope` 量的是 `max f′(p)`——
**速度一直在被计算，只是算完只用来判"够不够快"，从没用来驱动画面。**

这一档把它接上：`v(p) = f′(p) / max f′`，归一到峰值 1，然后同一条 `v` 同时决定
中途的拉伸量。位移仍走 `f(p)`，形变走 `v(p)`，两者从**同一条曲线**来，所以
"形变峰值时刻 = 速度峰值时刻"不是调出来的巧合，是结构上必然相等（判据因此能
钉住，见第七节）。

不写解析导数（比如 `sine.inOut` 的 `π/2·sin(πp)`）：换族换参数时，判据与成片必须
走同一条曲线。另写一份闭式解，就是两份互相对照的实现——一起错的时候测试照样绿，
`decode.md` 和 `spring.md` 都记过这笔账。

## 三、三段几何：预备 → 冲程 → 跟随

一条拍的总长恰等于 step 级 `duration`，三段按比例切，不另立时长：

```
0 ────────── a ────────────────── a+d ────────── dur
   预备 18%          冲程 66%         跟随 16%
   −A·sin(πu)        D·f(p)            D（不动）
   k=−0.35·s·sin(πu)  k=s·v(p)          k=−follow·sin(πu)
```

- `D` = `distance`（带符号，`axis` 决定写 `x` 还是 `y`），`A` = `anticipation·|D|`，
  预备段位移是**反向**的 `−sgn(D)·A·sin(πu)`：出去、回来，端点精确为 0，
  **不改变落点**。
- `k` 是沿运动轴的拉伸比：`scale_along = 1+k`、`scale_across = 1/(1+k)`。
  两者乘积恒为 1——这是 squash & stretch 的第一红线：**形变只能重分配面积，
  不能把物体吹胖**。预备段 `k<0`（压扁蓄力），冲程 `k>0`（拉长），
  跟随段 `k<0`（落地回压），端点全为 0。
- 冲程的位移 `D·f(p)` 就是一次普通落位；`k=s·v(p)` 是它多出来的那一层。

**只收无过冲的 `inOut` 档**（缺省 `sine.inOut`）。`inOut` 有 `f′(0)=f′(1)=0`，
速度包络两端自然归零，形变在段首段尾连续；换 `.out` 档（`power3.out` 起点速度
最大）会让 `k` 从预备段末尾的 0 一步跳到峰值，读成"抽了一下"而不是"冲出去"。
过冲族与弹簧的速度会反号，拉伸变挤压，语义整个翻掉。红线在 `_momentum.validate`，
和 `_hold.validate` 一样放在**消费侧**——`--set` 能把旋钮调坏，护栏不能指望写文档
的人记得。

## 四、被否掉的五个方案

**A. 形变轴跟着瞬时速度方向转。** 双轴位移时速度方向一直在变，前沿做法确实是让
拉伸轴每帧跟着切线转。但 GSAP 的 `rotation + scaleX/scaleY` 会把**整个元素**一起
转过去：一个圆角矩形走 45° 斜线，落地后是斜的。要只转形变矩阵不转元素，得解
`skewX/skewY/scale` 的矩阵分解，而 SVG 里元素自带 `transform` 时还会与它叠加。
这一档因此**只收单轴**（`axis` 二选一），并把"沿速度方向"诚实降级为"沿主轴"；
双轴弧线的轴向旋转留作下一步，不拿一个会转歪元素的假前沿充数。

**B. 写成新的 ease 扩展档。** ease 只改位置曲线，改不了形状；`spring(ζ)` 那条路
能复用注册机制，但拿不到 `scaleX/scaleY`。而且一条 ease 会被所有补间（含 hold
慢推、字幕换句）吃到，作用域根本收不住。

**C. 渲染端 `onUpdate` 每帧算。** 最像"物理引擎"，也最容易让 Python 侧的判据
退化成对着另一份 JS 实现自证。这里走 `morph` 那条老路：**生成期按帧率采样成
离散 `tl.set`**，渲染端零脚本、零回调，逐帧 `seek()` 下每一帧都是时间的纯函数。
截图档只拨 `tl.time()`，墙钟动画与 `onUpdate` 都不保证重算——`count`/`type` 能
用代理补间是因为有专门的 harness 触发，能不依赖就别依赖。

**D. 允许 `repeat` / `yoyo`。** 这一拍自带落位与跟随，重放会把"落定"演成
"又冲一次"；更糟的是采样跨度与 `beat_span` 游标分家，门禁报的时刻与成片差几倍。
契约层直接拒，`stagger` 同理：三段是一条连续时间线，错峰会把它拆成几条各自起跑的
动作。要一组元素各自演，就写多条拍。

**E. 跨段接续时跳过这一拍。** 最容易漏的一处：烘焙只认 `to`/`set`/`attr`，不认
新档的话，接续页第 0 帧元素会**弹回原位**——正是 `motion.md`「数字带单位」那节
说的"不是回弹，是字从来就不在"。`_stage_carry._settle_step` 为此把 momentum 的
收尾态折成 `x`/`y` 平移；尺寸回 1 是面积守恒的必然结果，本来就没有姿态可搬。

## 五、契约与旋钮

`momentum` 是第七种独立"演"，与 `type`/`count`/`morph`/`from`/`to`/`set`/`draw`
互斥，必配 `target`。**没有任何新的稿件键、没有 `--ctv-*` 令牌**：只有写了这一拍
的 SVG 元素会演，缺省全片一个字节都不变（四份 golden 快照照旧）。

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#ball", "duration": 0.8,
   "momentum": {"axis": "y", "distance": -180, "ease": "sine.inOut",
                "anticipation": 0.12, "stretch": 0.18, "follow": 0.10}}
]}}}
```

| 旋钮 | 缺省 | 管什么 |
|---|---|---|
| `axis` | 必填 | `"x"` / `"y"`：位移与拉伸都沿这一轴，另一轴负责守恒 |
| `distance` | 必填 | 主轴位移（SVG 用户单位，带符号），非零 |
| `ease` | `sine.inOut` | 冲程曲线，同时决定速度包络；只收无过冲 `inOut` |
| `anticipation` | `0` | 预备幅度 / 行程，上限 0.35；时长固定占 18% |
| `stretch` | `0` | 峰值拉伸比，上限 0.30 |
| `follow` | `0` | 落位回压峰值，上限 0.30；时长固定占 16% |

三个旋钮全写 0 仍是一条合法的拍：纯位移、`scale` 恒 1，等价于一次 `inOut` 落位。
**红线不是模板旋钮**：拉伸上限 0.30 与预备上限 0.35 写在 `_momentum`，不放进
`_template.py`，`--set` 碰不到。时长比例、采样帧数带（12~240）、面积容差同样是
工程判据，不开放。

`duration` 仍在 step 级（`_timeline` 的口径），`at`/`at_time`/`delay` 照旧；
`momentum` 属于 `_WHOLE_BEAT_KEYS`，相对链 `at_time:"+N"` 的游标按**整段**推进，
不会像纯 `set` 那样停在起点、把下一拍压在还在演的形变上。

## 六、生成期会拦什么

| 现象 | 级别 | 怎么消 |
|---|---|---|
| `momentum` 与 `from`/`to`/`set`/`draw` 同拍 | error | 两条时间线抢同一条 transform 通道，删掉一边 |
| `axis` 不是 x/y、`distance` 为 0 或非有限数 | error | 形变必须有方向，位移不能没有行程 |
| `ease` 是 `.out` / 过冲族 / 弹簧 / `steps` | error | 换 `sine.inOut` 一类无过冲 `inOut` 档 |
| `stagger` / `repeat` / `yoyo` 挂在 momentum 上 | error | 见第四节 D |
| `target` 在 SVG 里找不到 | error | 与其它拍同一条按文件拦的判据 |
| `target` 是 `#cam` | error | 相机层的收尾姿态由 `_fold_camera` 折进子层，只认 `to`/`set`；给它演形变，接续页会静默弹回原位。给主视觉元素单独命名 |
| 面积守恒、峰值对齐、落点精确任一不过 | error（生成期） | `_momentum.is_well_formed` 在发射 `tl.set` 前拦下 |

产物形如一组 `tl.set`：

```js
tl.set("#img-seg2 #ball", {"scaleX": 1.0, "scaleY": 1.0, "y": 0.0}, 2.40)
tl.set("#img-seg2 #ball", {"scaleX": 0.937, "scaleY": 1.067, "y": 21.45}, 2.44)
...
tl.set("#img-seg2 #ball", {"scaleX": 1.0, "scaleY": 1.0, "y": -180.0}, 3.20)
```

## 七、判据落在哪

`tests/test_momentum.py` 一个文件压完，判据全部**从产物里抠补间来读**，不在
Python 侧另写一份"应该生成什么"：

| 判据 | 拦的是什么 |
|---|---|
| 速度包络是纯函数、端点归零、单峰 | 逐帧 seek 下靠累计状态算出的第 N 帧对不上；`out` 档起点跳变 |
| 面积守恒（生成期严格 + 产物有限精度两把尺） | 把物体吹胖；或把正确实现因为截尾误差判红 |
| 形变峰值 == 速度峰值、落在冲程 20%~80% | 渲染端另写了一份包络；蓄力/落地比主运动还夸张 |
| 预备不改变落点、终点尺寸精确回 1 | 接续页第 0 帧弹回原位 |
| 契约层互斥 / 红线 / 白名单 | 两条时间线抢通道、`--set` 调坏旋钮、非法曲线混进成片 |
| **产物级对账** | 从 HTML 抠出的 `tl.set` 序列，锚点、帧数、逐帧变量必须与 `_momentum.frames` 逐项相等；两画幅各验，两次生成字节相同 |
| 作用域与跨段接续 | 没写 momentum 的页零新增补间；接续页烘焙出 `translate(0,-180)` |
| 模板/契约是唯一真源 | 改旋钮产物不跟着走；非法值在生成期就炸 |

## 八、什么时候不要

- **只变一个元素、行程很短**：0.3s 内三段会被压成几帧，读到的是"抖了一下"。
  用普通 `to` + `power2.out` 就够；这一档至少给 0.6s。
- **文字、表格、数据图**：字形被拉长 18% 会读成变形字，一屏对照表更不该变形。
  它适合图形主体（球、卡片、图标、箭头），不适合承载信息的排版。
- **该段已经写了 `animate` 的其它拍在动同一元素**：互斥是契约层硬拦，别绕。
- **整页画布的贴边内容**：形变会按元素 bbox 中心放大，贴边元素先按
  `references/canvas.md` 留够安全边距。

写完跑 `run.py --until html`，产物里应当看到一组等帧距的 `tl.set`，首末两帧
`scale` 都是 1、末帧位移正好等于 `distance`。全片动得对不对仍要按
`look.md`「交付前四道」翻 contact sheet——判词只证明"没有明显坏"。
