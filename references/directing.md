# 第 4 步 · 怎么演：导演编排与跨段接续

本文件是 `references/canvas.md` 的续篇：那一份讲**这张 SVG 怎么画**（几何、对比度、密度、自查），这一份讲**画完之后怎么让它动起来**——`director` 的原语清单、两档动画的取舍、以及下一页怎么接着上一页继续演。只做静态示意图、不打算让它跟着旁白逐拍推进的，不需要读本文件。

> 原语清单很长，但用不到几项就别通读：`at` / `at_time` 是时间锚（必读），`draw` / `count` / `type` / `morph` / `stagger` 按内容挑，运镜（`<g id="cam">`）与 `stage:"keep"` 跨段接续是两段独立能力，用到再读。

## SVG 动画：两档（氛围循环 vs 时间轴同步的「导演」）

动画分两档，选哪档只看一件事——**画面要不要对上某句话**：

**① 氛围循环（墙钟，默认，走 `<img>`）**：CSS `@keyframes` / SMIL 画的流动虚线、呼吸光效、循环位移。观感提升明显，但内部动画按**页面墙钟**自走，**无法与口播时间轴同步**，逐帧渲染时也不保证可复现。所以只用于"一直在动、动到哪儿都行"的氛围层，不要用于"必须在这句话时变成那个状态"。这一档什么都不用写，SVG 里带上 CSS/SMIL 即可，映射仍是普通 `src`。`check_svg.py` 会对墙钟动画打一条 `[warn]` 提醒它不同步。

**② 时间轴同步的「导演」（净化内联，opt-in）**：要"随旁白逐句推进"的状态变化（讲到第 2 句时高亮某个节点、讲到第 3 句时把箭头画出来、数值随句子跳到目标值），就在 images.json 给这张 SVG 写 `director`。写了 `director` 的 SVG 会：

1. **净化后内联成活 DOM**（`scripts/_svg_sanitize.py`）：删掉 `<script>` / `on*` 事件属性 / `<foreignObject>` / **任何带 scheme 的 href**（`http(s):`、`javascript:`、`file:`、`data:`、`blob:` 等一律算外部资源——产物 HTML 常以 `file://` 打开，`file:` 引用会触及本机磁盘；内部 `#id` 片段与相对路径放行）/ `@import`，**把外链 `url()` 整颗换成 `about:blank`**（`style=""` 里和 `fill` / `stroke` / `filter` / `mask` / `clip-path` / `marker-*` 这些**呈现属性**里都一样——别以为只有 CSS 那条路`<rect fill="url(file:///…)"` 照样能触及本机磁盘；内部的 `url(#id)` 不碰），**并剥掉 SMIL 与 CSS animation/transition**（墙钟动画在逐帧 seek 里不可复现，导演档一律由补间驱动运动）。净化让"内联会执行脚本"的风险回到 `<img>` 水位——**这是本节唯一允许内联进交付 HTML 的情形**，且内联前必过净化。
2. **由 GSAP 按句驱动**：`director.steps` 每一步挂在该段旁白某句的起点上，渲染器把它展开成时间线补间（属性补间，逐帧 seek 完全可复现，和标题/配图入场同一机制）。

`director` 结构（键集封闭，写错在契约层直接报错）：

```json
{
  "seg4": {
    "src": "images/seg4.svg",
    "director": {
      "steps": [
        { "at": 0,   "target": "#node-a", "set": { "opacity": 1 } },
        { "at": 0.4, "target": "#curve",  "draw": true, "duration": 1.2, "ease": "power1.inOut" },
        { "at": 1,   "target": "#cam",    "to": { "scale": 2.2, "svgOrigin": "500 360" }, "duration": 1.5, "ease": "power2.inOut" },
        { "at": 2,   "target": "#bar",    "from": { "attr": { "height": 0 } }, "to": { "attr": { "height": 220 } } },
        { "at": 2,   "target": "#spark",  "morph": { "from": "M 0 60 L 40 60 L 80 60", "to": "M 0 60 L 40 10 L 80 60" }, "duration": 0.9 },
        { "at_time": 3.5, "target": "#caption", "from": { "opacity": 0 }, "to": { "opacity": 1 } },
        { "at_time": "+0.4", "target": ".row", "from": { "opacity": 0, "y": 16 }, "to": { "opacity": 1, "y": 0 }, "stagger": 0.12 },
        { "at_time": "+0.3", "target": "#bigNum", "count": { "from": 0, "to": 6.02, "decimals": 2, "suffix": "×10²³" }, "duration": 1.4 },
        { "at_time": "+0.2", "target": "#caption", "type": {}, "duration": 1.8, "ease": "none" }
      ]
    }
  }
}
```

- `at`：**该段内第几句旁白**（0 基句序，不是全片句号），**支持小数 = 句内偏移**。补间位置 = `sentences[⌊at⌋].start_time + (at−⌊at⌋)·duration`，句序部分越界（≥ 该段句数）在生成期报错。

    **整数句序是准的，小数是线性猜的。** 旁白音频逐句拼出来，`start_time` 是算出来的不是估的；但小数假设句内语速均匀，而 TTS 会在标点处插停顿（接口只回整段音频、没有词级时间戳，句内只能估）。实测（22 拍全小数锚反查）：平均每拍偏 0.2 个字、最大 1.2 个字（≈0.15s）；**唯一会放大到 1s 量级的是长句**（超过 ~5s 又带两三个标点），规矩是**别让一句话长到那个份上**（写旁白时就拆成两句），而不是给渲染端加停顿估计。

    真要现场确认某拍踩在哪个词上：

    ```bash
    ffmpeg -hide_banner -i audio_output/sentences/s007.wav -af silencedetect=noise=-35dB:d=0.18 -f null -
    ```

    看 `silence_start` 落在句文本第几个标点后，再决定 `frac` 往前提还是往后推。

- `at_time`：**与 `at` 二选一**（两个都写或都不写契约层报错）。从**该段音频起点**排时间线：写**数字** = 绝对秒；写**相对串** `"+N"` / `"-N"` = 上一条 beat 结束后再 N 秒（首条退到段落起点；只有真会占时间的步才推进游标——有 `from`/`to`/`draw`，或 morph/count/type 这类负责整段的原语，纯 `set` 停在原地）。

    **它与语音没有任何绑定，这是"动画和语音不同步"最常见的来源。** 绝对秒是按某一版配音手算的，重配音、改句长、动 `--gap` 都会让它整体错位，**而不会报错**。相对链只保证步与步之间的节奏，同样不保证对上话。

    **所以：跟旁白走的节拍用 `at`；`at_time` 只留给真不跟旁白的那一拍**（相机推镜、纯节奏卡点）。

    **生成期查三件事**（解析函数 `_timeline.beat_positions` 与渲染端共用，所以门禁算出的落点就是真正执行的那一拍）：

    1. 落在**本页可见窗口之外**（早于本段旁白起点、或晚于下一段起点）→ `[warn]`。引擎按 `data-start`/`data-duration` 硬切 clip 可见性，排在窗口外的补间等于根本没演。
    2. 压在句间静音或段尾静音上的**不报**——那是节奏不是 bug。
    3. **起点在窗内、终点越过下一段起点**的那一拍 → `[warn]`。它被切在半路，作者以为演到的终态在成片里从没出现过。跨度按 `duration × 遍数` 算，**另加 `stagger` 的展开**（一组元素逐个错开，最后那个的收尾比单拍更晚；元素数只有渲染端知道，门禁按下界判：至少多一个间隔）。这一拍若落在 `stage:"keep"` 的接续页上更要紧：接续烘焙把时间轴折到最后一帧，搬走的正是那个没演到的终态。

- `target`：图内**单个 id 或 class 选择器**（`#`/`.` 开头，后接字母/数字/-/_，字母或下划线起头）。作用域自动收到该段容器 `#img-<sid>` 之下，多段内联 SVG 的同名 id/class 不会串台。**class 选择器专为 `stagger` 开**：一条 step 用 `.row` 命中一组同类元素，配 `stagger` 让它们按递增 delay 逐个演，省掉"三条标记写三个 step"。逗号/后代/伪类一律不收（会拆掉"一条 step 打一个简单选择器"的约束）。**target 指的 id/class 必须在 SVG 里真实存在**——落空不是报错而是静默没动画，所以 `gen_hyperframes.py` 生成期按文件拦成 error。
- `draw`：可选布尔。`true` 时这一 step 做**描边自绘**——渲染端用 `pathLength="1"` 归一化任意 path 长度（不需要量 `getTotalLength`），段起点先把描边收起（`stroke-dasharray:1; stroke-dashoffset:1`，视觉上无形），`at` 到时把 `strokeDashoffset` 补到 0，线"自己长出来"。目标必须是**有描边的形状**（`path`/`line`/`polyline`/带 `stroke` 的圆矩形），否则看不见生长效果（无 stroke 就是空）。
- `morph`：**同拓扑 path 形变**（对象 `{"from": "M…", "to": "M…"}`）。一条 `<path>` 随时间从 `from` 变到 `to`，生成期按渲染帧率的 2 倍把中间态采样成一串 `tl.set(attr:{d})` 关键帧——逐帧 seek 可复现，**不引入任何 morph 库**。

    硬约束三条：`from` 与 `to` 必须**同拓扑**（命令字母序列一致、每条命令的数值个数一致，只有坐标不同）；`target` 必须是那个 `<path>` 的 id；不能叠 `from`/`to`/`set`/`draw`。

    `duration` 决定形变跨度，`ease` 决定形状随时间的**缓动手性**（缺省 `power2.out`；GSAP 不会对 set 再缓动，所以曲线由生成期采样定义，档位见下面 `ease`）。`from` 要和元素在 SVG 里画好的 `d` 一致，否则第 0 帧会有一次跳变。

    **做不了的事**：任意两个不相干形状的互转（拓扑不同）仍需外部 morph 库，本技能刻意不做。

- `set` / `to` / `from`：GSAP 补间变量，`draw`/`morph`/`count` 之外至少要有一个。`set` = 瞬时赋值；`from`+`to` = fromTo；单独 `to`/`from` 各走一路。变量只收 **JSON 可序列化**的值（标量/数组/对象，非 CSS 属性如 `r`/`height`/`d` 走 `attr:{}`），**禁任何 `on*` 回调键**（信源不可信，回调等于在渲染页执行任意逻辑）。`attr` 本身**必须是对象**（`{"attr": {"d": "M0 0L1 1"}}`）：标量/数组写法本页不会报错，但跨段接续的烘焙只认对象，非对象会被当成 CSS 属性写进 `style`，让下一页的起始画面从第一帧就是坏的。

- `count`：**数字滚动**（对象 `{"to": 数字, "from"?, "decimals"?, "prefix"?, "suffix"?}`）。一条 `<text>` 的数值从 `from`（缺省 0）随时间缓动到 `to`，`decimals` 定小数位（缺省 0），`prefix`/`suffix` 裹住数字（如 `"≈"`、`"×10²³"`、`"%"`）。"数字跳到 6.02×10²³""百分比涨到 87%"这类效果靠它，不必手搓逐帧。`target` 要指一个 `<text>`；`duration`/`ease` 决定滚动手感。不能叠 `from`/`to`/`set`/`draw`/`morph`。

    实现是**渲染端生成**的代理补间 + `onUpdate` 写 `textContent`——成片逐帧 seek 会触发回调（和字幕高亮同一条 `onUpdate` 路），故 seek 可复现。这里的回调是技能自己写的、只读校验过的标量，与被禁的信源 `on*` 回调不是一回事。

    **手动在浏览器 console 探针时要写 `tl.seek(t, false)`**——GSAP 的 `seek()` 默认 `suppressEvents=true` 会跳过 `onUpdate`（属性补间照常渲染，唯独 count 这种靠回调写文本的看起来"卡住"，容易误判成坏了；字幕高亮同理）。

- `type`：**打字机逐字揭示**（对象，只认空对象 `{}`）。把 `<text>` 里**现成的整段文本**按进度逐字打出来：运行时读该元素的 `textContent` 作源串，`onUpdate` 写 `slice(0, 已打字数)`。

    所以"打什么字"完全由你在 SVG 里写好的 `<text>` 决定，**这里没有任何参数可配**——刻意如此：要改文字就改 SVG，要改快慢就用 step 级 `duration`/`ease`。`target` 要指一个**直接写文本的 `<text>`**（带子 `<tspan>` 排版的复杂文本会被压平成纯文本，别用在这类节点上）。`ease` 缺省取模板（多为 `power2.out`，打字会前快后慢）；**想要匀速打字的手感就写 `"ease": "none"`**。不能叠 `from`/`to`/`set`/`draw`/`morph`/`count`，且 `stagger` 会被契约层直接拒（type 负责整段、没有"错峰"可言）。

    与 `count` 复用同一条 `onUpdate` 代理补间路，所以同样 seek 可复现、零 DOM 改写、不引入新净化面。
- `stagger`：可选，**配 class 目标做一组元素的错峰揭示**。数字（`0.12`=每个间隔秒）或对象（GSAP 原生配置 `each`/`amount`/`from`(`"start"`/`"center"`/`"edges"`/序号)/`grid`/`ease`）。`{"at_time":"+0.4","target":".row","from":{"opacity":0,"y":16},"to":{"opacity":1,"y":0},"stagger":0.12}` = 一组 `.row` 依次浮入。只对有补间的 step（`from`/`to`/`fromTo`/`set`）生效；`morph`/`count`/`type`/`draw` 各自负责整段，`stagger` 会被契约层拒（静默失效与 `repeat`/`yoyo` 挂纯 `set` 同类）。
- `duration` / `ease` / `delay`：可选。缺省 `duration`/`ease` 取模板 `animation.director`（视觉真源单一数据源，别在 JSON 里各处写死）。这三个旋钮连同 `stagger`/`repeat`/`yoyo` **只能写在 step 级**：塞进 `to`/`from`/`set` 的补间变量里会被契约层拒——那种写法要么被渲染端覆盖掉、要么让门禁算的跨度与补间真实跨度分家，两种都是静默的。

- `ease`：缓动档。**能用的档不是照 GSAP 文档抄的**，是拿技能实际钉固的那份 `gsap.min.js` 逐个 `gsap.parseEase()` 试出来的，所以**认不出的档当场报错**——不会留成"作者以为演的是弹一下落定、成片里是平稳落定"。写错时报错会列出全部合法族名、方向写法与四种例外（`none` 不带方向、`steps` 带方向必须给档数、`rough`/`slow`/`CustomEase` 属插件不在 core 目录、`elastic` 两个参数必须 > 0），照报错改即可，不必回查这张表。

    **选档的手感**（报错替代不了的部分）：缺省 `power2.out` 是"慢收"，整期都用它，所有动画就都读成"淡入"。物件**进场**用 `.in`（慢起，像被推进来）、**退场**或落定用 `.out`、来回摆与推镜用 `.inOut`，要弹要跳就 `back`/`bounce`/`elastic`。

    morph 的缓动是生成期采样定义的（GSAP 不会对 `tl.set` 再缓动），用的就是同一族曲线、同一份实现（`scripts/_ease.py`），与补间同手性。

- `repeat` / `yoyo`：可选，让**同一拍演好几遍**（GSAP 的同名补间变量）。`repeat: N` 是"再演 N 遍"，共 N+1 遍；`repeat: -1` 是无限循环，演到这一页被下一页盖过来为止。`yoyo: true` 是来回——第 2 遍倒放、第 3 遍正放，遍数为偶数时正好收在起点。"呼吸/脉动"就是一条步：`{"at": 2, "target": "#halo", "to": {"opacity": 0.35, "scale": 1.08}, "duration": 0.6, "repeat": 3, "yoyo": true}` 让一圈光晕随旁白明灭四次，不必写八条。跟着四条规矩：
  - **跨度按遍数算**（`duration × 遍数`）。相对链 `at_time: "+N"` 的游标、"这一拍会不会被下一页切在半路"的 warn、接续烘焙"最后停在哪儿"读的都是同一个数（`_timeline.beat_span`），不会出现门禁按一拍算、成片演四遍。
  - **只有真会"演"的步能配它**（`from`/`to`/`draw`/`morph`/`count`/`type`）。纯 `set` 是瞬时赋值，重放它在成片里看不出区别，还会让门禁算出的落点变成假时刻，契约层拒。单写 `yoyo`（`repeat` 缺省或 0）也拒：只演一遍时 GSAP 不会回头。
  - **`morph` 不能配 `repeat: -1`**：形变是生成期采样成离散关键帧的，没有终点就无从采样。补间与 `count`/`type` 可以——它们走运行期，GSAP 按时间解析求值，无限循环反而是确定的。
  - **`morph` 也不能配 `duration: 0`**：0 秒采不出中间态，成片里这一步是**瞬跳**而不是"很快的形变"，而作者看到的仍是自己写的那条曲线。补间类步的 `duration: 0` 是"瞬时生效"，合法。
  - **跨段接续按收尾那一头搬**：偶数遍的 `yoyo` 与无限循环各有一套话，见下面「跨段接续」的 `repeat`/`yoyo` 一条。

**觉得"动画和语音不太同步"时怎么查**（别急着重渲染一遍用肉眼看）：

`gen_hyperframes.py … --beat-report` 会为每个导演段打一张对轴表，逐拍列出解析后的绝对秒与它踩在哪儿——`in` 句内 / `gap` 句间静音 / `tail` 段尾静音 / `before`·`after` 窗外。**窗外的那两类就是没在成片里演过的。**（同样的判据平时以 `[warn]` 自动打出来，`--beat-report` 只是把没报警的那些也摊开给你看。表按每一拍的**起点**分类，所以"起点在窗内、终点被下一页切掉"那一类只在 `[warn]` 里有。）

`in` 不等于准：句内 frac 是线性假设，偏差量级与"什么样的长句才会偏到 1s 量级"的实测都在上面 `at` 那一条，这里不复述。怀疑某一拍踩错词，照那条末尾的 `silencedetect` 一行命令定位，**别改代码**。词级对轴要么听一遍，要么换带 word timestamps 的配音接口。

浏览器预览里的偏差另算一回事——`preview.js` 是时间线为主、音频跟随（差超过 0.15s 才硬拉一次 `currentTime`），而成片是逐帧 seek，画面时刻与音频时刻严格相等。

**十二个够用的"演"的 pattern**（都在现有确定性/安全范围内，不需要新原语）：

- **逐句推进**：一步挂一句，`set`/`to` 把该讲到的节点点亮、卡片浮起。这是最基本的"讲到哪儿亮到哪儿"。
- **运镜 / 相机（pan·zoom）**：把要动的场景包进一个 `<g id="cam">`，对它补间 `scale`/`x`/`y`（GSAP 会写成 SVG `transform`，逐帧 seek 确定）。不需要专门的相机字段。

    ```json
    {"at": 0, "target": "#cam", "to": {"scale": 2.2, "x": -300, "y": -120, "svgOrigin": "500 360"}, "duration": 1.8, "ease": "power2.inOut"}
    ```

    上面就是"推进局部"，再来一步 `scale: 1` 拉回全景。

    **焦点没写时渲染器替你钉一个**：注入本页 `#cam` 内容并集中心当 `svgOrigin`，于是运行期、跨段烘焙、出画 warn 三方看到的是同一个点。（GSAP 自己的缺省原点是 bbox 左上角，还跟着别的步的 `from` 飘——一个 `from:{x:-420}` 的入场就能把 bbox.x 从 90 拽到 −40。）**写了 `svgOrigin` 的页面以你写的为准**，那一页什么都不注入。

    **`#cam` 里只放主视觉。** 标题、结论句、公式带、图例条这类"文字带"要留在 `<g id="cam">` **之外**——它们是给观众读的，不该跟着镜头跑；只有被推近的那块图形进相机。真要让某行字跟着推镜，就单独给它一步与相机同步的补间。

    **为什么**：`scale>1` 是以 `svgOrigin` 为中心把整组放大，离焦点越远位移越大。实测一张 1080×1440 画布用 `scale:1.16 svgOrigin:"540 660"` 推镜，页底 y=1362 的标签被推到 1476（画到画面外），页顶标题也贴着边。

    **机器兜住的部分**：生成期 `director_prepare` 会把 `#cam` 里的内容按运镜的**收尾位**投影回画幅，静止时整条被推出画幅的元素、以及切在上下边缘外的文字都会打 `[warn]`（几何在 `scripts/_cam_crop.py`，口径写在它的模块头：只看收尾位，途中出画是合法的入场滑动；只认 `<g id="cam">`；祖先带 rotate/matrix 的子树跳过不猜；满幅底板豁免）。它停在 warn 不上 error，因为"静止位看不见某样东西"也可能是你故意的取舍。

    **机器兜不住的那件事**：它只判"出画"，不判"撞字"——`#cam` 里的图形被推出去以后，可能正好压到 `<g id="cam">` **之外**那行静止的标题/旁白上。所以**留白要按“推完那一帧”算，不是按 SVG 源码算**：把相机收尾位的 `scale`/平移套一遍坐标，再和静止元素的基线比。
- **自绘 + 错峰（draw-on·stagger）**：`draw:true` 让曲线/坐标轴自己长出来；一组元素（`.row`/`.marker`）配 `stagger` 就是**一条 step 逐个错峰揭示**，不必给每条线手写递增的 `at`。多条线要错峰生长也可各给递增 `at`（句内小数最顺手，如 `0.2 / 0.5 / 0.8`）。配合运镜，一段"边讲边画、镜头跟上去"的 3b1b 味镜头就拼出来了。
- **数字滚动（count）**：`count:{from,to,decimals,suffix}` 让一个 `<text>` 的数值"讲到就数上去"——阿伏伽德罗常数跳到 6.02×10²³、百分比涨到 87%、计数从 0 数到 128。这是科普最有说服力的"演"之一，过去只能靠手搓逐帧，现在一步搞定；`suffix`/`prefix` 把单位裹上，`ease` 调滚动手感。
- **逐字揭示（type·打字机）**：`type:{}` 把一条 `<text>` 里现成的整段文字逐字打出来——定义、金句、小标题"讲到才一个字一个字冒出来"。文字写进 SVG，`duration` 决定打完要多久、`"ease":"none"` 要匀速打字手感。它和 count 复用同一条 onUpdate 代理补间路（切片写回，零 DOM 改写），所以同样 seek 可复现。
- **自由场景（整页画布 × 导演 = 一整个可编排的画面）**：给段落写 `layout: "canvas"`，这一页的标题层与句子流层连 DOM 都不生成，整屏就是这一张图；再给它写 `director`，于是**整页变成一个你自由编排的舞台**。这是技能里最接近 3b1b"演"的写法，也是它**不需要第四档版式**的原因：canvas 已经把模板网格拆干净，director 负责在上面任意编排。

    文字/图元全画在 SVG 里，要什么时候出现用 `at_time` 按秒排：

    ```json
    {"at_time": 0.6, "target": "#title-line", "from": {"opacity": 0, "y": 20}, "to": {"opacity": 1, "y": 0}}
    {"at_time": 2.4, "target": "#cam", "to": {"scale": 1.8, "svgOrigin": "500 360"}, "duration": 1.6}
    ```

    **代价一：旁白句子默认不上屏。** 需要文字就画进 SVG（大标题、结论句本来就该在图里）。这一档没有"页底字幕带"可以要——模板那一层在整页画布根本不生成。

    **代价二：整页画布不走模板转场。** 擦除时长被强制归零，整页在自己的音频起点硬切出现，旧页直接被盖住而不被掀走。（理由是擦除/剥离属于图层级翻页语言，和导演在一页内部逐拍揭示抢叙事，见 `references/rendering.md`「动画」的整页画布条目。）

    跟着来的实操是**第一拍要尽早落子**——切过来的一瞬间画布是空的（导演从 opacity 0 起步），所以把整页的底图/坐标轴/标题放在 `at_time` 最靠前的一拍（0.1s 量级，与 `canvas.md`「整页画布的密度与层次」同一口径），别让观众盯着空页。
- **形变（path morph·同拓扑）**：`morph:{from,to}` 让一条 `<path>` 随时间改变形状——"柱子长高"用同一个矩形 path 换 y 坐标、"折线被拉直"用同一段折线换点、"示意图 A 态到 B 态"只要保持命令序列一致就能演。它把最缺的那种"演"补上了，且**仍是逐帧可复现的、零依赖的**（生成期把中间态烘焙成 `tl.set(attr:{d})` 关键帧）。约束只有一条：起止**同拓扑**，见上面 `morph` 键。
- **立体感（投影多边形 + morph，不是真 3D）**：SVG 没有 Z 轴，但解说里的"立体"从来只是**把三维点投影到画面坐标**。等距（`x=(u−v)·cos30°`、`y=(u+v)·sin30°−w`）或单点透视都能手算。

    **画法**：同一个物体在 2–3 个姿态下各写一条**同拓扑 path**，用 `morph:{from,to}` 串起来。"立方体翻一面""坐标轴倾斜一下""晶格换个朝向"本质就是逐点 reshape，morph 恰好最擅长这个。

    **为什么走这条路而不是 three.js**：投影出来的仍然是一张可解析的 SVG，图内字号、对比度、空带、运镜裁切这些门禁照常生效；WebGL 是一块像素缓冲，那些检查在它里面一条都没有判据，交付页还要多背一条离线钉固依赖。

    **做不了的别硬凹**：连续平滑自转的真透视曲面是真 3D 的活，硬用投影串姿态会抖——那种镜头改成"两个姿态 + 一次 morph"，比"让它转起来"更好读，也更便宜。

- **呼吸 / 脉动（`repeat`·`yoyo`）**：一圈光晕随旁白明灭几次、一条警戒线来回闪、一个数滚上去又滚回来——都只要**一条**步配 `repeat`/`yoyo`，不必为每一遍写一条。收尾停在哪一头由遍数说话（`yoyo` + 偶数遍回到起点），而这个数同时是相对链的游标、出窗 warn 的右界与跨页接续搬走的那个状态，所以"这一拍演完是什么样"在门禁和成片里是同一个答案。想让观众看见"重复"就想让某一拍明显比兄弟短：`duration` 0.4–0.7s 的往复最像呼吸，1.5s 的往复只会读成"它还没演完"。
- **聚光（压暗对照组，而不是点亮主角）**：要"讲到哪儿看到哪儿"，给**其余那组**一步 `to: {"opacity": 0.25}` 比给主角加一步"亮起来"更省——主角本来就看得见，压暗别的才产生亮度差，而且被压暗的那些还留在原位，回到全景时不必重画。配 `stagger` 让一组 `.dim` 错峰暗下去，一句"这三条路里只有中间那条走得通"就是两步。
- **两层视差（推镜时前后景不同速）**：背景那层给 `scale: 1.05`、主视觉给 `scale: 1.3`，同一个 `svgOrigin`，推近时两层错开速度，画面立刻有厚度。运镜自查只认 `<g id="cam">`（口径见相机那一条），所以第二层不在它的视野里——推近幅度要按**收尾位**自己套一遍坐标。
- **歪元素而不是歪相机**：要"这一项被推翻/被审视"的观感，给那个元素一步 `rotation: -4`，别给相机转角度。相机一转，整页连文字带一起斜，读起来是"页面坏了"；单个元素转，读起来是"它在被掂量"。相机只负责推与移，方向感交给元素自己。

导演档的边界：

- **只对 `.svg` 生效**（其它素材没有可被逐帧驱动的图内命名元素）；非 SVG 写 `director` 契约层直接拒。
- **初始状态自己画**：补间只负责"从 A 到 B"，元素在图里的起始样子（比如要最后才亮的节点写 `opacity="0"`）要作者在 SVG 里画好，导演在句子到来时把它推到目标态。`draw:true` 是唯一的例外——dash 的起收它自动配（`pathLength` 归一），作者只要给有 stroke 的形状。
- **墙钟动画会被剥掉**：同一张 SVG 里既写 CSS `@keyframes` 又写 `director`，前者在净化时被删（`check_svg.py` 与生成期都会 warn/告知）。要氛围循环就别写 `director`，走 ① 的 `<img>` 那档。
- **决定性与安全都由净化 + 补间保证**，不需要再退回"交付必须 `<img>`"那条老规矩——那条规矩的前提是"内联=执行未净化脚本"，导演档内联的是净化后的 SVG。

**版式跟着该段内容的逻辑走**，不要每期都落到"两个方块加一支箭头"上：时间演化用时间轴，机制因果用带箭头的流程，层级用树，占比用环形或堆叠条，对照用双栏。骨架类文件只提供画布几何、背景（不铺满幅底）与取色三条约束（见下面三节），具体摆什么图形由旁白决定；同一期里几张示意图长得一模一样，就是没做这个判断。

## 跨段接续（images.json 的 `stage: "keep"`）：下一页接着上一页演

一个舞台上的动作常常一句话讲不完，但段落边界是硬的：每页各自内联一份 SVG、各自从 `opacity="0"` 起步，于是"推进局部"这一页演完，下一页切回去就把全景重画一遍，观众看到的是**回弹**。给接续页写 `"stage": "keep"`，这一页的起点就不再是盘上原图，而是**上一页演完的那幅画面**。

```json
{
  "seg2": {"src": "images/stage.svg", "director": {"steps": ["… 最后一拍是 #cam 推近 …"]}},
  "seg3": {"src": "images/stage.svg", "stage": "keep",
           "director": {"steps": ["… 在推近后的画面上继续演 …"]}}
}
```

机制（口径在 `scripts/_stage_carry.py` 的模块头）：生成 HTML 时按 manifest 段序再走一遍，把上一页所有补间的**收尾态**烘焙进这一页的内联副本——相机姿态折成 `#cam` 内新增的一层静态 `<g data-ctv-stage transform="…">`（**不写进 `#cam` 自己的 transform**，否则本页导演对相机的补间会踩在一份被改写过的起点上），元素级的 `opacity`/`attr` 落到各自节点的起始属性，`x`/`y` 平移折成元素 `transform` 前面的一层外层平移（`translate(dx,dy) 原串`，原串一个字不动地留着当本段补间的基值）。

实测（三段链 1080×1440、12fps 逐帧取样）：**页界那两帧在配图区完全重合**——柱子与坐标轴的边沿在切页前后一字不差。**量连续性要按柱子边沿定位，别拿整幅 PSNR 当判据**：每页 `--seg-accent` 不同，模板的氛围光与进度条在切页那一帧整幅换色，整幅 PSNR 停在 26 dB 是配色差异不是画面没接上。

约束：

- **两页的 `src` 必须指向同一张图**（不同路径无从烘焙）。接的是谁、是不是同一张，由 `gen_hyperframes` 按段序判，判不过就是点名到段落的 error。
- **上一页必须写了 `director`**——写了才净化内联，`<img>` 那份没有可读的元素态。接续页**自己可以不写** `director`：一段演完、下一页只是"停在那幅画上说话"是合法演法，那种页 steps 为空，画面照样接续。
- **元素级 `transform` 只接 `x`/`y`**：平移跟原点无关，能精确折成元素 `transform` 前缀的一层外层平移（`translate(dx,dy)` + 作者原串，原串一个字不动地留给本段当基值）。`scale`/`rotation`/`skew`/`xPercent` 仍跳过并打一条 warn——那要以元素自己的 bbox 中心为原点折算，而中心是"占位盒"估的（口径见 `scripts/_cam_crop.py`），宁可少接一样也不悄悄挪位。元素自身写了 `rotate`/`matrix`/`skew` 时连 `x`/`y` 也接不动（平移基值读不准），同样出声。
- **`repeat` / `yoyo` 按收尾那一头接**：`yoyo` 且遍数为偶数的那一拍本来就回到起点，接续页什么都不搬（这是对的，不是漏搬）；写了 `repeat: -1` 的那一拍**没有收尾态**，不搬并点名到 target 出声。相机上有一条无限循环，整台相机的收尾位就不作数（不折 `<g data-ctv-stage>`），因为那一页的镜头根本不停在任何一处——编一个姿态折过去比不折更容易查不出来。
- **接续页不要给 `<defs>` 里的元素写补间**（渐变/滤镜/marker/`<symbol>`，以及任何被 `url(#id)`/`href="#id"` 引用过的 id）：同一张 SVG 内联两份后图内 id 重复，而图里的引用按文档序只认第一份（= 上一页那一幅），这一拍打在本页这份上没有任何图形会去读它。生成期按步报 error，别靠"反正看不见"。要延续渐变/滤镜的状态就在前一段写。
- **相机绕的那一点是渲染器钉的**（这条是"页界不跳"的前提，不是可选项）：作者整页没写 `svgOrigin`/`transformOrigin` 时，渲染器给相机步注入**本页 `#cam` 内容并集中心**当 `svgOrigin`（`_cam_crop.cam_default_origin`），跨段烘焙与上面那条出画 warn 算的就是同一个点。GSAP 自己对没写原点的 SVG 元素绕的是 `#cam` bbox 的**左上角**，那个角还跟着别的步的 `from` 瞬态飘（一个 `from:{x:-420}` 的入场就能把 bbox.x 从 90 拽到 −40），不钉死就在接续页界上留一次纯平移阶跃（三段链实测 24~36px，柱子宽高不变所以只有位置跳）。**写了原点的页面一律以你写的为准**，那一页什么都不注入。

跟着来的两处行为变化（做 `keep` 时才补的，都在渲染端）：接续页**不走擦除**（wipe 强制归零，与整页画布同一条硬切路径），也**不生成配图入场补间**（`#img-{sid}` 的淡入 + 上移 40px 正是"页界回弹"的本体）——起点既然是上一页演完的样子，再演一次入场就是穿帮。
