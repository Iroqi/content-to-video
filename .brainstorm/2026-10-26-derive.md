# 2026-10-26 · 走向 3b1b：把"讲什么"从旁白里搬到画面上（构图语法层）

本轮是**对标 3Blue1Brown 的一轮结构性对标**。不是加动效，是补一层仓库里完全没有的
东西：**画面本身的语法**。一句话概括目标——

> 现在这套管线能保证"每一页都有东西、都在动、都和旁白对得上"；
> 3b1b 保证的是"**每一页都在用画面讲那句话**"。

前者的反面是空页、死帧、错位（观感门禁已能证伪）；后者的反面是**画面与台词各说各的**
（现在没有任何一道门禁能证伪，因为画面里根本没有"台词所讲的那个东西"）。

---

## 一、3b1b 的画面语言拆成七个可实现的部件

先把它拆到"能写成判据"的粒度。每一件都标了本仓库的现状，以及对标的入口。

| # | 3b1b 的做法 | 它解决什么 | 本仓库现状 | 对标的入口 |
|---|---|---|---|---|
| 1 | **一屏一句**：一个镜头只承载一个数学事实，讲下一句就换构图（不是叠东西） | 观众永远知道该看哪里 | 段落 = 4~20 秒，一张图 + 一句话流；段内只有一个静态图 | `layout:"canvas"` + `director`，但要求**整页重画** |
| 2 | **每个视觉事件绑定一句话**（"现在，把这两个向量加起来"） | 画面不会抢跑、不会迟到 | 已有 `beats`（台词板）——**这一件仓库做对了**，比 3b1b 的剧本还严格（`on` 必填、越界 exit 2） | 已存在 |
| 3 | **变化是连续的**：参数从 0 扫到 1，观众看见"为什么是这个结果"，而不是"结果长这样" | 理解而非记忆 | `count` / `morph` / `draw` 各自都能做，但**没有"一条参数驱动整张图"的机制**——要变三个元素就写三条补间，还要求它们同步 | 缺 |
| 4 | **同构两态**：A 态与 B 态用同一套几何，只换坐标 | 让"变形"读得出来，否则是两张图硬切 | `morph` 有，但只支持**单条 path**，`from`/`to` 手抄；一张图里十个元素要变，抄十遍 | 缺（局部） |
| 5 | **几何约束门禁**：箭头不出画、标签不压线、字不叠字 | 画面"看起来是对的" | 有三道：出画 `warn`（`_cam_crop`）、压字 `error`（生成期 `zorder`）、对比度（`check_svg` 静态）。**标签压线、箭头指向、同轴对齐均无** | 缺（局部） |
| 6 | **视觉真源单一**：全片一套"颜色 = 含义"的语义色、一套字号节奏 | 观众把颜色读成信息 | 缺省 accent 沿"情绪色温弧"按段序取——**颜色是进度信号，不是语义信号**；相邻两段色相可差 60°，而"增长率"在两段里各是一支色 | 缺 |
| 7 | **画布优先**：`canvas` 是默认真相，而不是"高级档" | 保证画面主导 | `canvas` 是 opt-in，且要付出"没有标题层、没有句子流、两画幅各画一张"三份代价，所以**实际稿子里几乎没人用** | 设计问题 |

一句话结论：**第 2 件我们做到了，第 3/4/6 件是"有原语但没有机制"，第 5 件是"有三道但有四类漏洞"，第 1/7 件是"付不起代价"。**

## 二、为什么"再加原语"不会缩小差距

天真的做法是继续堆原语（再给 director 加一个 `rotate`、加一个 `glow`）。但这在
3b1b 的尺度上无效，原因是**三条结构性错配**：

### 1. 补间是"逐属性手写"，而 3b1b 是"逐参数演绎"

3b1b 的镜头脚本里，一个场景有一个**主参数** `t ∈ [0,1]`（"把 θ 从 0 转到 2π"），
所有几何都由 `f(t)` 算出来。我们的 `director.steps` 是**属性级**的：

```json
{"at": 1, "target": "#vx", "to": {"attr": {"x2": 430}}},
{"at": 1, "target": "#vy", "to": {"attr": {"y2": 210}}},
{"at": 1, "target": "#sum", "to": {"attr": {"d": "M…"}}}
```

三条补间要**同一时刻开始、同一缓动、同一时长**才对得上——而这件事没有任何门禁检查，
作者抄错一处就是"两个元素不同步地长"。这在 3b1b 里根本不会发生，因为那里只有一个数。

**推论**：迭代方向不是"更多原语"，而是**"一个参数驱动一组几何"**。这是 `morph`
的推广：`morph` 已经是"同拓扑 path 换坐标"，只是被钉死在一条 path 上。

### 2. `canvas` 的代价让"画面主导"变成奢侈品

`layout:"canvas"` 要求：① 两画幅各画一张；② 标题自己画进图；③ 丢掉句子流（听障/
静音观众只剩画面）；④ 一张图里同时承担标题、主视觉、注脚三层。

3b1b 没有这些问题，因为他的**画面本来就是唯一载体**（没有"配图槽"这个概念）。
我们的槽位版式则是"文字主导 + 一张配图"，画布版式是"图主导 + 什么都没有"——
中间缺一档：**图主导，但保留最少的文字层（标题 / 关键式子 / 一句字幕）**。

### 3. 颜色是"进度"而不是"含义"

色温弧（`2026-10-20-emotion-temperature-arc.md`）解决的是"段落之间要有方向"。
但它把**唯一的一支 accent 给了段落**，于是同一段里"营收"和"成本"只能用同一个色相
区分，观众读到的是"这两个东西是一类"——这是错误信息。

3b1b 的做法相反：**全片一套语义色板**（蓝 = 输入、红 = 输出、黄 = 当前焦点），
段落只决定明度/氛围，不决定色相。这跟色温弧并不冲突——冲突的是"一个 accent 变量
同时承担了两件事"。

## 三、本轮做的一件（以及为什么只做这一件）

按"一件真做、其余留作候选"的规矩，本轮挑的是**第 3/4 件的合流**：

> **`derive`：一条参数驱动的几何演绎。**
> 在 images.json 里给这张 SVG 声明"哪些属性是参数、参数取什么范围、几何怎么由它们
> 算出来"，然后**一拍只写参数**，几何自动跟着走。

它一次解决三个已存在的病：

| 病 | 现状 | `derive` 之后 |
|---|---|---|
| 多元素不同步 | 三条手写补间，缓动/时长各写一遍 | 一拍一个参数，所有几何同一时刻同一曲线 |
| 中间态不可见 | `to` 只给终点，中间的形是插值出来的（线性或 ease），**不是"这个参数等于 0.5 时真正的样子"** | 每一帧都按参数真值重算几何——真正"扫过去" |
| 要可见的中间态就得写 `morph` | 得手抄 A、B 两态且同拓扑 | 只写公式 |

**它和 `morph` 不是一件事**：`morph` 是把两条路径之间**插值**（视觉上顺滑，但不是
真几何）；`derive` 是**代入参数重算**（视觉上就是真几何，比如"圆心在圆上转"走的是
圆，不是弦）。

### 设计（实现前的定稿）

```json
{
  "seg4": {
    "src": "images/seg4.svg",
    "derive": {
      "params": {"theta": 0},
      "steps": [
        {"at": 1, "param": "theta", "to": 90, "duration": 1.2, "ease": "sine.inOut"}
      ],
      "bind": [
        {"target": "#arm", "attr": "x2", "expr": "540 + 260*cos(theta*pi/180)"},
        {"target": "#arm", "attr": "y2", "expr": "720 - 260*sin(theta*pi/180)"},
        {"target": "#tip", "attr": "cx", "expr": "540 + 260*cos(theta*pi/180)"}
      ]
    }
  }
}
```

- **`params`**：初始值，必须是有限数字。键名 `[A-Za-z_][A-Za-z0-9_]{0,31}`（它要进表达式）。
- **`bind`**：`attr` 白名单 = `x y cx cy r rx ry x1 y1 x2 y2 width height transform`；
  `d` / `points` 是复合几何（要整条重写路径）、颜色与透明度归 director，都不收。
- **表达式**：`+ - * / % ^ **`（`^` 是乘方且右结合）、常量 `pi tau e`、白名单函数
  `sin cos tan asin acos atan sqrt abs floor ceil round exp log min max pow`。
  **不执行任何 Python**（`eval` 带 `{"__builtins__": {}}` 仍能被 `().__class__` 打穿，
  所以自己写 tokenizer + 递归下降；信源不可信这条红线在这儿不开口子）。渲染页里
  同样不出现 `eval`：表达式在**生成期**就编译成 JS 字面代码。
- **`steps`**：复用 director 的锚点与节奏写法（`at` / `at_time` 二选一，`duration` /
  `ease` / `delay`），但载荷只有 `param` + `to`（+ 可选 `from`）。时间轴解析走同一个
  `beat_positions`，句序越界同样 exit。**`duration` 必须 > 0**：参数演绎每帧都是重算
  出来的，时长 0 会让整段退化成一次瞬跳。
- **起点态**：SVG 里画的是 `params` 取初始值时的样子；生成期按"唯一命中的单 id 绑定"
  核一遍静态值，对不上打 `[warn]` 并给出差值（否则第一帧会跳一下）。

### 为什么它不破坏既有契约

- 不引入新的时间源：`at` 还是句序，越界还是 exit。
- 不引入新的内联路径：`derive` 与 `director` / `evolve` 一样要求净化内联
  （同一份 `sanitize_svg_for_inline`），安全水位不变。
- **逐帧可复现**：每个绑定属性的值只由 `(时刻 → 进度 → 参数 → 表达式)` 决定，无状态、
  无缓存，乱序 seek 幂等。实现是一条**代理补间**：每拍一个 0→1 的进度变量，
  `onUpdate` 里按全部进度重算并 `setAttribute`——所以三拍串联天然接着前一拍的终值走。
- 与 `director` **可以共存**（一个管出场、一个管连续演绎），但同一个属性不能同时被
  两者写：两条时间线都写它时先写的白写，且谁后写取决于脚本挂载顺序——生成期按
  error 拦下并点名是哪一步。

## 四、候选清单（本轮**不**做，但按优先级排好）

优先级依据：**它替观众解决多大的困惑** ÷ **实现代价**。前三项的解读如下。

### A. `layout: "plate"`：图主导但保留一层文字（P0，下一轮）

解决「二-2」那条错配。一页 = 满幅主视觉 + **一条** 标题带 or 式子带（单行，
32–48px）+ 一句字幕（仅当前句，不做句子流）。它填的是 `slot`（文字主导）与
`canvas`（无文字）之间的空档，正是 3b1b 每一帧的样子。

代价：一个新版式要过渲染器三处（卡装配、句子流层是否生成、门禁的版式分派），
而且要重答"句子流不是动词的时候字幕挂哪"。**它比 `derive` 贵**，所以排在后面，
但它比 `derive` 更接近"看起来像 3b1b"。

### B. 语义色板：颜色从"进度信号"升级成"含义信号"（P1）

- 顶层新增 `palette: {name: accent}`（可选），全片一套；段落 accent 保留，但降级为
  "本页氛围光"。
- `canvas_kit` 与 `check_svg` 认得这套名字，图里写 `fill="var(--ctv-c1)"` 或
  `data-role="input"`，生成期替换成真色。
- 收益：一张图里"输入/输出/当前焦点"三种东西终于能有稳定的三种颜色，且**跨段一致**。
- 风险：与色温弧的交互（每段明度不同、色相固定）——需要一次设计，不能拍脑袋。

### C. 几何门禁补四类漏洞（P1，可与 A/B 并行）

现在能查"出画 / 压字 / 对比度"，查不到：

1. **标签压线**：文字 bbox 与任何描边元素的 bbox 相交（箭头穿过文字是 3b1b 最忌的）。
2. **箭头指向**：写了 `marker-end` 的 line/path，其终点是否落在被指对象附近
   （落空就是"箭头指着空气"）。
3. **同轴对齐**：同一组元素（同 class）的基线/中心线偏差 > 2px 就报——3b1b 的图
   几乎全部严格对齐，这是"看起来专业"最大的一条来源。
4. **主视觉占比**：整页画布已有"占页宽 ≥70%"的文档判据，但**没有机器实现**；
   槽位版式完全没这条。

前两类的做法都是现成的：`shape_bbox` + `_svg_text_metrics` 已经在手，
只差一个"相交 + 距离"的判据与阈值标定。

### D. 一屏一句的自动拆页（P2）

`dead_seconds` 判词现在只会说"这一段该动"。更接近 3b1b 的做法是**把一段拆成两页**
（短页 = 一次一件事），但拆页要重新配音（时间轴按段切）。断点可以自动找：
段内句子数 ≥4 且句间语义断点明显（连接词"那/所以/接下来/但是"开头）时建议拆。
——这条只有建议，不自动执行；自动拆页会改时间轴，是本技能红线。

### E. `canvas` 的"一次画两画幅"降价（P2）

现在两画幅必须各画一张，所以绝大多数稿子直接放弃 `canvas`。可以学 `canvas_kit`
的办法：给一个 `--aspect auto` 的**布局重排**规格（同一份元素清单，按画幅重算坐标），
让作者只写一份。但这会引入"同一份 spec 两个版式"的调试成本，且与"按原尺寸画"这条
红线相冲，需要一次完整设计。

### F. 明确不做的

- **真 3D（three.js）**：产物会从可解析 SVG 变成不透明 canvas，`check_svg` /
  `_stage_carry` / `perceptual` 全部失明。3b1b 自己的 3D 是离线渲染的，我们不做。
- **LaTeX 排版**：公式继续走 `<text>` + `tspan`（26px 下限已守住）。引入 MathJax
  会把"逐帧确定"变成"等字体加载"，与渲染确定性冲突。
- **手写动画 DSL**：`derive` 的表达式已经是能力上限；再往上就是一门语言，而它的
  使用者是 agent，不是人。

## 六、留给下一轮

1. **A（`layout:"plate"`）** 是"看起来像 3b1b"的最近一步，但它是版式改动，要连带重答
   句子流与门禁分派。
2. `derive` 的**几何门禁**：现在只查"端点算不算得出来"，查不到"这个演绎在画面上会不会
   出画/压字"。`_cam_crop` 的投影思路可以复用，但要先解决"参数在整段里的极值"。
3. `derive` 目前**一个属性一条 bind**。三角恒等式里同一段表达式会在多条 bind 里重复，
   可考虑允许 `bind[i]` 引用前面 bind 的结果（一条"派生量"），但要先想清楚它与
   `params` 的区别，别把表达式语言做成编程语言。
