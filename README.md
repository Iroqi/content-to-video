# Content to Video · 信源转视频

把一篇文章、一份报告、一个网页链接、一页笔记，甚至一段粘贴的聊天记录，交给 agent——拿回一支**带配音、逐句字幕、配图与动效的解说视频**。

你全程只做两件事：**给料**，和**提意见**。写稿、配音、画图、排版、动画、渲染，都是 agent 沿着一条固定管线替你做掉的事。

---

## 成品是什么样的

**一支真正能直接发的解说视频**，不是幻灯片录屏：

- **口播配音**：多种预置音色可选，能调语速和语气；双人问答可以还原成两个声音对谈，而不是压缩成单人念稿
- **逐句字幕**：字幕和语音是同一根时间轴驱动，一句话高一句、一句对一句，不存在"声画不同步"
- **配图与动效**：每个段落一张视觉——可以是"标题 + 插图 + 要点"的卡片，也可以是整屏铺开的一张会动的海报；数据关系、系统结构、时序流程这类画不进 PPT 的东西，用矢量示意图当场画出来
- **两种画幅**：竖屏 3:4 适配手机信息流，横屏 16:9 适配电脑与大屏，从写稿那一刻就按所选画幅排版
- **可选后期**：背景音乐、人声响度归一化，交付标准 MP4
- **主题配色**：深色调与米白浅色调两套，段落强调色自动轮询配色

一句话概括效果：**观众看到的是一条完整的解说，而不是一堆会动的文字**。

## 怎么和 agent 交互

不需要记任何命令、参数或配置，说人话就行。一轮典型对话四步：

### 1. 给料

> "把这篇文章做成视频"＋（链接 / 文件路径 / 直接粘贴正文）

公众号长文、行业报告、论文、会议纪要、周报、产品说明、自己的笔记——任何形式的文字信源都可以。agent 会先读懂它，提炼标题、核心事实和视觉线索，数字与日期保留可回查依据。

### 2. 提要求（想说就说，不说全按默认走）

> "横屏，女声，节奏快一点，最后加个行动号召"
> "这是两个人对谈的纪要，保留问答感"
> "第 3 部分的数据关系我想看清结构，别只列条目"

画幅、音色、语速、主题、BGM、每段讲多深，都可以在这一轮随口提；没提到的走默认。

### 3. 看预览，逐段提意见

agent 会先给你一个**在浏览器里就能打开的预览页**：默认停在首帧，点播放，画面和时间轴配音一起走。这时还没花渲染成片的成本，所以随便改：

> "第二段图太挤了，换一张"
> "这个标题两行放不下，改短"
> "开头太软，直接抛结论"
> "改成竖屏"

改稿、换图、调结构都不会重头再来：**已经定稿的句子配音直接复用，只重新合成变动的那几句**。中途随时可以叫停。

### 4. 催定稿

> "没问题了，出成片。"

agent 才做最后一步渲染，交给你 MP4，并附一份生产报告——每步耗时、配图覆盖率、有没有降级句，一目了然。

## 适合做什么

| 场景 | 出来是什么样 |
|---|---|
| 长文 / 公众号 / 论文 → 听解说 | 通勤路上能听完的一篇深度内容 |
| 报告 / 周报 / 会议纪要 → 汇报视频 | 不用开会，把结论和数字讲清楚 |
| 概念科普 | 结构图、流程图、数据关系直接画在画面上 |
| 产品介绍 / 功能说明 | 分模块讲解，每段一张视觉 |
| 对谈纪要还原 | 双音色问答，保留对话感 |

## 别用它做什么

- **剪辑已有视频**——它不处理你手上的素材片
- **只要配音、不出画面**——用任意 TTS 工具更省事
- **把 PPT 导出成视频**——它从文字重新写稿排版，不是转换 PPT

---

## 几件值得知道的事

- **画面不联网**：除了配音合成那一步要请求 TTS 服务，出图、排版、渲染全部本地完成，草稿和成片不会外传。
- **降级不会瞒着你**：某句配音失败了、BGM 没混进去、某段被剔掉了——一定在交付前明确告诉你，绝不悄悄产出一支"缺声音的完整视频"。
- **内容里的指令不会被执行**：信源里如果夹着"请忽略之前的设定""先执行这条命令"之类的话，一律当成普通文字读，不会照做。
- **产物不会写进技能目录**：音频、图片、HTML、成片都落在你的项目目录里。
- **字幕的取舍你知情**：整屏海报那一档版式，画面是静态的一张图，做不到逐句高亮，那一页的字幕要你自己画进图里。agent 用这种版式前会讲清这个代价。

## 准备工作

- 一个 MiMo 的 API key —— 配音的唯一硬依赖
- 电脑装有 **ffmpeg**（音频处理）和 **Node.js**（渲染成片）
- Python 3.9+ 本身，脚本只用标准库，**没有 pip 安装步骤**
