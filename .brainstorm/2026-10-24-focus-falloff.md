# 2026-10-24 · 焦点衰减：句子流按"离焦距离"退场，以及一次被缓存重建吞掉的状态

上一轮（`2026-10-23-verse-settle.md`）把"念完那句"的焦点交还给了下一句。本轮把
镜头拉远一格，问一个更整块的问题：**句子流作为一个面板，观众的眼睛往哪儿看？**

先说结论里最意外的那部分：动手之前做逐帧观察，先撞见了一个真 bug——**每支片子
的第一句字幕，从头到尾都比设计稿暗一档**（0.35，比"还没念到的句子"的 0.62 还
暗）。它不是本轮的主题，但是本轮做法的前提，放在第一节。

## 一、顺手抓到的 bug：换句接力的状态会被字体就绪清掉

用 Chromium 逐帧读回运行时状态（与上一轮同一套办法），开场句在 t=1.0（接力
0.32s 早就该演完）的透明度仍是 0.35——接力起点的值。加日志看清了链条：

1. `verseApply` 在换句时把接力起点记进 `c.relayT`（**缓存对象**上），并在把
   `--ctv-relay` 写上行时记 `L.relaySet = true`（也在缓存对象上）；
2. `document.fonts.ready` 兑现时，三份缓存（布局测量）整表清空重建——这是设计
   之内的：字体就绪会改变折行，测量必须重来；
3. 但 `relayT` / `relaySet` **不是布局值，是时间轴状态**，它们躺在同一张被清的
   表里。重建之后 `relayT` 变回 undefined，`verseRelay` 直接早退；
4. 于是行上那份已经写出的内联 `--ctv-relay:0.35` 成了孤儿：运行时忘了"这值是我
   写的"，再也不更新、也再也不清。当前句卡在 0.35，直到下一次换句才被新的接力
   值覆盖；已过的行则卡在 0.35（比 `past` 档的 0.45 还暗）。

字体就绪发生在页面打开后的第一秒内——那时活跃的正是**第一句**。所以每支片子的
开场句整句都暗着念完；预览里同样。

修法顺着"这是谁的状态"想：接力本来就是 `(t − cue 起点) ÷ 0.32` 的**纯函数**，
起点就是当前 cue 的起点，`verseTick` 手里就有——根本不需要存。于是：

- `relayT` 删掉，改成逐帧从 cue 起点**重算**（缓存清不清都无所谓）；
- `relaySet`（"这行上的内联值是不是我写的"）改成**看行上有没有那个内联值**
  （`getPropertyValue` 非空），同样是派生量；
- 顺带把 `verseEmClear` 的 `lastK === -1` 早退守卫去掉：缓存重建后 `lastK` 归
  −1，早退会让上一份缓存时代挂上的 `verse-ved-on` / `verse-ved-settled` 类留在
  行上（同一类病：内联/类状态活着，管它的状态死了）。清一次的成本是几个空操作。

修完之后，"字体就绪"与"往回 seek"对运行时是同一件事：状态全部从 t 重推，
重演一遍就是了——这正是注释里一直声称的 seek-safe 口径，这次是让它真的成立。

## 二、主题：焦点衰减（focus falloff）

| 观察 | 现状（改动前） | 前沿案例在做什么 |
| --- | --- | --- |
| 面板的层级 | 三档阶跃：当前句 1.0、已念 0.45、未念 0.62——**同档内一视同仁** | Apple Music 逐行歌词、Spotify 同步歌词：亮度按**离当前句的距离**衰减，远处的行沉进背景 |
| 眼睛找焦点 | 0.62 的"未念墙"里，最亮的那行是唯一线索 | 渐变本身就是路标：越亮离"现在"越近 |
| 已念与未念 | 只差 0.17（0.45 vs 0.62），方向对但只有一级 | 念过的比没念的**退得更快**——注意力向前看 |

三档阶跃是历史长出来的：0.62 是"未念"的底色、0.45 是"已念"的压暗，两数都是
单点决策，从来没被当成一条曲线的两端。

### 曲线不是新发明，是把 existing 数连起来

0.62 与 0.45 之间本来就藏着一条几何衰减：`0.62 × 0.726 ≈ 0.450`。也就是说
**"已念"恰好是"未念"沿着同一条曲线多走的一步**——这不是凑数，是这条曲线一直在
那里，只是被砍断在第二级。本轮把它延长：

- 未来侧：`d=1 → 0.62`，每远一步 ×0.726：`d=2 → 0.45`、`d≥3 → 0.327` 封住；
- 过去侧：整条曲线**提前一档**：`d=−1 → 0.45`、`d=−2 → 0.327`、`d≤−3 → 0.237`。

两侧在 0.45 与 0.327 处**无缝拼接**（未来 d=2 就是过去 d=−1 的值）——"念过的
比没念的同距更暗一档"不用任何特判，是曲线错位一档的自然结果。封在第三档不往下
走：再远的行基本已滚出窗口，继续衰减只是让数字好看。

### 淘汰掉的三个候选（都试推过）

- **字幕层视差**（上一轮留下的钥匙）：量了 Ken Burns 的实际行程——15s 段漂
  20~28px，视差取 15% 就是 3~4px，30fps 成片里**低于可感知阈**。做出来是"纸面上
  有视差"，画面上没有。真视差需要更猛的运镜，那是导演档的事，不是字幕层的。
- **正在念的字轻轻抬起**（CapCut/剪映卡拉OK模板的词级 pop）：结构性不可行。正文
  必须保持**一个裸文本节点**（拆叶子会被 Layout 门禁逐字报 `text_occluded`），
  逐字变换只能落在覆盖层上，而覆盖层里"已念"的字是 alpha 0——抬起一个看不见的
  字没有意义。
- **遮罩推入（mask reveal）**：行上不能写 transform（与 `.verse-clip` 的滚动
  叠加错位，既有约束），clip-path 收在行盒上也切不到"从遮罩里升起来"的观感。
  放弃。

### 实现口径

- 三个数（`future` 0.62 / `past` 0.45 / `ratio` 0.726）进 `_template.py` 的
  `subtitle.focus`，渲染器内联成 `--ctv-focus-*` 三个变量；运行时启动时读一次、
  展开成长度 4 的查表（`[1, a, a·r, a·r²]`），`|d|` 封顶 3。老产物没有这几个
  变量时回退到同一组默认值——行为与从前逐字节一致。
- 写值挂点只有 `verseApply`（换句才跑，距离只在那刻变）：`d=0` 撤内联、交还
  CSS 的 active 档；非活跃句所在的 verse 整表撤内联，退回 CSS 底色 0.62。
- CSS 的 `.verse-line` 仍是 `min(var(--ctv-line-op,.62), var(--ctv-relay,1))`，
  一个字不改：内联的衰减值与接力的瞬时值继续"谁更暗听谁的"。CSS 里的 0.62/0.45
  从此降级为**运行时未接管时的兜底**（与 `verseVedSettled` 内外两份同值的口径
  一样，注释里写明真源在模板）。
- 接力收窄到**活跃句所在的 verse**：以前靠"relayT 只在有活跃行的 verse 上赋值"
  间接达成，状态化删掉后这层保护没了，改成显式判"这行是否属于当前句所在
  verse"——否则删状态会让别的页的行也被接力扫到（实测扫到了才看见）。

## 三、验收

逐帧读回（Chromium，与上一轮同一办法）：

| 时刻 | 期望 | 实测 |
| --- | --- | --- |
| t=1.0（开场句，字体早已就绪） | 当前句 1.0——bug 修复 | `1`（改动前 0.35） |
| t=4.0（si=1 稳态） | d=0→1.0、d=+1→0.62、d=−1→0.45 | 逐项命中 |
| t=5.05（si=2，接力中） | 活跃行沿接力爬升、已过行落衰减档 | 0.858 / 0.45 命中 |
| t=8.0（si=3，三句同段的临时稿件） | d=−2→0.327（深过去退场）、d=−1→0.45 | `0.327` / `0.45` 命中 |
| 其它 verse（被盖住的页） | 内联撤干净，0.62 兜底 | 命中 |

Python 侧：模板三个数 → 变量注入的契约、`--set` 覆盖贯通、runtime 无 relayT 残留、
`verseEmClear` 无早退守卫。三道文档契约全绿（check_numbers 新登记 future/past/ratio
三条）。
