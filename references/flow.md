# 第 3 步 · 流线档：让轨迹由图上画的那条曲线给出

**"演什么"在第 1 步就定了**（`beats` 写在稿件里）。这一档只答一件事：当这一拍要「一整片元素被一条看不见的河流带着走，不同位置的元素朝不同方向弯过去」，而不是「一组元素逐个出现」或「一个扰动从中心扩散」，怎么写。画图 → `references/canvas.md`；入场 → `references/look.md`；该不该动 → `references/motion.md`；按距离传播 → `references/wave.md`。

## 一、对标：前沿在打的是「几何给方向，作者不给」

2025/2026 的前沿 MG 有一支很一致的语言，几份独立来源说的是同一件事——

| 来源 | 点名的手感 | 落到画面上是什么 |
|---|---|---|
| GSAP MotionPath / AE 的 Create Nulls from Paths | 一组物体沿一条**画好的曲线**走；改控制点，整条运动跟着改 | 曲线是运动场，不是装饰 |
| Cavalry 一类节点式工具的 field driver | 每个元素按**自己所在位置**从场里取方向和幅度 | 方向不由作者逐个填 |
| 2026 趋势里的 flowing organic movements、liquid ribbon、kinetic ribbon | 连续、流动、有机的运动；一屏里只有一条流在跑 | 不是逐个出现，也不回原位 |
| 2026 的 optical-flow / motion-field / depth-driven staging | 一整片点各自朝不同方向走，画面读成「场」而不是「队列」 | 位移是二维向量，不是一根轴 |
| dot-matrix ripple、halftone wave（本仓库 `wave` 对标的那一支） | 扰动从一点扩散，波过回原位 | 与本档最近，但它是**延迟**，本档是**输运** |

把这一叠词翻成工程语言，还是那三个约束：**延迟/方向不许手写**、**起止干净**、**逐帧可复现**。第三条是本仓库的硬纪律；前两条在这一档里比波场档更狠——波场档只让「延迟」退出契约，本档让**每个元素的起跑位置、行进方向、收尾落点**全部退出契约，只剩一条画在图上的 `<path>`。

## 二、域地图：曲线的形状一直是空的

先看已有档位各自消费了哪个「域」：

| 档 | 消费的量 | 从哪读出来 | 收尾在哪 |
|---|---|---|---|
| `to` / `morph` / `draw` | 位置 / 形状 | 作者写在补间里 | 终点 |
| `spring` | 阻尼 | 作者选曲线 | 终点 |
| `momentum` | 速度包络（做形变） | 作者给距离 | 终点 |
| `drag` | 相位（一条链共享曲线） | 链序 `φᵢ = i·φ` | 全链一起落定 |
| `step` | 时间量化 | 帧号 | 终点 |
| `hold` | 静止 | 无 | 原位 |
| `stagger` / `decode` | 时序 / 锚点 | 序号 + 分配曲线 | 逐个留在终态 |
| `arc` | 空间曲率（**单个**元素的两条轴） | 作者给幅度 | 终点 |
| `organic` | 值域不规则 | 不公度谐波 | 精确回原位 |
| `trail` | 时间叠加 | 层间 `lag` | 影子收干净 |
| `wave` | 距离 → 波前 → 延迟 | **元素间的欧氏距离** | 每格回原位 |
| `flow` | **一条 path 的弧长 + 切线** | **曲线自身的形状** | 曲线算出的新位置 |

它们有一条从没被写破的共同前提：**没有任何一个量是从「一条画出来的曲线的形状」读出来的**。`morph` 把 path 当成要被变形的**对象**；`params` + `bind` 让作者手写一条算术表达式把几何算出来（`references/motion.md`「参数演绎」），那是图之外的第二份真源；`arc` 是单个元素两条缓动合成的一条 C 形弧；`wave.radial` 读的是「元素到震中」的直线方向，恒为**从一点向外辐射**，而且波过之后精确回原位。

**所以这一档不是「第十四条位移曲线」，是补上第一个曲线场域。** 它与 `wave` 正交：`wave` 增加的是**延迟的空间来源**（谁先动），`flow` 增加的是**方向的空间来源**（往哪走）；`wave` 的格子只在波前经过的一小段时间里动一下，`flow` 的元素整拍都在走并且**落在一个新位置**。与 `drag` 也正交：链是一维序号、全链重参数化后一起落定在一个常量 `distance` 上；本档每个元素的落点由曲线形状算出来，彼此不同。

最接近「流」的既有写法有三条，但都不成立：

- `wave.radial` 的方向是径向的、幅度带距离衰减、端点回 0；它是一次**扰动**，不是一次**输运**。
- `params` + `bind` 确实能算出一条曲线上的点，但那条曲线是作者用 `expr` 写出来的第二份几何。改 SVG 里那条 path 的控制点，成片纹丝不动且零报错——本档存在的全部理由就是消灭这份手写。
- `morph` 让一条 path 自己变形；本档让 path 当**别人的运动场**，path 自己一动不动。

## 三、几何：曲线 → 弧长 → 投影 → 相对位移

难点不是「让几个元素沿曲线动」，而是**起跑位置与方向不许手写**：作者一旦能给每个元素填一个 `delay` 或 `from` 坐标，那串数字就是几何的第二份真源。解法是让生成期直接从 SVG 里量：

```
P(s)  = path 的弧长参数化（把 d 采样成折线，建 s → (x,y) 表）
cᵢ    = center(riders[i])                    元素包围盒中心（图上真实元素）
sᵢ    = argmin_s |P(s) − cᵢ|                 投影到曲线上的弧长坐标，唯一真源
L     = 曲线总弧长
qᵢ    = (sᵢ − s_min) / (s_max − s_min)       相对弧长，最近的元素 0、最远 1
dᵢ    = distance · exp(−taper · qᵢ)          每个元素实际前进的弧长
u(t)  = 1 − (1 − t/D)³                      生成期算死的 .out 包络
Sᵢ(t) = sᵢ + sign · dᵢ · u(t)               沿曲线走到的弧长处
Δᵢ(t) = P(Sᵢ(t)) − P(sᵢ)                    相对位移：t=0 精确 0，段首不跳
```

**不把元素搬到曲线上**。`Δ` 是相对位移，元素从自己原来的中心出发，走的是曲线那一整段的**平移副本**：`cᵢ + Δᵢ(t)`。若写成 `P(Sᵢ(t)) − cᵢ`（贴到曲线上），段首第一帧就会把整组元素从画好的位置瞬移到曲线上——那是 `references/motion.md`「跨段接续」记过的「页界静默错」在段内的版本。曲线是**位移场**，不是轨道；这也是它与 MotionPath 最本质的分界。

弧长按 `M L H V C Q Z` 折成绝对坐标，每条 `C` / `Q` 固定采 24 段（固定值而非自适应：逐帧可复现要求同一份 `d` 永远得到同一张弧长表）。祖先的 translate/scale 由共享的 `decompose_transform` 复合，旋转/斜切读不准就判废并出声，不猜一个中心；包围盒走 `_cam_crop._box`，与 `check_svg` 的空带/越界、运镜取景、波场档量距离同一份口径。**rider 自身不许带 transform**——生成期写 `x`/`y` 会覆盖元素自带的平移，段首静默跳一下。

坐标读进来必须是有限数：`d` 里写 `1e309` 这类溢出数会被 `float()` 读成 `inf`，累计弧长跟着变成 `inf`，`1e-6 × L` 的退化阈值与 `max(sᵢ+dᵢ) ≤ L` 的越界闸就一起失效——守卫失效且零报错。生成期在采样点入口就地拦掉，报错直接点出是哪一段 `d`。

**五条设计决定，都是被成片纪律逼出来的**：

**1. 相位不进契约。** `riders` 只写「哪些元素参与」，`path` 只写「哪条曲线」；sᵢ 由投影算出。产物里 `tl.set` 的写入顺序是作者给的 `riders` 序（导演意图），起跑弧长却只按投影排——**相位不听序号的话**，这是本档与 `stagger` / `drag` 最本质的分界。

**2. 曲线必须真的会转弯。** 生成期取各元素 sᵢ 处的单位切线，要求至少两处方向差 ≥ 6°。全落在直线段上时所有 `Δ` 平行，读成「整块平移」而不是「流场」——这不是参数越界，是**这一拍根本不是流**，按文件拦。与波场档里「格子全等距就是同步脉动」那条判据同一类（见 `references/wave.md`）。

**3. 流必须在曲线内走完。** `max(sᵢ + dᵢ) ≤ L`（`backward` 为 `min(sᵢ − dᵢ) ≥ 0`）是生成期硬红线：sᵢ 依赖几何，作者写稿时没法预知最靠后的元素离曲线终点还有多远。放宽这条，它会静默停在曲线末端，成片里是「流到一半卡住」。另有地板：`distance` 不小于 8 个 SVG 用户单位，否则 24fps 下一帧挪不到一像素。

**4. 落点是一个几何量，不是常量。** 与 `drag` 的「全链终点都是 `distance`」不同，每个元素的收尾位移是 `P(sᵢ ± dᵢ) − P(sᵢ)`。`_stage_carry` 因此必须**读这一页的内联 SVG** 才能逐元素折出 translate；只折流头的话，链尾会在页界静默弹回原位，正是 `references/drag.md` 记过的那一类错。这是本档独有的接续判据。

**5. 生成期采样成离散 `tl.set`。** 沿用 `morph` / `momentum` / `drag` / `step` / `organic` / `trail` / `wave` 的老路：渲染端零脚本、零 `onUpdate`、零依赖，成片里是一串确定的数值，逐帧 `seek()` 下每一帧都是时间的纯函数。行程包络 `1−(1−u)³` 在生成期算死——起步就有位移、到位导数归零；它**不是 GSAP 缓动**，拍级 `ease` 因此直接拒，写进去只会静默失效。

**不写 `rotation`（自动朝向）**：MotionPath 的 auto-orient 会把切线角变成元素旋转，但本仓库的接续烘焙只搬得动 translate，绕元素 bbox 中心的 rotation 折不进内联副本；且 `references/motion.md`「六种够用的演法」明确把整页旋转读作「页面坏了」。本档因此只写 `x`/`y`：**方向由位移向量给，不由朝向给**。要一个元素真的转过去，用拍级 `to:{"rotation":…}` 自己写。

## 四、被否掉的五个方案

| 方案 | 为什么不收 |
|---|---|
| **渲染端 MotionPathPlugin / `onUpdate` 按时间实时求值** | 带累计状态，逐帧 `seek()` 下第 N 帧与跳到第 N 帧对不上；Python 侧判据只能退化成对着另一份 JS 自证（`references/decode.md` / `references/spring.md` 记过这笔账）。 |
| **把 `wave.radial` 当流用** | 幅度带距离衰减、脉冲紧支撑、端点精确回 0：那是一次扩散的扰动，不是一次有落点的输运；方向恒为从震中向外，不会沿曲线拐弯。 |
| **`params` + `bind` 手写 `expr` 算出曲线上的点** | 几何的第二份真源。改 SVG 里那条 path，成片纹丝不动且零报错——本档存在的全部理由就是消灭这份手写。`expr` 还刻意不收时间函数，逐帧可复现下算不出「流到哪儿了」。 |
| **作者手写每个元素的 `delay` / 起跑坐标，契约层只收数字** | 同上一行，而且是这一档最容易被「先跑通」诱惑写出来的形状。挪动一个元素，成片里它的起跑位置仍停在旧地方。 |
| **`drag` 的链当流用** | 链是一维序号、重参数化后全链一起落定在同一个常量；本档每个元素的落点由曲线形状算出来、彼此不同，链尾也不会等链头。 |

另外试过、又删掉的一条判据：对产物做**位移向量互相关**去证明「远元素沿曲线走了同一条轨迹的不同段」。曲线一旦折返，两段位移的夹角会随时间漂移，互相关峰值随 `taper` 变化，判据会变成「调衰减就红」。最后改成直接读**弧长单调性**与**切线方向差**——都是结构性事实，不靠在短信号上做谱分析。

## 五、契约与旋钮

一拍写 `flow`，整段负责全部元素。五个旋钮：

| 键 | 默认 | 读什么 |
|---|---|---|
| `riders` | 必填 | 2～12 个有序 `#id`，图里真实存在的一组元素；`riders[0]` 必须等于 step 级 `target` |
| `path` | 必填 | 单个 `#id`，图里一条带 `d` 的 `<path>`；生成期从它的几何读曲线，**不写坐标** |
| `distance` | 必填 | 沿曲线前进的弧长（SVG 用户单位，≥8）；最近的元素精确走这么多 |
| `direction` | `"forward"` | `"forward"` / `"backward"`：沿弧长增大 / 减小方向走 |
| `taper` | `0.0` | 沿弧长的幅度衰减（0 = 全体等距前进；2.0 时最远元素只剩约 13.5%） |

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#d4", "duration": 1.2,
   "flow": {"riders": ["#d4", "#d1", "#d3", "#d2"], "path": "#track",
            "direction": "forward", "distance": 180, "taper": 0.45}}
]}}}
```

图里要有一条会拐弯的 `<path>` 与一组沿它分布的元素，`riders` 顺序随作者写（只决定产物里 `tl.set` 的写入顺序）：

```svg
<svg viewBox="0 0 980 735">
  <path id="track" d="M 40 360 C 200 40 380 680 560 300 C 700 80 820 120 940 420"/>
  <rect id="d3" x="90"  y="272" width="20" height="20"/>
  <rect id="d1" x="324" y="375" width="20" height="20"/>
  <rect id="d4" x="581" y="245" width="20" height="20"/>
  <rect id="d2" x="824" y="213" width="20" height="20"/>
</svg>
```

**互斥**：`flow` 与 `from` / `to` / `set` / `draw` / `morph` / `count` / `type` / `momentum` / `drag` / `step` / `organic` / `trail` / `wave` / `lens` / `swarm` 同拍即 error——两条时间线抢同一条 transform 通道，GSAP 后写的那条静默覆盖前一条。不收 `stagger` / `repeat` / `yoyo` / 拍级 `ease`，不能打在 `#cam`，`path` 不能是 `riders` 之一。

## 六、生成期会拦什么

| 现象 | 级别 | 怎么消 |
|---|---|---|
| 未知键 / `riders` 数越界或重复 / `path` 非法 / `distance` 太小 / `direction` / `taper` 越界 | error（契约层） | 只认五个键；红线见上一节 |
| `riders[0]` ≠ step 级 `target` | error（契约层） | 流头就是这一拍的目标，接续烘焙与按文件拦只认 `target` |
| 与别的「演」同拍 / `stagger` / `repeat` / `yoyo` / 拍级 `ease` 挂在 flow 上 | error | 删掉一边；要逐个出现用 `stagger`，要按距离传播用 `wave` |
| `riders` / `path` 在 SVG 里找不到，或 `path` 不是带 `d` 的 `<path>` | error（生成期，按文件拦） | 落空一个不会报错，只会让那一片区域静默不动 |
| 包围盒读不出 / 祖先带 rotate、matrix、skew / rider 自带 transform | error（生成期，按文件拦） | 改成图元或包一层 `<g>`；rider 的平移写进 `x`/`y` 属性 |
| `d` 里含 `A` / `S` / `T` | error（生成期） | 改写成 `C` / `Q` 或折线；这些命令要在本模块里复刻第二套路径求值 |
| 曲线不转弯 / 所有元素落在同一个弧长上 | error（生成期） | 让 path 真的弯一次、把元素沿曲线散开；否则这一拍是整块平移，用 `to` |
| 流走出曲线（末端或起点） | error（生成期） | 缩短 `distance`、减小 `taper`、把 path 画长，或换 `direction` |
| 拍长 < 0.12s / 帧时刻撞进同一个 0.01s 格 | error（生成期） | 加长 `duration`；否则产物静默少一帧 |
| 段首有位移 / 收尾没走出去 / 沿弧长进度不单调 / 采样网格不递增 | error（生成期） | 生成期自查会拦，正常配置不会出现 |

## 七、判据落在哪

`tests/test_flow.py` 一个文件压完，判据全部**从产物里抠补间来读**，不在 Python 侧另写一份「应该生成什么」的实现。

| 组 | 钉住什么 |
|---|---|
| 信号 | 纯函数（正序/逆序/乱序一致、窗口外夹回端点）、相对位移（段首精确 0、元素不贴到曲线上）、包络端点与单调、衰减归一到最近元素 |
| 场 | 弧长按投影排且与 `riders` 序号无关、切线方向差 ≥ 6°、四个落点互不相同、几何红线（落空 / 非 path / `A` 命令 / 同弧长 / 自带 transform / 相对命令与绝对写法量出同一条曲线） |
| **改图即改编排** | 挪动一个元素 → 产物里只有它的位移序列变、其余不变；改 path 的一个控制点 → 弧长表与整组落点一起变 |
| 网格 | 采样带两端、帧时刻严格递增且不撞 0.01s 格、条数 = (帧数+1)×元素数、一帧地板与「流在曲线内走完」红线 |
| 契约 | 红线、与其余所有「演」互斥（含后加的透镜档）、不收错峰/重放/拍级缓动、相机层与自指曲线、绕过契约层的坏值在生成期炸 |
| **产物级对账** | 从 HTML 抠出的 `tl.set` 序列，锚点、帧数、逐元素选择器与逐帧变量必须与 `_flow.frames` 逐项相等；两画幅各验，两次生成字节相同；五个旋钮各自真的改产物 |
| 作用域与接续 | 没写 flow 的页零新增补间；`_stage_carry` 逐元素折出**由曲线算出的** translate，四个落点互不相同、不搬不动的 transform 为零 |

「接续落点是几何量」是本档独有的一条判据：既有档位的收尾态要么为空（`organic` / `wave`）、要么是配置里的常量（`drag` / `trail`），只有本档必须重读这一页的 SVG 才能算出四个互不相同的落点。

## 八、什么时候不要

- **一组元素要逐个出现并留在画面上**：用 `stagger`；要逐行锁定结论文字，用 `references/decode.md`。流线档整拍都在走，读完就到了别处。
- **一个扰动从某处按距离扩散、每个格子波过回原位**：用 `references/wave.md`。那是延迟的几何来源，本档是方向的几何来源。
- **一枚透镜扫过画面、元素的位移方向随场心移动而转、扫完精确回原位**：用 `references/lens.md`。流线档是输运、收尾落在新位置；透镜档是一次扫过、收尾回到原位，方向是时间的函数而非曲线弧长的函数。
- **要主体带动一条真实元素的链、全链一起落定**：用 `references/drag.md`。本档每个元素的落点由曲线算出来，链尾不等链头。
- **要一帧里同时看见主体的几个过去**：用 `references/trail.md`。那是时间叠加，本档是空间场。
- **要到位停住 / 安静落位**：用 `.out` 档或 `spring`。本档整拍都在走，收尾是一个新位置。
- **要元素真的转过去（自动朝向）**：本档不写 `rotation`，理由见第三节；用拍级 `to:{"rotation":…}` 自己写，或换视频素材。
- **文字 / 数据图 / 只有两三个元素**：本档只写 `x` / `y`，逐字揭示与数字滚动各有自己的整段语义；两三个点排不出方向场，读成「一起斜着走」。
- **一屏同时动的不超过三处**：一开 flow 就是一整片元素在动，别再叠一层 `organic` 呼吸或 `wave` 涟漪。先问 `--perceptual` 的四道验收够不够。
