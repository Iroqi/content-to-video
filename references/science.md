# 第 1 步 · 科普视频专项：先定推演，再定画面

这份只管一种片子：**把一个概念、机制或原理讲明白**。品牌叙事、产品评测、周报、播客摘要、书评各有写法，见 `references/writing.md` 的「内容类型举例」。财报解读与科普最接近，差在目的——财报是「把材料讲完整」，科普是「让观众建立起一个能自己用的模型」。

科普片失败的样子几乎都一样：旁白已经推到第三步，画面还停在第一步；或者画面很炫，却没承担任何信息。**根因不是动效不够，是「演什么」没在写稿时定下来**。这份把已有能力按科普路径重排一遍，不新增档位。

## 一、结构：一个概念六步走

| 步 | 观众此刻的问题 | 画面该承担什么 | 常见错误 |
|---|---|---|---|
| 1 钩子 / 直觉错答 | 这事我好像知道 | 把多数人的第一反应摆出来，留一个问号 | 直接给结论，观众没有「我原来想错了」的落差 |
| 2 建立模型 | 那到底该看什么 | 给出真正起作用的那个量、那层结构、那条关系 | 换成一张好看但没标注的意象图 |
| 3 分步推演 | 它怎么一步步起作用 | 每一步画面跟着旁白变一次 | 一整段只有一张静图 |
| 4 排除错答 | 原来那个说法错在哪 | 用量化或对照把错答证伪 | 只说「不对」，不给理由 |
| 5 反直觉结论 + 边界 | 所以呢 / 什么时候不成立 | 结论上屏，并写清适用范围 | 说成万能规律，反而误导 |
| 6 收束 | 我带走哪一句 | 一句话回扣开头那个问号 | 再加一个新概念 |

内容段最多 7 段，留得下 `cta` 的是 ≤6 段——上面六步正好用满。`opening` / `closing` 单独成页，不占这六个位置。`kicker` 那行 ≤18 字的分类小字，科普片别拿来写「第一章」，拿来写**推演进度**（`第 3 步 · 分步推演`）：观众随时知道自己在模型的哪一层。

## 二、`beats` 是骨架，不是装饰

推演段**必须**在写稿时写 `beats`：每条绑一个整数句序，`on` 必填，「这一句讲到哪儿、画面该变成什么」用人话写清。句序只按终止标点切，写稿时就能数准，配音不改句子也不改编号。规则见 `references/writing.md` 的「字段规范」与 `references/motion.md`。

要记住这三层不互相替代：

| 层 | 回答什么 | 落在哪 |
|---|---|---|
| `beats` | 这一拍说什么、画面该变成什么（意图） | `segments_source.json` |
| `animate.steps` | 具体哪条属性从多少补到多少（实现） | `images.json` |
| `--perceptual` | 成片里到底有没有变（验收） | 取帧判词 |

**中间那台「意图 → 实现」的翻译机不存在，得人写。** 所以科普片有一条硬检查：跑完 `--until html` 看 `production_report.beats`，`warnings` 非 0 就是「提了没落实」——当前这道闸只 warn 不拦，必须人看。逐拍写法与红线见 `references/decode.md`、`references/motion.md`。

## 三、科普意图 → 用哪个原语（不要先挑动效档）

| 要让观众看到 | 用这个 | 别这么干 |
|---|---|---|
| 机制一步步走、流程逐格接上 | `beats` 配 `stagger`（逐项）或 `draw`（描线） | 一整段只贴一张画好的终态图 |
| 公式代入、一个连续量驱动多个元素 | 参数演绎 `params` + `bind`（表达式逐帧重算几何） | 逐帧手算坐标写死在 steps 里 |
| 数字长到目标值 | `count` | 直接换一张写着答案的图 |
| 分布从尖到平、形状之间「变」而不是「换」 | `morph`（同拓扑） | 淡出淡入两张无关的图 |
| 结论逐条揭晓、一组文字逐行落定 | `type.decode` + `stagger`，见 `references/decode.md` | 一次性全亮 |
| 多对象对照、突出其中一项 | 静态 SVG + 高亮那一处的 `attr` | 上一节那类场档 |
| 尺度、数量级、比例 | 带标尺与参照物的 SVG，先定标尺再画图形（`references/canvas.md`，数据图的几何自查那节） | 没有刻度的意象图 |
| 抽象原理、氛围、现场 | ImageGen 生图，画面里不出现可读文字（`references/imagery.md`） | 让生图去写公式、标注或数字 |

### 装饰性场档的边界

`organic` / `trail` / `wave` / `flow` / `lens` / `swarm` 这六个档是为品牌页与前沿 MG 手感建的，共同前提是「一整片元素按几何场运动」。`SKILL.md` 路由表里逐条写着「文字数据图时别用」——而科普片的主画面恰恰是文字、公式、数据图和标注。

不是不能用，是**别让它们承担信息**：

- 需要说「看这里」时，用高亮 / 引线 / 编号，不要用透镜扫过；
- 想表达「扩散」时，先问是不是真在讲传播过程，是才用 `wave`，否则那只是装饰；
- 推演段、数据图、术语定义页一律不用场档。动错了比静图更糟：它会把注意力从「这一步在说什么」挪到「刚才什么动了一下」。

`hold` 的静止窗口与 2% 慢推是另一回事——它管的是「落位之后别让画面整段死成静帧」，科普片照用，见 `references/hold.md`。

## 四、语义色优先于色温弧

`scripts/_theme.py` 的默认 `accent` 按段序走一条情绪弧（冷开场 → 中段偏暖 → 收束回品牌色），颜色被读成「进度」。这在叙事片里是免费的一层信息，在科普片里是干扰：观众会把第一页的蓝色认成变量 A，下一页蓝色又给了变量 B。

科普片的颜色该承担**概念身份**：同一个变量 / 同一个对照组 / 同一条结论，跨页同色。做法是用段落级 `accent` 显式指定（`references/writing.md` 的字段规范），并让 SVG 内部用同一组色值；别让默认弧替你换色。图内文字定色与对比度见 `references/canvas.md`，图内正文级字号 26px 是下限。

## 五、事实与术语：最容易漏的三条

1. **数字带单位、量级带参照**。口播里说「薄到几纳米」不够，要给一个观众能抓住的参照；坐标轴要有刻度与量程，柱高由标尺反算而不是凭手感。
2. **术语首次出现给一句话定义**。用 `tagline`、`takeaway` 或该段第一句口播交代，别让概念裸奔；同一术语全片一个叫法，不给别称。
3. **反直觉结论必须给边界条件**。「在什么范围内成立、什么情况下失效」要上屏或进口播，否则科普就成了断言。

信源里的数字、日期、比例等事实保留可回查依据（`SKILL.md` 核心工作流前置）；素材来源用 `images.json` 的 `provider` / `license` 记账（`references/imagery.md`）。出处留在稿件与生产报告里，不必硬塞进画面。

## 六、科普专项验收（在通用四道之外补五条）

1. **暂停一帧还成立**：每个推演段随手暂停，图能不能独立说明这一步，见 `references/canvas.md` 的整页画布密度与层次那节。
2. **推演步数对得上**：每个推演段的 `beats` 条数 ≈ 旁白里的步数，且 `production_report.beats.warnings == 0`。
3. **每个数字都有单位 / 标尺**，坐标轴有刻度与量程。
4. **术语首次出现有一句定义**，同一概念跨页同色、同叫法。
5. **跑一次 `--perceptual`**：看「有没有长时间不动」与「换页对不对得上旁白」。它只报不拦，判词要人读。

`references/look.md` 的交付前四道照旧要过，contact sheet 仍要人翻——这五条补的是「讲没讲明白」，通用验收只证明「没有明显坏」。
