# 第 4 步深度参考：画布素材方式 A/B/C/D

本文件是第 4 步的唯一配图规则真源。四种方式虽然来源不同，但进入成片后都服务同一个**内容画布**：每个内容段固定一个视觉区域（竖屏居中 / 横屏右侧图栏），素材负责铺满它。

核心原则只有一句：

> **先判断内容应该呈现什么，再决定素材从哪里来。四种方式的画布规格、质量要求、落盘格式和人工验收标准保持一致。**

## 一、四种方式先统一：共用规则

### 1. 先选“表现方式”，再选素材来源

不要把 A/B/C/D 当成四套独立流程。每个 segment 先回答“观众应该看到什么”：

| 内容特征 | 首选方式 | 原因 |
|---|---|---|
| 有明确真实人物、产品、地点、事件、新闻现场 | **A 真实照片** | 真实实体需要真实影像，避免生成图替代事实照片 |
| 画面里**不需要出现可读文字**：抽象概念、原理、机制意象、氛围、场景 | **B ImageGen** | 一句 prompt 出一版，复杂结构它也扛得住，风格还更容易整期统一 |
| 画面里**必须有准确文字/数字**，或必须是精确矢量几何、严谨数据 | **C 图表 / 公式 / SVG** | 信息准确性只能自己画，生图的文字不可信 |
| 需要连续运动、过程、场景变化 | **D VideoGen** | 真正有"过程"时才值得让画面动起来 |

**B 与 C 的分界线只有一条：图内要不要文字。** 要（标签、步骤名、数值、图例、公式）→ C；不要 → **选 B，哪怕内容复杂**。两个方向各有一条实测代价：手绘 SVG 返工率高——构图、图内文字对比度、卡片内文字宽度全得靠人肉自查（见 C3 取色表），改一版就是重画；ImageGen 则是**文字崩率高**（错字、缺笔、乱码、糊成一团），所以它只接不带文字的活。

另外两条边界：

- 严谨数据/公式仍走 C1/C2（Chart.js 与公式卡），它们不靠手绘，返工成本低于 SVG。
- **故事性强 → D**，但不是"任何故事都要动画"；如果动画只增加氛围、不增加信息，回到 A/B/C。

再按**信息结构**细分该画成什么形式。别问“我能画什么”，问“哪种形式最能帮观众理解”：

| 信息结构 | 首选形式 | 路线 |
|---|---|---|
| 数值比较 / 占比 / 趋势 / 双变量关系 | bar / pie / line / scatter | C1 |
| 时间演进（要标年份） | 时间线 | C3 (SVG) |
| 步骤 / 机制流程（要标步骤名） | 流程图 | C3 (SVG) |
| 层级 / 关系 / 系统结构（要标节点名） | 树状图 / 网络图 / 架构图 | C3 (SVG) |
| 几何 / 空间关系，**不带文字** | 生图（isometric / 3D render 风格词） | **B** |
| 外观、场景、氛围 | 图片 | A / B |
| 运动本身携带信息 | 视频（VideoGen）/ GIF | D |

同一张图若能不写字就说清楚，就从中性形式降级交给 B：时间线可以变成"发光节点串成的路径"，架构图可以变成"层叠的节点群"，标注该说的事让标题和 verse 字幕去讲——省掉一次重画，也免掉图内文字的对比度自查。反过来，一旦某个信息**只能靠图上那几个字**表达（数值、术语、步骤名），就必须走 C3，不能赌生图。

图只承担**增量信息**：标题和 verse 已经把话说清楚时，不要为填满画布而画，也不要为“高级感”堆 3D、仪表盘、多图拼贴这类不帮助理解的装饰。

### 2. 四种方式统一使用同一个内容画布

- 视频总画幅：竖屏 **1080×1440（3:4）** 或横屏 **1920×1080（16:9）**，`--aspect` 选择，默认竖屏。
- 内容画布：竖屏 980×735，横屏右侧图栏 1067×800（4:3 按整数像素取整）。
- 配图规格只有一条：**按 4:3 出图**。画布是 `cover` 铺满，比例不合会居中裁掉四边。B/C/D 三条路线本来就能满足（ImageGen 选最接近 4:3 的档位，图表/公式卡自适应容器，VideoGen 按 4:3 出片；手绘 SVG 的 4:3 落在根节点 viewBox 上，见 C3 画布几何）；只有方式 A 的真实照片可能比例不合或带烧录水印。
- 所有方式最终都写入同一份 `images.json`，由同一个 renderer 放进画布。

### 3. 四种方式统一的质量标准

无论来源是什么，都按下面这套标准审：

**内容准确**：画面必须对应当前段落在讲的对象、动作或概念，不接受“气氛类似但事情不对”。

**主体明确**：画面第一眼能看出主角是什么；不要塞过多无关元素。



**可读可看**：如果画面内部有文字、公式、标签，必须在成片观看尺寸下（竖屏与横屏都算）依然清楚；无法保证就不要把关键信息放进素材内部。

**风格统一**：同一期可以混用 A/B/C/D，但要统一背景明暗、主体尺度、主色倾向和视觉密度。方式不同不等于风格失控。

**来源可追溯**：方式 A 保留来源 URL 等 provenance；方式 B/C/D 也尽量记录生成工具、来源或生成说明，避免二次整理时丢失来源信息。

### 4. 四种方式统一的制作流程

每个 segment 都按同一条链走：

```text
判断内容 → 选择 A/B/C/D
       ↓
得到媒体文件或可渲染规格
       ↓
放入 hf-project/images/
       ↓
写入 images.json
       ↓
生成 HTML
       ↓
审关键帧：主体、构图、文字可读性、与歌词关系
```

不要因为方式不同就省略最后的人工验收。**素材正确性和实际观感不能只靠 JSON 或脚本判断。**

### 5. images.json 是唯一统一入口

四种方式最终都映射到同一份 `images.json`。静态图最简单：

```json
{
  "seg1": {"src": "images/seg1.png"},
  "seg2": {"src": "images/seg2.jpg"}
}
```

视频按需增加播放属性：

```json
{
  "seg3": {
    "src": "images/seg3.mp4",
    "type": "video",
    "loop": true,
    "muted": true,
    "autoplay": true,
    "playsinline": true,
    "poster": "images/seg3-poster.png"
  }
}
```

字段：

- `src`：必填，相对 HTML 输出目录的媒体路径。
- `type`：可选，合法取值 `auto`/`image`/`video`/`gif`/`chart`（`chart` 见方式 C）；缺省即 `auto`，按扩展名判断。`.mp4/.webm/.mov/.avi/.mkv` → video，`.gif` → gif，其余 → image。
- `loop` / `muted` / `autoplay` / `playsinline`：视频播放属性，默认均为 `true`。
- `poster`：可选，视频加载前显示的封面图。
- `provider` / `source_url` / `license` / `attribution` / `query`：可选，方式 A/B/D 的来源
  记账（SKILL.md「配图」一节的 provenance）。画面不读它们，但二次整理时不要覆盖掉。

值只能是上面这种对象；裸字符串路径（`{"seg1": "images/seg1.png"}`）会在契约层直接报错。

**上面这份键清单就是渲染端读的全部**：写了清单外的键（`alt`、`position`、`fit` 这类
凭空发明的写法）不会生效——归一化配图的 `html_renderer._normalize_images`（由
`gen_hyperframes.py` 在生成 HTML 时调用）会打一条 `[warn]` 点名是哪几个键，
看到就删掉或换路：想改构图改稿件或 SVG 本体，想改文字就写进文案，images.json 不管这些。

方式 C 的图表/公式是唯一例外：它们可以直接写 `chart` 规格，不需要先生成图片文件。

## 二、方式 A：真实照片 / 真实素材检索

### 适用

真实人物、真实产品、真实地点、真实事件、发布会、比赛现场、新闻现场、历史照片等，有明确实体且真实影像本身就是信息的一部分。

### 流程

用你可用的**联网搜索 / 图片搜索能力**执行以下流程——同样是能力泛称：模型自身搜索能力、平台提供的检索工具或已安装的搜索类 Skill，任一可用即可（本技能不内置检索工具）：

1. 从段落标题和正文提炼检索词；中文实体尽量加英文别名或型号。
2. 检索来源页，不要只看缩略图。
3. **逐张打开原图**，确认不是标题党、截图、带角标或与正文无关的图片。
4. 下载到 `hf-project/images/`，命名 `<sid>.<ext>`。
5. 在 `images.json` 中写映射，并保留 provenance。

### 选图标准

- 主体与段落讲的是同一个人、同一个产品、同一个地点或同一事件。

- 分辨率足够；长边低于约 1200px 时，进入成片后容易发虚。
- **入库前裁成 4:3**，保留哪块主体由看图的人判断。

找不到合适的真实图时，不要为了"覆盖率"凑图，直接改走 B/C/D。

### 不要做

- 把真实人物的 AI 生图冒充现场照片。
- 用同一张泛化图片反复覆盖多个不相关 segment。
- 为了满足 4:3 裁掉关键人物、产品或场景主体——裁之前先确认主体完整，放不下就换图或换路线。

## 三、方式 B：ImageGen

**ImageGen 是能力泛称**，不特指某个工具：模型自身的多模态生图、平台提供的图片生成工具、或已安装的生图类 Skill，用当前环境里任一可调用的能力执行本方式。

### 适用

抽象概念、原理、机制意象、情绪意象、无法对应真实照片的内容，以及需要整期视觉风格统一的段落。**只要画面内不出现可读文字，复杂示意图也归这里**：几何/空间关系、节点群、层叠结构、透视与等距视角，这类图常被误派给手绘 SVG，但生图一句 prompt 就能到位，重画成本几乎为零。

### 统一规格

每个 segment 生成一张**横版 4:3**图，尺寸在所用能力支持的档位里选最接近 4:3 的（如 1152×864）。同一批 prompt 保持同一背景明暗与风格词。

### Prompt 原则

Prompt 先描述“讲什么”，再描述“怎么画”。不要先写一堆风格词，最后才补主体。

推荐顺序：

```text
主体 / 场景
+ 核心动作或结构
+ 视觉关系
+ 风格
+ 背景与色调
```

示例：

- AI 模型发布：`Three interconnected AI model nodes, clear causal connections, dark background, blue-cyan digital art, clean composition`
- 反向传播：`Minimal neural network diagram with arrows flowing backward through layers, dark background, flat vector illustration style, no text, no labels`
- 供需关系：`Simple supply and demand diagram with two intersecting curves and highlighted equilibrium point, dark background, clean vector style, no text, no labels`

`diagram / chart / schematic / infographic` 这些词会把坐标轴标签和说明文字一起带进来，末尾补一句 `no text, no labels, no letters, no numbers`。出图后仍看到文字就重新生成——放大裁剪糊弄不过去，缩进画布后那串乱码照样看得清。

### 统一规则

- 一期视频保持同一套背景明暗和视觉语言。
- 讲解类画面优先 `diagram / flat vector / minimal`，不要为了“高级感”做无意义写实场景。
- **不要在图里放文字**（label、数字、公式、招牌、界面文本都算）。生图的文字崩率高：错字、缺笔、乱码、糊成一团，且崩在图里的字改不动。该标注的信息交给标题区、verse 字幕，或改走 C 路线。真带上文字且无法接受崩字风险时，这张图本来就该是 SVG。
- 主体和 accent 色保持同色相倾向，让画面进入主题后不会跳色。
- 生成后统一重命名为 `seg1.png`、`seg2.png`……并写入 `images.json`。

## 四、方式 C：图表 / 公式 / SVG

方式 C 用于“信息本身应该被画出来”的内容，是四种方式里最偏信息展示的一类。

### C1 数据图表

适合营收、增长率、排行、占比、趋势、变量关系等真实数据。

支持：

- `bar`：少量离散值比较。
- `line`：时间或顺序趋势。
- `pie`：构成比例。
- `scatter`：两个变量的离散关系。
- `curve`：受限数学表达式采样后生成 line chart。

数据必须直接来自信源或可追溯的数据源。红线（对 C1/C2/C3 与生图同样适用）：

- 不为“好看”改数字；估算值必须在画面或文案里标明，不得画成事实。
- 不使用误导性比例（截断坐标轴、面积失真对比等）；不隐藏或省略单位。
- 不编造不存在的数据点、关系或会改变含义的关键关系。

### C2 公式

适合数学/物理公式本体。`formula` 会在内容画布内生成 HTML 文本卡，不生成 SVG，也不依赖额外数学字体库。

示例：

```json
{
  "id": "seg3",
  "type": "formula",
  "title": "质能方程",
  "formula": "E = mc^2"
}
```

### C3 矢量示意图 / SVG

**定位：图内必须出现准确文字（术语、步骤名、数值、图例）或必须是精确几何关系时的首选。** 不带文字的画面一律先试 B——SVG 是四种方式里返工最贵的一种：构图、图内文字对比度、卡片内文字宽度全靠人肉自查，管线里没有任何一项检查看得见它们（见下面的取色表），每次改方向就是重画一遍，而生图换一句 prompt 就行。

承担文字示意时它仍是表现力上限最高的一种，**不等于"简笔线框图"**：渐变、光影层次、等距视角、装饰细节都可以把示意图提到成片质感；如果发现自己在画单色方块加直线，就是画得太素了。但别把这份力气花在"画一个 3D 分子结构"上——那不带文字，是 B 的活。

三条获取路径：

- **手绘 SVG**：按该段内容自己写 `.svg` 放入 `images/`，适合该段特有的机制/结构。
- **SVG 图库 / 现成素材**：品牌 logo、通用图标优先用成熟的开源 SVG 库（如 simple-icons、lucide、tabler）或开放许可素材，而不是凭印象手画一个“长得像”的；同一期用同一套图标库、统一线宽风格，来源与 license 记进 provenance。
- **SVG 动画**：可以用 CSS `@keyframes` / SMIL（流动虚线、呼吸光效、循环位移等），观感提升明显。注意内部动画按页面墙钟时间走，**无法与口播时间轴同步**——只用于“氛围循环”，不要用于“必须对上某句话的状态变化”；后者交给方式 D 视频。

映射都走普通 `src`：

```json
{
  "seg4": {"src": "images/seg4.svg"}
}
```

外部 SVG 以 `<img>` 载入（内部脚本不会执行），但仍只从干净知名来源获取，不引入来源不明的素材。

**版式跟着该段内容的逻辑走**，不要每期都落到"两个方块加一支箭头"上：时间演化用时间轴，机制因果用带箭头的流程，层级用树，占比用环形或堆叠条，对照用双栏。骨架类文件只提供画布与取色约束（见下面两节），具体摆什么图形由旁白决定；同一期里几张示意图长得一模一样，就是没做这个判断。

#### C3 的画布几何：根节点必须是 4:3

SVG 唯一的一条硬规格，写死在根节点上：

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="980" height="735" viewBox="0 0 980 735">
```

- 内容画布竖屏 980×735、横屏 1067×800，**两者都是 4:3**，所以按竖屏尺寸画一份就两画幅通用，不必出两张。
- 画布是 `cover` 铺满（见 `references/rendering.md`）：viewBox 不是 4:3 时短边对齐、长边居中裁掉，贴边的图内标题、图例、卡片描边会缺一块，内置动画还会露出位移被切的痕迹。要改就改根节点的画布尺寸再重排内容，**别靠缩内容凑比例**。
- 图库来的图标（simple-icons / lucide / tabler 多为 24×24，即 1:1）**不能整幅当配图**，只能作为 4:3 画布里的一个元素套进 `<g transform="translate(…) scale(…)">`，四周留出与同段其他图一致的边距。
- 这条**没有任何管线检查看得见**：`gen_hyperframes.py` 对 svg 只校验文件是否存在，既不量根节点比例，也量不到图内文字的溢出与对比度（下一节）——全靠下笔时按规格写死、画完用 Chrome 无头截图自查。

#### C3 内的文字对比度：定色在前，自查在后

**为什么只能自己盯**：SVG 以 `<img>` 载入，它内部的文字不属于 HTML 文本流，管线里没有任何一道检查会量它。实测把深色底 SVG 的标签色换成与背景几乎同色的 `#1a2536`（对比度 1.2:1，肉眼完全读不出），从生成到渲染全程零报错，一路带到成片才发现是空白。"深底配深字"没有第二道防线，下笔时定错就一路带到观众眼前。

**判定线**（WCAG）：正文与标签 ≥ 4.5:1，图内大标题 ≥ 3:1，低于 3:1 重画。4.5:1 只是及格线——图内小字还要经两画幅缩放和成片压缩编码，次要文字按 ≥ 7:1 取色。

**深色主题取色表**（以自建深色面板底色 `#0c1320` 实测）：

| 用途 | 取色 | 对比度 |
|---|---|---|
| 图内标题 | `#f2f6fc` | 17.1:1 |
| 主标签 | `#dbe6f5` | 14.7:1 |
| 次要说明下限 | `#8fa6c2` | 7.4:1；再暗一档 `#6b7c93` 只剩 4.4:1，已越线 |
| 背景深蓝族 | `#0c1320` `#16233a` `#1a2536` | 1.0–1.3:1，出现在 `fill` 上就是瞎字 |

**浅色主题**（cream，底约 `#f0ead9`）方向相反：正文 `#22262b`（12.7:1）、次级 `#3a5c8c`（5.7:1），不要用近白当正文色。这里最常发生的翻车是**串主题**：把 dark 主题的 `#eef2ee` 抄进 cream 稿，1.06:1。

**三条最常踩的**：

- **深色文字只能待在明确的浅色底板上**。符号常写成近黑 `#0c1320` 摆到浅色渐变圆盘上（圆盘上 15.1:1，没问题）——可圆盘一挪、一删、或换了渐变，这行字立刻瞎掉。改任何底板颜色，都要同时复核压在它上面的文字；`fill` 能就近写死就别靠 `<g>` 继承。
- **背景色族不得当文字色**。同一支深蓝只用于背景与面板。判据是"这个色值属不属于背景族"，不是"看起来有没有对比度"。
- **半透明按合成后的颜色算**。`opacity` / `fill-opacity` 会真实吃掉对比度：50% 的 `#dbe6f5` 叠在 `#0c1320` 上合成 `#747c8a`，只剩 4.4:1。要弱化文字就换一个更暗的实色，不要用透明度。

### C1/C2 配置

先写 `charts.json`：

```json
{
  "charts": [
    {
      "id": "seg1",
      "type": "bar",
      "title": "2026 Q2 营收（亿元）",
      "labels": ["Q1", "Q2"],
      "values": [12.3, 15.8]
    },
    {
      "id": "seg2",
      "type": "pie",
      "title": "用户构成",
      "labels": ["个人", "企业", "教育"],
      "values": [55, 30, 15]
    }
  ]
}
```

每种 `type` 的必填字段不一样，写错字段名不会报错到画面上——只会在渲染端画成空图，所以照这张表写：

| type | 必填 | 可选 | 备注 |
|---|---|---|---|
| `bar` / `line` / `pie` | `labels`（非空列表）、`values`（与 `labels` 等长的数值列表） | `title`、`x_label`、`y_label` | pie 另要求 `values` 总和 > 0 |
| `scatter` | `points`：`[[x, y], ...]` 非空（`values` 可替代 `points`，但同样必须是 `[x, y]` 二元组） | `title`、`x_label`、`y_label` | `labels` 被丢弃。一维 `values` 两条入口都在契约层报 `必须是 [x, y]`（`gen_charts.py` 与手写 `images.json` 同一口径）；渲染端那个"按序号补 x"的兜底只有绕过契约的库调用才走得到 |
| `curve` | `curves`：`[{expr, label}, ...]` 非空 | `x_min` / `x_max`（默认 `0` / `10`，仍须 `x_min` < `x_max`）、`points`（采样点数，2..400，默认 80）、`title`、`x_label`、`y_label` | **必须经 `gen_charts.py`**：它把 `curves[].expr` 求值采样成 `curve_datasets`，`images.json` 只认归一化后的形态，手写 `curves` 会被契约层直接拦下 |
| `formula` | `formula`（非空字符串） | `title` | 纯 HTML 文本卡，不产文件 |

`x_label` / `y_label` 是坐标轴标题（渲染端只读这两个键名）：数值带单位、口径要交代时挪到这里，别塞进 `title`。pie 与 formula 没有坐标轴，写了也不显示。

生成：

```bash
python scripts/gen_charts.py -i charts.json -o hf-project/images.json
```

脚本会合并写回已有 `images.json`，不会删除 A/B/D 已存在的映射与 provenance。相同 segment 已存在非 chart 条目、**或同一 id 的 chart 内容变了**（逐字节相同才幂等覆盖）时直接报错，由人工决定，不静默覆盖——改过 charts.json 后先删掉 images.json 里的旧条目再重跑。

`gen_charts.py` 的职责到 `images.json` 为止：它只把 `charts.json` 转换成 `{type:"chart"}` 条目，**不产任何图片文件**——图形由 Hyperframes 渲染阶段用 Chart.js 在浏览器里绘制。注意 Chart.js 画在 canvas 上，**不走页面的 CSS 字体栈**：刻度数字用主题的内嵌等宽栈（`_template.py` 的 `monoStack`），标题/图例/轴名由浏览器系统字体兜底渲染中文，正常用字即可、没有需要额外配置的字体；`composition.css` 的 `@font-face` + `--ctv-font-family` 只管页面文字（字幕、标题、公式卡）。Python 侧不含字体代码，直接以 CLI 调用即可（自带合并写回、原子写入与 chart id 冲突检测）。

### 文字与尺寸

图表、公式、SVG 内部的文字必须按“**进入内容画布后**的最终可读性”设计，而不是按原始文件尺寸设计。

尤其 SVG：竖屏按 980×735 画、横屏按 1067×800 画。正文级文字建议从 35px 起步，页内标题 40–50px；如果内容很密，优先减少文字、扩大图形，不要继续压字号。

图表标题同理：Chart.js 的标题超出容器宽度会被截断，**标题控制在 20 字内**，单位与口径挪进轴标签（`x_label` / `y_label`，见上表）。

文字放进卡片后还要**估一次宽度**：一行汉字数 ≈（容器宽 − 左右内边距）÷ 字号（26px 落在 330 宽、左右各留 34 的卡片里只能放 10 个字）。溢出时换行或加宽卡片，别靠缩字号——缩到 26px 以下两画幅缩放后就读不出来了。

SVG 以 `<img>` 载入时是独立文档，页面的 `--ctv-font-family` 渗不进去，`<style>` 里要自带中文无衬线字体栈（如 `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", "Noto Sans CJK SC", "Noto Sans CJK JP", sans-serif`——Linux 沙箱里 `Noto Sans SC` 会回落到无 CJK 字形的 NotoSans-Regular，`Noto Sans CJK SC/JP` 才是能匹配上的名字，别省）。

## 五、方式 D：VideoGen

**VideoGen 与 ImageGen 同为能力泛称**：模型自身的视频生成多模态能力、平台提供的视频生成工具、或已安装的视频类 Skill，任一可调用即可；本文不列举具体工具名，以当前环境里实际可用的能力为准。

### 适用

只有当“运动本身”是信息的一部分时才使用：过程演示、镜头变化、真实动作、持续状态变化等。

### 三类来源

| 来源 | 获取方式 | `images.json` |
|---|---|---|
| D1 AI 视频 | **VideoGen**：当前环境任一可用的视频生成能力 | `{"src":"images/seg3.mp4","type":"video"}` |
| D2 现成视频 | 自有或已生成的 mp4/webm/mov | 同上 |
| D3 GIF | 已有 GIF 文件 | `{"src":"images/seg3.gif"}` |

### 播放规则

视频默认：

```html
loop muted autoplay playsinline
```

GIF 使用自身循环。

### 动画细则

- 动画不是“默认更高级”；如果没有增加信息，优先 A/B/C。
- 同一期多个 segment 描述同一对象时，锁定主体外观、镜头方向、色调和风格。
- AI 视频不要为了塞满整段时长而强行延长；循环一个短镜头通常比低质量补帧更自然。
- 视频封面可通过 `poster` 提供，避免首帧空白。
