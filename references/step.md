# 第 3 步 · 定格档：让唯帧数成为导演意图

## 一、对标：缺的是采样域，不是又一条位置曲线

2026 年的 MG 有一股很明确的反向潮流：屏幕越刷越快（120Hz 起），一线作品反而
**故意少画几张**。"Animating on twos / on threes"——一秒只画 12 或 8 张唯帧——
连同 stop-motion CGI、可见颗粒、逐帧手绘的不规则，被归到"视觉摩擦 / 手作质感"
这一档里。它和"卡"不是一回事：成片仍按 24fps 逐帧渲染，变的是**画面隔多久才换
一张**。节奏由此从"曲线多顺"转到"停顿多长"，观众读到的是定格动画那种有分量的
呼吸感。同一批趋势里另一条更工程：motion 应当是一套可调的系统（spacing /
stepping / easing 各自成旋钮），而不是每次手 K 一遍关键帧。

把这两条摆到本仓库的动效版图上，缺口就很清楚了：

| 已经有的域 | 谁在管 | 作者能拧的旋钮 |
| --- | --- | --- |
| 位置 / 形状 | `to` / `morph` / `draw` | 位移、路径、描边 |
| 阻尼 | `spring(ζ)` | 阻尼比 |
| 速度 | `momentum` | 预备 / 拉伸 / 跟随 |
| 相位 | `drag` | 链序滞后 / 过冲 / 衰减 |
| 静止 | `hold` | 落位后的静止窗口与慢推 |
| 时序 | `stagger` / `decode` | 错峰窗口、解码波 |
| **采样** | **空的** | — |

`hold` 管"落位之后"，`stagger` 管"几条拍怎么错峰"，`decode` 管"文字按什么顺序
锁"，`spring` 管"怎么停得稳"——**没有一档管一张画停几帧**。前几次迭代把一条
运动能拆的连续量都拆完了，但都共享同一个前提：按 `duration × fps` 满帧采样。

这一档不新增第十种位移语义。仍是一条 `f(p)`，仍落在 `distance`；多出来的只有
时间轴上的一层**量化**，以及把采样密度从内部工程参数升格为作者旋钮。

## 二、唯帧一直是工程参数，只是没被独立消费

`_momentum.frames` 与 `_drag.frames` 都是「每帧一条 `tl.set`」，条数被
`SAMPLES_MIN` / `SAMPLES_MAX` 钳在 12~240，目的只是防产物膨胀；`_step` 的台阶上限
沿用同一个数（`MAX_STEPS` 直接导入），两档的产物都是离散 `tl.set`，膨胀口径不该
分家。作者从头到尾碰不到这个数。

最容易走错的一步是**把这个数直接暴露给作者**。若只是"每两帧写一条、但数值按
满帧算完再重复"，产物条数不变、画面一模一样，HTML 反倒胖了一倍——那是伪定格。
决定画面何时换的不是数值表，是 **`tl.set` 的时刻**。所以这一档必须改时间网格，
而不是改采样数值。反过来也成立：生成期少写几条 `tl.set`，GSAP 会自然保持上一张，
台阶之间不需要任何补间、回调或第二份脚本——这正是 on twos 的画面。

## 三、阶梯的几何：量化 → 抖动 → 左连续

```
K   = every                                每 K 个渲染帧才换一张画
M   = ceil(D·F/K)                           台阶数 → M+1 张唯帧
q_j = min(j·K/(D·F), 1)                    名义进度（不受抖动影响，q_M = 1）
w_j = normalize(raw_j − raw_0)·(1−j/M)²    双频不规则核，w_0 = w_M = 0
τ_j = min(τ^nom_j + timing·w_j/F, 上界)    每张画的显示时刻（抖动单位是"帧"）
s_j = distance · f(q_j)                    位置只认名义进度
```

三条设计决定，都是被成片纪律逼出来的，不是审美偏好：

**① 左连续阶梯，不是取整。** `state_at(t)` 取满足 `τ_j ≤ t` 的最大 j。`t=0` 就是
第 0 张（`w_0=0`，`f(0)=0`），`t=D` 精确落在 `f(1)=1`；再补一条"补到终点"的
`set` 纯属画蛇添足。`dur` 很少正好是 `K/F` 的整数倍，所以**末台阶是时长余数**，
名义网格末帧夹到 `dur`——这不是误差，是"整段刚好演完"的定义。

**② 抖动只进时间域，不进位置域。** 前沿说的 "slight timing variations" 本来就是
**什么时候换画**的不规则，不是"这一张画歪了多少"。位置若也抖，台阶本就少
（M+1 常常只有十几张），落位前一张反向就是整段最显眼的错，还会和 `hold` 的
活动度判据打架。`w_j` 用两个不成整数比的频率叠加、减去 `raw_0` 让首帧不漂、
按峰值归一让 `timing` 能直接当幅度上界，再乘 `(1−j/M)²` 让落位处抖动与它的
一阶导同时归零——与 `_drag._kernel` 同一条纪律，只是一个管位移、一个管时刻。

**③ 时间抖动有硬上界，因为单调性是充要条件。** 相邻两张的名义间隔是 K 帧，抖动
差值最多 `2 × timing` 帧；`时间抖动上限 0.35` 帧 ⇒ 最多 0.7 帧 < K ≥ 2 帧，
`τ_j` 必然严格递增。再放大就会有两张挤到同一时刻，GSAP 只认后写的那条。

**④ 不用 GSAP 的 `steps()` / `snap` / 运行期回调。** 那些都要在渲染端再存一份
实现，Python 侧判据只能退化成对着另一份 JS 自证（`decode.md`、`spring.md` 记过
这笔账）。沿用 `morph` / `momentum` / `drag` 的老路：生成期把 M+1 张唯帧摊成
离散 `tl.set`，渲染端零脚本、零 `onUpdate`，逐帧 `seek()` 可复现。

产物里还有一条这一档独有的静默错：时刻写进 HTML 前锁两位小数，两张唯帧若撞进
同一个 0.01 秒格，成片里就凭空少一张画，而 HTML 与门禁照样全绿（与
`references/rendering.md`「官方校验命令」记的"全 0 项不是通过、是失明"同一类）。
`plan` 给后面每张留一格，`is_well_formed` 再数一次 `round(t, 2)` 的唯一值。

## 四、被否掉的五个方案

| 方案 | 否掉的理由 |
| --- | --- |
| GSAP `steps()` / `snap` ease | 曲线在渲染端解析，Python 判据只能对着另一份实现自证；且 `seek()` 下不同版本的取整边界不敢钉 |
| 位置域也加抖动 | 台阶少，落位前一张反向就是全片最显眼的错；`hold` 的活动度判据会把静止窗口误读成"还在动" |
| 渲染端 `onUpdate` + 累计帧计数 | 靠上一帧状态推进，逐帧 `seek()` 下第 N 帧与直接跳到第 N 帧对不上，成片不可复现 |
| 把 `SAMPLES_MIN/MAX` 开给作者 | 伪定格：每帧都写、数值重复，画面没变只是 HTML 胖一倍；真正决定节奏的是时刻不是条数 |
| 降成片 fps / 用 `repeat` 复制同一帧 | 时间轴单一来源是 `timing_manifest.json`，动帧率就是动旁白对轴；音频与画面会整体错位且不报错 |

## 五、契约与旋钮

`step` 是第九种独立「演」，与 `type` / `count` / `morph` / `from` / `to` / `set` /
`draw` / `momentum` / `drag` 互斥，必配 `target`。**没有新的稿件键、没有
`--ctv-*` 令牌**：只有写了这一拍的 SVG 元素会演，缺省全片一个字节不变（四份
golden 快照照旧）。

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#tile", "duration": 1.2,
   "step": {"axis": "y", "distance": -160, "ease": "power3.out",
            "every": 2, "timing": 0.18, "wavelength": 7}}
]}}}
```

| 旋钮 | 缺省 | 管什么 |
| --- | --- | --- |
| `axis` | 必填 | `"x"` / `"y"`：主轴位移 |
| `distance` | 必填 | 主轴位移（SVG 用户单位，带符号），非零 |
| `ease` | `power3.out` | 主运动曲线；只收无过冲、终点速度归零的 `out` / `inOut` |
| `every` | `2` | **每步帧数 2～4**（on twos / threes / fours）；1 是满帧、没有定格可谈 |
| `timing` | `0.18` | 时间抖动幅度，单位渲染帧，时间抖动上限 0.35；0 = 纯等距阶梯 |
| `wavelength` | `7` | 不规则核的双频波长，单位台阶，3~64 |

`every=2` 且 `timing=0` 仍是一条完全合法的拍：等距定格，等价于把一条普通
`to` 补间按每两帧取一张。**红线不是模板旋钮**：每步帧数、时间抖动上限、波长带、
最少唯帧数都写在 `_step`，不进 `_template.py`，`--set` 碰不到。契约层、渲染端、
跨段接续烘焙调的是同一个 `validate`——手改过的 images.json 把旋钮调坏时，
生成期就炸，不留到成片里静默变成一张不动的图。

`duration` 仍在 step 级（`_timeline` 的口径），`at` / `at_time` / `delay` 照旧；
`step` 属于 `_WHOLE_BEAT_KEYS`，相对链 `at_time:"+N"` 的游标按**整段**推进——
M+1 张唯帧铺满整段，最后一张就在 `pos+dur`，游标若停在起点，下一拍会压在
还没换完的阶梯上。

## 六、生成期会拦什么

| 现象 | 级别 | 怎么消 |
| --- | --- | --- |
| `step` 与 `from` / `to` / `set` / `draw` 同拍 | error | 两条时间线抢同一条 transform 通道，删掉一边 |
| `every=1` / `>4`、`timing>0.35`、`wavelength<3` | error | 分别是满帧、幻灯片、高频噪声；前两个还会破坏时刻单调 |
| `ease` 是 `none` / `linear` / `.in` / 过冲族 / 弹簧 | error | 台阶少，终点速度不归零或带过冲会把最后两张读成一次回弹 |
| 打在 `#cam` 上 | error | 相机层归整页取景，收尾姿态由折层负责 |
| 配 `stagger` / `repeat` / `yoyo` | error | 唯帧网格由 `every` 定；重放会把落定演成又冲一次 |
| `duration × fps / every` 不足 3 张 | error | 至少 3 张唯帧；再短就是瞬跳，改用普通 `to` |
| 台阶数超过 `MAX_STEPS` | error | 定格档不该演长镜头；缩短 `duration` 或改用普通 `to` |
| 两张唯帧撞进同一个 0.01s 格 | error | 帧率过高 / `every` 太小，产物会少一张画；调大 `every` |

## 七、判据落在哪

判据尽量从生成的 HTML 里抠 `tl.set` 来读，不在 Python 侧另写一份"应该生成什么"。
唯一例外是 `_step.plan`——它是契约层、渲染端、接续烘焙共用的真源，测试拿它跟
产物**对账**，而不是拿它替产物背书。

| 一组 | 钉住什么 |
| --- | --- |
| 数学 | `state_at` 是时间的纯函数（乱序调用不改结果）、首末精确、台阶严格递增、抖动幅度有界、位置比单调 |
| 契约 | 文档示例过 `validate_images_json`、与其余八种「演」互斥、红线在消费侧、相对链游标按整段推进 |
| 产物对账 | 条数 = M+1、逐条时刻与数值等于 `frames`、旋钮改了产物跟着走、两画幅一致、两次生成一字节不差 |
| 作用域与接续 | 选择器收在 `#img-{sid}` 里、`bake_settled_state` 把终点折成 x/y 平移、不泄漏 scale |
| 缺省不动 | 没写这一拍的页零新增补间，四份 golden 快照不变 |

跨段接续是最容易漏的一处：只认 `to` / `set` / `attr` 的烘焙不认新档，接续页
第 0 帧元素会弹回原位。`_stage_carry._settle_step` 为此把 `step` 的终点折成
`x` / `y` 平移；这一档不带形变、不带速度，本来就没有姿态可搬。

## 八、什么时候不要

- **文字、表格、数据图**：定格台阶会把逐行落定读成跳字；这些用 `stagger` 或
  `type.decode` 的解码波。
- **一条拍里已经有别的档在动同一元素**：互斥是契约层硬拦，别绕。
- **要"柔和地停住"**：这一档的观感是"一格一格到位"，要丝滑落位用受控弹簧
  `spring` 或普通 `.out` 补间，别拿定格档假装缓动。
- **拍太短**：`duration` 不到 0.4s 时 M+1 只有三四张，读到的是"跳了两下"；
  这一档至少给 0.8s，让 on twos 的节奏成形。
- **整页画布的贴边内容**：每一张唯帧都走完整段行程，先按
  `references/canvas.md` 留够安全边距——出画 warn 是按收尾位算的。
- **全片每一拍都用它**：视觉摩擦之所以有效，是因为它和光滑段落有对比；
  通篇定格只是通篇卡。

写完跑 `run.py --until html`，产物里应当看到目标元素一组 `tl.set`，条数正好是
`ceil(duration × fps / every) + 1`，首帧为 0、末帧精确等于 `distance`，相邻时刻
约 `every/fps` 秒（末台阶是余数，会短一截）。全片动得对不对仍要按
`look.md「交付前四道」`翻 contact sheet——判词只证明「没有明显坏」。
