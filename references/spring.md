# 第 3 步 · 受控弹簧：阻尼比与承接

`ease` 除了 GSAP core 那批多项式曲线，还有一档**受控弹簧**：`spring` / `spring(ζ)`。
它不靠"把位移调大"造首帧速度，而是给落位一个**质量**——元素带着上一拍的速度继续走，
在落点上稳住。这是代码绘制的 motion graphics 里最鲜明的特征，
也是本仓库此前全靠 `power*.out` / `expo.out` 撑着、缺掉的那一态。

该不该动、动多快 → `references/motion.md「四职务」`；一组元素的错峰 →
`references/stagger.md「窗口、曲线、锚点」`；标题为什么不能缩放 →
`references/look.md「三条换版式时会坏的」`。

## 一、为什么标准弹簧进不了本仓库

弹簧在本项目里不是"再加一条好看的曲线"。它和仓库已有的确定性纪律是同一条根：
`params` 表达式白名单禁 `random`、禁时间函数，理由是**逐帧 seek 下靠历史状态算出来的
第 N 帧，和直接跳到第 N 帧会对不上**；代码绘制的 motion graphics 采用闭式弹簧阶跃响应而不是数值
积分，理由一模一样。所以弹簧必须是 `f(p)` 的**闭式解**：给定归一化进度 p 就能算出这一
帧，不积分、不存上一帧速度、不读墙钟。

矛盾出在起步。标准阶跃响应 `x(0)=0, x'(0)=0`——**t=0 的速度是零**。仓库的硬判据是
"首帧位移 ≥ 4px"（见 `references/motion.md「曲线的行程预算」`），按 40px 行程、0.5s、
30fps 实采：

| ζ | 首帧位移 | 走完 90% 用了 | 判定 |
| --- | --- | --- | --- |
| 0.70 | 4.3px | 33% | 勉强 |
| 0.80 | 3.3px | 44% | 首帧不够 |
| 0.85 | 2.9px | 50% | 首帧不够 |
| 1.00 | 2.2px | 66% | 两项都不够 |

也就是说，把常见的 ζ 0.7~0.85 经验区间直接抄进来，四档里三档过不了本仓库的行程
预算。这不是弹簧不好，是**用错了地方**：起步慢的弹簧适合"被抛出去的东西"（松手那一刻
已经有速度），不适合从静止开始的入场落位。

于是本档的初值不是 `x'(0)=0`，而是**承接初速** `x'(0)=0.85·ω`：这一拍是接着上一拍
来的（跨段接续、退场、被推走的物体），不是凭空起跑。同一组实采：

| ζ | 首帧位移 | 走完 90% 用了 | 峰值过冲 |
| --- | --- | --- | --- |
| 0.80 | 14.0px | 26% | 3.3% |
| 0.85 | 13.0px | 30% | 1.3% |
| 0.90 | 12.2px | 35% | 0.2% |
| 1.00 | 10.9px | 47% | 0 |

全带都进得了行程预算。**ζ 下界定在 `0.80` 而不是常见的 `0.70`**：带承接初速时
ζ=0.70 的峰值过冲实测 9.2%，会撞上"落位是一个精确值、不许冲过去再收回来"这条红线
（`back.out(1.7)` 是 9.98%、`elastic.out(1,0.5)` 是 20.44%，两者都已被
`reject_overshoot` 拦在精确落位之外）。0.80 是实测分界：3.3% 的过冲仍在"轻微"里。
照搬经验区间没有意义，按自己的判据裁剪才有。

## 二、契约

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#card", "to": {"y": 0}, "from": {"y": 48},
   "ease": "spring(0.85)", "duration": 0.8}
]}}}
```

写法只有两种：`"spring"`（ζ 取缺省）与 `"spring(0.85)"`。**不收方向后缀**——弹簧是从
0 到 1 的完整阶跃响应，没有 `.in` / `.out` 之分；写 `spring.out` 时 GSAP 查不到这个
键，会静默退回缺省缓动，作者以为演的是弹簧、成片里是另一条曲线。

| 旋钮 | 取值 | 它管什么 |
| --- | --- | --- |
| 阻尼比 ζ | `0.80`~`1.00` | 越小过冲越大；ζ=1 是临界阻尼，零过冲 |
| 缺省 ζ | `1.00` | 不写参数时与仓库既有的"位移不过冲"红线一致 |
| 承接初速系数 | `0.85` | 初速 v₀ = 系数 × ω；内部常量，不暴露给作者 |
| 末帧衰减目标 | `0.004`（0.4%） | 由它反解 ω = −ln(ε)/ζ |
| 过冲预算 | `0.05`（5%） | 峰值越过落位的上限，契约层实算复核 |

一个旋钮就够了。幅度、快慢、疏密仍按 `references/motion.md「入场的两维节奏」` 各走
各的旋钮，弹簧只换**曲线**，不另立一套节奏参数。

### 三条红线

1. **透明度与颜色不许过冲**（分色纪律）。
   ζ<1 的弹簧补间 `opacity` / `color` / `fill` / `stroke`（含 `attr` 里的）会在生成期
   报错：颜色越过 1 再回来读成一次闪白，而且它没有"落位"可看，观众只觉得这一帧脏了。
   位置、尺寸、缩放可以用 ζ<1。
2. **精确落位不许过冲**。字幕换句那类补间（`subtitle.scroll.ease`）走
   `reject_overshoot`，ζ<1 的弹簧同样被拒；写 `"spring"`（ζ=1）或换 `power2.out`。
3. **末帧必须精确落在 1**。闭式响应只在 t→∞ 才等于 1，差 0.4% 就是 40px 位移差
   0.16px——跨段接续时会被读成回弹。所以曲线除以 `raw(1)` 把终点钉死，形状只被抬了
   不到千分之五。

## 三、判据落在哪

`tests/test_spring_ease.py` 钉六件事，其中"产物与曲线同式"照
`tests/test_type_decode.py` 的办法：把产物里那段注册 JS 抠出来，在 Node 里重放，
而不是在 Python 里再写一份实现（两份实现互相对照，一起错的时候测试照样绿）。

| 判据 | 它拦的是什么 |
| --- | --- |
| 端点 `f(0)=0`、`f(1)=1` 精确 | 末帧没落位，页界处回弹 |
| 首帧 ≥ 4px、90% 行程 ≤ 50% 时长 | 起步慢的弹簧被当成入场档用（见第一节实采） |
| 峰值过冲 ≤ 5% 且只上穿一次 | ζ=0.70 时 9.2% 的大幅过冲 |
| 纯函数：同一 p 两次求值恒等，JS 里无墙钟与累计状态 | 逐帧 seek 下两帧对不上 |
| 注册完备性 | 见下 |
| ζ 带、方向后缀、分色 | 契约层 fail-fast，不留到成片里退化 |

**注册完备性**是这档最容易静默坏掉的一处。`spring` 不在钉固的 GSAP core 里，是生成期
调 `gsap.registerEase` 才存在的扩展档。实测：注册了裸 `spring` 之后，
`gsap.parseEase("spring(0.9)")` 会拿到**裸 spring 的函数**、把括号里的 ζ 丢掉，作者写
的阻尼比和成片演的不是一回事，而 GSAP 一声不响。所以生成期扫的是**最终 `gsap_code`**
（模板派生的时间线、`--set` 临时改的 ease、作者写的 `animate.steps` 都已落进这段文本），
按产物里实际出现的**完整串**精确注册，绝不额外注册一个兜底的裸名。产物里没写 spring
时一行注册代码都不注入，四份 golden 一个字节都不变。

## 四、什么时候不要用

- **入场落位**：题头、配图容器、图块从静止开始进场，用 `.out` 档（见
  `references/motion.md「曲线的行程预算」`）。弹簧是**承接**语义，从静止用会读成
  "顿了一下才动"。
- **只变一个元素的小位移**：0.3~0.6s 的短拍里，弹簧的收尾会被切掉一半，
  `power2.out` 更干脆。
- **整屏都在动**：同屏同时动的不超过三处（见 `references/motion.md「三条减法」`），
  弹簧自带一次过冲，多来几条会互相打架。

写完之后 `run.py --until html` 会把上面整张体检表跑一遍；产物里有没有真的注册上，
看 HTML 里 `gsap.registerEase` 那几行的名字是不是和 `ease` 写的一字不差。
