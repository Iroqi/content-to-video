# 第 4 步 · 素材：选哪条路线 + 怎么落盘

本文件答第 4 步里的两个问题：**观众应该看到什么**（选哪条路线）、**素材从哪里来**（检索照片 / 生图 / 手绘 SVG / 现成视频）。第一问"这一页要不要交给导演演"在写稿那一步就答完了，判据见 `references/writing.md`「哪些段值得交给 canvas」。

> **可以跳读**：全片都是槽位版式、素材全是现成位图时，只读「images.json 是唯一统一入口」与「位图素材：检索照片 / 生图」两节就够了。手绘 SVG 与导演编排在 `references/canvas.md`，本文件不复述。
>
> **按症状查**：画面出问题时不必通读本文件，去 `references/rendering.md`「画面翻车速查表」按现象定位成因与去处。

## 三条路线的统一规则

### 1. 先选“表现方式”，再选素材来源

不要把位图 / C / 视频当成三套独立流程。每个 segment 先回答"观众应该看到什么"：

| 内容特征 | 首选方式 | 原因 |
|---|---|---|
| 有明确真实人物、产品、地点、事件、新闻现场 | **位图·检索照片** | 真实实体需要真实影像，避免生成图替代事实照片 |
| 画面里**不需要出现可读文字**：抽象概念、原理、机制意象、氛围、场景 | **位图·生图** | 一句 prompt 出一版，复杂结构它也扛得住，风格还更容易整期统一 |
| 画面里**必须有准确文字/数字**，或必须是精确矢量几何、严谨数据 | **C SVG 矢量示意** | 信息准确性只能自己画，生图的文字不可信 |
| **运动本身携带信息**：真实过程、逐步演进、场景变化 | **视频** | 画成 SVG 是假的连续；`stage:"keep"` 只能接静帧，接不了过程 |

**位图（检索 or 生图）与 C 的分界线只有一条：图内要不要文字。** 要（标签、步骤名、数值、图例、公式）→ C；不要 → **选位图，哪怕内容复杂**。两个方向各有一条实测代价：手绘 SVG 返工率高——构图、图内文字对比度、卡片内文字宽度全得靠人肉自查（见 `canvas.md`「图内文字的对比度」的取色表），改一版就是重画；生图则是**文字崩率高**（见「位图素材」的统一规则），所以它只接不带文字的活。

**视频与位图的分工别搞反**：位图是一帧，视频是段时间。同一件事能画成静帧（一张 SVG 图 + `draw`/`count` 逐拍演）就优先画——它逐帧可复现、能对上旁白的某一秒；只有"过程本身"是信息（真实物理过程、镜头运动、场景变换）才用视频，代价是它走页面墙钟、同秒抓帧不保证一致（见「视频素材」）。

数据图和公式也归到 C：**坐标刻度、柱长比例、扇区角度全都自己算自己标，没有任何一道门禁替你检查几何**。这类内容什么时候该从 4:3 槽位换成整页画布（`layout: "canvas"`）、平时又该穿插几段，判据统一在 `canvas.md`「整页画布」。

再按**信息结构**细分该画成什么形式。别问"我能画什么"，问"哪种形式最能帮观众理解"：

| 信息结构 | 首选形式 | 路线 |
|---|---|---|
| 数值比较 / 占比 / 趋势 / 双变量关系 | bar / pie / line / scatter（比例自己算） | C (SVG) |
| 时间演进（要标年份） | 时间线 | C (SVG) |
| 步骤 / 机制流程（要标步骤名） | 流程图 | C (SVG) |
| 层级 / 关系 / 系统结构（要标节点名） | 树状图 / 网络图 / 架构图 | C (SVG) |
| 几何 / 空间关系，**不带文字** | 生图（isometric / 3D render 风格词） | **位图** |
| 外观、场景、氛围 | 图片 | 位图（检索 or 生图） |
| 真实过程、镜头运动、场景变化 | 短视频 | 视频 |

同一张图若能不写字就说清楚，就从中性形式降级交给生图：时间线可以变成"发光节点串成的路径"，架构图可以变成"层叠的节点群"，标注该说的事让标题和 verse 字幕去讲——省掉一次重画，也免掉图内文字的对比度自查。

图只承担**增量信息**：标题和 verse 已经把话说清楚时，不要为填满画布而画，也不要为“高级感”堆 3D、仪表盘、多图拼贴这类不帮助理解的装饰。

### 2. 统一使用同一个内容画布

- 内容画布：竖屏 980×735，横屏右侧槽位 1067×800（4:3 按整数像素取整）。
- 配图规格有两条：**按 4:3 出图**，**像素要够铺满**。画布是 `cover` 铺满，比例不合会居中裁掉四边；更隐蔽的是第二条——`cover` 只保证填满、**不保证清楚**，一张 400×300 的照片塞进横屏 1067×800 的槽位要放大 2.67 倍，成片里那一段就是糊的，而生成期、`hyperframes check`、渲染日志全都一声不吭（它们查的是"图在不在、能不能解码"，不是"够不够大"）。所以生成期会拿素材的固有像素尺寸跟它要被铺进去的那个框对账，放大超过 1.25 倍（`_media_size.UPSCALE_WARN`）打 `[warn]` 点名哪一段、素材多大、要放大几倍、以及换成多大 / 改走 SVG；超过 2.0 倍（`UPSCALE_SEVERE`）再换一档更重的措辞，直说细节基本没了。**别把这条 warn 当噪音**：它是"这一段成片是不是糊的"唯一的机器证据。位图与 SVG 两条路线本来就能满足（生图选最接近 4:3 的档位；手绘 SVG 的 4:3 落在根节点 viewBox 上，见 `canvas.md`「画布几何：根节点尺寸按版式分两种」）；**SVG 不验尺寸**（矢量放大不失真），只有位图与视频走这一问。视频按 4:3 出片最省事（同样走 `cover`），但它多一条硬约束：**成片只显示前段**，比段落长的视频会被截断，生成期打 `[warn]` 报出实测时长与段落时长（见「视频素材」）。**整页画布（段落 `layout: "canvas"`）是唯一例外**：它铺的是整个画面（1080×1440 / 1920×1080），尺寸对账按整幅算、规格见 `canvas.md`「整页画布」。

### 3. 统一的质量标准

无论来源是什么，都按下面这套标准审：

**内容准确**：画面必须对应当前段落在讲的对象、动作或概念，不接受“气氛类似但事情不对”。

**主体明确**：画面第一眼能看出主角是什么；不要塞过多无关元素。

**可读可看**：如果画面内部有文字、公式、标签，必须在成片观看尺寸下（竖屏与横屏都算）依然清楚；无法保证就不要把关键信息放进素材内部。同一条线也管素材本身：**位图与视频的像素要够铺满它那一页的框**（见「统一使用同一个内容画布」的第二条规格），不够大的素材在成片里就是糊的，而没有任何一道门禁替你说。

**风格统一**：同一期可以混用位图 / SVG / 视频，但要统一背景明暗、主体尺度、主色倾向和视觉密度。方式不同不等于风格失控。

**来源可追溯**：检索照片保留来源 URL 等 provenance；生图 / SVG / 视频也尽量记录生成工具、来源或生成说明，避免二次整理时丢失来源信息。

### 4. 统一的制作流程

每个 segment 都走同一条链：选路线 → 得到媒体文件或可渲染规格 → 落 `images/` 并写进 `images.json` → **人工审关键帧**（主体、构图、文字可读性、与这一段旁白的关系）。素材正确性和实际观感不能只靠 JSON 或脚本判断，最后一步不要因为方式不同就省略。

### 5. images.json 是唯一统一入口

三种路线最终都映射到同一份 `images.json`。静态图最简单：

```json
{
  "seg1": {"src": "images/seg1.png"},
  "seg2": {"src": "images/seg2.jpg"},
  "seg3": {"src": "images/seg3.mp4", "type": "video", "poster": "images/seg3-cover.png"}
}
```

字段：

- `src`：必填，相对 HTML 输出目录的媒体路径。
- `type`：可选，合法取值 `auto`/`image`/`video`/`gif`；缺省即 `auto`（按扩展名判断：`.mp4/.webm/.mov/.avi/.mkv` → video，`.gif` → gif，其余 → image）。gif 与 image 同档，都走 `<img>`。
- `loop` / `muted` / `autoplay` / `playsinline`：可选，视频播放属性，默认均为 `true`。**必须写 JSON 布尔**，字符串 `"false"` 会被契约层拒（渲染端按 `opts.get(flag, True)` 取值，字符串是真值，"关掉循环"会变成"永远循环"）。
- `volume` / `duck` / `fade_in` / `fade_out` / `media_start`：可选，**仅视频**的音轨旋钮。关掉 `muted` 却不写 `volume` 时渲染端会落一个让路默认增益并出声（`duck` 默认再开一条让路 EQ），口径与关闭方式见「视频素材」的「音轨」。
- `poster`：可选，视频加载前显示的封面图，与 `src` 同一校验口径（禁绝对路径、禁越出项目根）。
- `director`：可选，**仅 `.svg`**，`directing.md`「SVG 动画：两档」里的导演档编排块。写了它这张 SVG 才走净化内联、由 GSAP 逐句驱动图内元素；不写就是普通 `<img>` 静态图。结构与语义见下面方式 C「SVG 动画：两档」。
- `stage`：可选，**仅 `.svg`**，目前只认字符串 `"keep"` 一个值——**跨段接续**：这一页不从头画，而是接着上一页演完的那幅画面继续演（写在哪一页的条目上就接续哪一页的前一段）。口径与能接住什么/接不住什么见 `directing.md`「跨段接续」。
- `provider` / `source_url` / `license` / `attribution` / `query`：可选，素材来源记账。二次整理重配时保留旧值不要覆盖，画面不读它们。

值只能是上面这种对象；裸字符串路径（`{"seg1": "images/seg1.png"}`）会在契约层直接报错。

**上面这份键清单就是渲染端读的全部**：写了清单外的键（`alt`、`position`、`fit` 这类凭空发明的写法）不会生效——归一化配图的 `html_renderer._normalize_images`（由 `gen_hyperframes.py` 在生成 HTML 时调用）会打一条 `[warn]` 点名是哪几个键，看到就删掉或换路：想改构图改稿件或 SVG 本体，想改文字就写进文案，images.json 不管这些。

## 位图素材：检索照片 / 生图

位图是**一张静帧**，落盘之后与生图出来的图走完全相同的那条路：同样的 4:3 规格、同样的 `images.json` 映射。所以这一节把两条来源并在一起讲——**先按内容特征选来源，再按下面的共同纪律收尾**。它与 C（SVG）的分界线只有一条：图内要不要文字。

### 何时用检索照片，何时用生图

| 段落讲的是 | 走哪条 | 为什么 |
|---|---|---|
| 真实人物、真实产品、真实地点、真实事件、发布会、比赛现场、新闻现场、历史照片 | **检索** | 真实实体需要真实影像，生成图替代事实照片是造假 |
| 抽象概念、原理、机制意象、情绪意象、无法对应真实照片的内容 | **生图** | 没有对应实体可检索 |
| 需要整期视觉风格统一 | **生图** | 同一套风格词批量出一版，比拼凑真实照片更齐 |
| 几何 / 空间关系、节点群、层叠结构、透视与等距视角（**图内无字**） | **生图** | 这类常被误派给手绘 SVG，但生图一句 prompt 就够，且不返工 |

### 检索流程

用你可用的**联网搜索 / 图片搜索能力**（能力泛称，见 SKILL.md 第 4 步；本技能不内置检索工具）：

1. 从段落标题和正文提炼检索词；中文实体尽量加英文别名或型号。
2. 检索来源页，不要只看缩略图。
3. **逐张打开原图**，确认不是标题党、截图、带角标或与正文无关的图片。
4. 下载到 `hf-project/images/`，命名 `<sid>.<ext>`。
5. 在 `images.json` 中写映射，并保留 provenance。

**找不到合适的真实图时，不要为了"覆盖率"凑图，直接改走生图或 C。**

### 生图规格与 prompt

每个 segment 生成一张**横版 4:3** 图，尺寸在所用能力支持的档位里选最接近 4:3 的（如 1152×864）。同一批 prompt 保持同一背景明暗与风格词。

Prompt 先描述"讲什么"，再描述"怎么画"。不要先写一堆风格词，最后才补主体。推荐顺序：

```text
主体 / 场景
+ 核心动作或结构
+ 视觉关系
+ 风格
+ 背景与色调
```

`diagram / chart / schematic / infographic` 这些词会把坐标轴标签和说明文字一起带进来，末尾补一句 `no text, no labels, no letters, no numbers`。出图后仍要**逐张打开看有没有崩字**——生图的文字崩率高（错字、缺笔、乱码、糊成一团），且崩在图里的字改不动。

### 选图标准（两条来源共用）

- 主体与段落讲的是同一个人、同一个产品、同一个地点或同一事件。

- 分辨率足够；长边低于约 1200px 时，进入成片后容易发虚。
- **入库前裁成 4:3**，保留哪块主体由看图的人判断。

### 不要做

- 把真实人物的 AI 生图冒充现场照片。
- 用同一张泛化图片反复覆盖多个不相关 segment。
- **不要在图里放文字**（label、数字、公式、招牌、界面文本都算）。该标注的信息交给标题区、verse 字幕，或改走方式 C——图内文字的对比度与折行全得靠人肉自查（见 `canvas.md`「图内文字的对比度」）。
- 为了满足 4:3 裁掉关键人物、产品或场景主体——裁之前先确认主体完整，放不下就换图或换路线。
- 为了"高级感"堆 3D、仪表盘、多图拼贴这类不帮助理解的装饰。
- **透明出图不要铺底色**。本技能支持透明 PNG/WEBP 直接叠在画布背景上（见「透明通道」一节）：给 imageGem 这类出图能力下 prompt 时明确"无背景 / transparent background / 透明底"，**别让它填不透明底色**——一旦出图端铺了底色，透明能力就失效，还会盖死主题渐变与 accent 辉光。

### 透明通道：位图也能直接贴背景（无需抠图）

带 alpha 通道的**透明 PNG / WEBP** 与 SVG 等价：渲染端把它当 `<img>` 放进同一张场景图，图里透明的地方会透出主题渐变与 `--seg-accent` 辉光，效果就是 SVG「不铺满幅底」那条。所以 imageGem 这类出图能力只要给出透明底，就能像 SVG 一样直接叠在画布背景上，不必做抠图。

前提与边界：

- **透明只在「同一 scene 内」成立**。本技能是 SVG/HTML scene 合成，`npx hyperframes render` 一次性把背景 + 前景渲成视频帧，alpha 自然保留；不存在「透明 PNG 去叠另一段渲染好的背景视频」这种需要 ffmpeg overlay 的流程。
- **透明由出图端保证，契约层不校验像素内容**。如果前景图「本该透明」却被出图能力填了不透明底色，就会盖死画布——这属于信源问题（对应核心规则「信源不可信 / 视觉真源」），images.json 的 schema 只管路径 / 锚点 / 尺寸这类结构，不查 alpha。看到前景图盖住背景时，回去查上面「不要做」里那条不铺底色的纪律——问题几乎都出在出图端填了底色。

## 视频素材：VideoGen / 现成视频

VideoGen 同为能力泛称，见 SKILL.md 第 4 步。本文不列举具体工具名，以当前环境实际可用的能力为准。

### 什么时候才真的需要它

**只有当"运动本身"是信息的一部分时**：过程演示、镜头变化、真实动作、持续状态变化。判断口径是一句话——**这件事能不能画成一张静帧 + 逐拍补间？** 能，就别用视频：静帧走 SVG 导演档是逐帧可复现的，能精确对上旁白的那一秒；视频做不到（见下面的代价）。

| 来源 | 获取方式 | `images.json` |
|---|---|---|
| AI 视频 | 当前环境任一可用的视频生成能力 | `{"src":"images/seg3.mp4","type":"video"}` |
| 现成视频 | 自有或已生成的 mp4/webm/mov | 同上 |
| GIF | 已有 GIF 文件（走 `<img>`，与位图同档） | `{"src":"images/seg3.gif"}` |

### 已知代价：它走页面墙钟，逐帧不可复现

- **播放进度与段落时间轴不做逐帧同步**。段落显示多久由时间轴决定，视频只是循环填充。比段落长的视频**渲染只显示前段**（生成期按 ffprobe 实测时长打 `[warn]`，报出视频时长与段落时长）。
- **`<video>` 走页面墙钟，多 worker 各自从 0 起播，抓到的帧可能不同**——同一秒的画面不保证可复现，同一份稿件两次渲染可能不一致。这与方式 C「导演」的逐帧 seek 不可比，也与 CSS 氛围循环同类（见 `directing.md`「SVG 动画：两档」的①档）。**画面必须对上某句话时别指望视频帧同步**：改用剪好的静态 poster 序列，或者换成 SVG 导演档编排。
- **原声是第二条进混音器的轨**（见下面「音轨」）：关掉 `muted` 才有声音，且默认与口播同音量叠加。要了原声又不给 `volume`，成片就是两条声音打架——跑完不报错，听不了。

**所以判断口径是**：画面必须对上某句话 → SVG 导演档；只是有个过程在动、观众不需要它停在哪一帧 → 视频可以。是否观感正确仍以预览和成片为准。

### 播放规则

视频默认 `loop muted autoplay playsinline`，四个开关都能在 `images.json` 里显式关掉（布尔 `false` 的写法坑见上面字段一节）。GIF 用自身循环，走 `<img>` 不受这些开关影响。

**视频封面用 `poster` 提供**，避免首帧空白。它与 `src` 同一校验口径（禁绝对路径、禁越出项目根），`poster` 的问题会被单独点名，不影响 `src` 自己的报错。

### 音轨：要原声就一定要写 data-has-audio

视频是**唯一一条不经过第 3 步 TTS、却照样混进成片**的声音。口播是 `<audio id="main-audio">`（`templates/composition.html`），而引擎的 ffmpeg 混音只读两类源：`<audio>` 元素，和**声明了 `data-has-audio="true"` 的 `<video>`**。

所以 `images.json` 里关掉 `muted`（＝我要原声）时，渲染端会**自动**补上 `data-has-audio="true"`。不该由人来记这个属性名：漏了它等于一条都不混，成片有画面、没原声，而生成期、`hyperframes check`、渲染日志全都一声不吭——这正是本技能要堵的那类静默退化。反过来，**静音时绝不能写它**：契约是二选一（静音 / 带音轨），两个都挂会让 lint 的判据失效。

代价跟着来：原声和口播抢同一段频谱。默认该怎么办，见下面「让路」那一条。

#### 让路：默认那一版必须是不盖旁白的那一版

关掉 `muted` 时的默认处置是**脚本替他落一个让路默认**（不是再打一条 `[warn]` 让人自己记）：

- **没写 `volume`** → 渲染端直接落 `data-volume="0.25"`（实测可听档的下沿，见上），并打一条 `[warn]` 点名这一段、说清压成了多少、以及怎么改回去。**1.0 不是默认**：把等响留作默认等于默认交付一支没法听的片子。
- **另外再开一条让路 EQ**（`data-fx-chain`，默认开）：只压整条轨的响度是把原声整个拧小，环境声、音乐、现场厚度一起没了，"要原声"这一诉求只剩一点残余。所以再按 Hyperframes 的 voiceover carve 那一路，在**人声占住的那几档频段**上开槽（1.6k / 2.5k / 4k Hz 三段窄带 peaking，−3/−3/−2 dB），床铺的其余部分保持原样。官方的 carve 是 Studio 分析语音后落下来的一条链（`data-fx-carve` 本身在播放期不读），本技能没有那次分析，给的是同一类链的**静态保守版**——深度只到 −3 dB，不会留下"被挖了个洞"的听觉痕迹。

- **要原声当主体**（采访原声、现场同期声、原声本身就是信息）就显式写 `volume: 1.0` **并**给 `duck: false`：前者收回响度，后者撤掉那条 EQ。两个旋钮各管一半，缺一个都还是被压着的。

#### 四个音轨旋钮

四个音轨旋钮 + `duck` **只对 video 成立**（位图 / SVG / GIF 没有音轨也没有可裁剪的时间轴，写在它们上面会被契约层按"写了不会生效"拒掉）：

| `images.json` | 落到标签 | 说明 |
|---|---|---|
| `volume` | `data-volume` | 增益倍数，1 = 0 dB。不写时由渲染端落让路默认 0.25 |
| `duck` | `data-fx-chain` | 人声频段上开一条让路 EQ；`false` = 撤掉它（原声当主体时用） |
| `fade_in` | `data-fade-in` | 淡入，锚片段自己的入点 |
| `fade_out` | `data-fade-out` | 淡出，锚片段自己的出点 |
| `media_start` | `data-media-start` | 从源片第几秒起播（trim） |

**取值范围不必查**：写错时报错会带上该旋钮的范围与含义（`volume` 写成布尔值会被 Python 的 `isinstance(True, int)` 放过，症状是"要了原声、成片没声音"）。**淡入淡出之和超过本段时长会被引擎按比例压进片段内**，写了一段淡变、实际几乎听不出来。

两条手拼属性才要记住：**`media_start` 只能叫 `data-media-start`**（写成 `data-playback-start` 会渲染出"裁过的画面配没裁过的声音"）；**`data-fx-chain` 里的 JSON 引号必须写成 `&quot;`**（裸双引号会把整条属性截断；渲染器已转义，别在别处手拼这条属性）。

### 动画细则

- 动画不是"默认更高级"。如果没有增加信息，优先位图或 SVG。
- 同一期多个 segment 描述同一对象时，锁定主体外观、镜头方向、色调和风格。
- AI 视频不要为了塞满整段时长而强行延长。**循环一个短镜头通常比低质量补帧更自然**。
- 视频当画布的比例与字号口径与照片一致，见 `canvas.md`「整页画布」末尾那条。
