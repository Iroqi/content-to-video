# 第 3 步 · 透镜档：让位移方向在这一拍之内改变

**"演什么"在第 1 步就定了**（`beats` 写在稿件里）。这一档只答一件事：当这一拍要「一枚透镜扫过画面，同一批元素先被推开、随场心移动改变朝向、再干净地收回去」，而不是「一组元素逐个出现」「一个扰动从中心扩散」或「一整片元素沿曲线流走」，怎么写。画图 → `references/canvas.md`；入场 → `references/look.md`；该不该动 → `references/motion.md`；按距离传播 → `references/wave.md`；沿曲线输运 → `references/flow.md`。

## 一、对标：前沿在打的是「方向随时间转」

2025/2026 的前沿 MG 里最显眼的一支，几份独立来源说的是同一件事——

| 来源 | 点名的手感 | 落到画面上是什么 |
|---|---|---|
| Apple 带起来的 liquid glass / refraction sweep | 一枚半透明玻璃扫过，底下的图形被推开、挤拢、再弹回 | 位移由**玻璃当前在哪**决定，不是由元素自己决定 |
| Senate Media 2026 趋势 | 「mimics the smooth movements of water, combining it with the visual reflections and refractions of glass」 | 液态的连续形变，读成「扫过」而不是「出现」 |
| Motion Luma 的 liquid glassmorphism | refraction / dispersion / caustics | 透镜有**影响半径**，圈外纹丝不动 |
| AE 的 Displacement Map / Liquify、Cavalry 的 field driver | 一张场图驱动一整片元素，各自取自己所在位置的方向 | 方向是位置与时间的函数，不是作者逐个填的常量 |
| 2026 的 depth-driven staging / kinetic variable type | 镜头穿过一层排版，近处错得多、远处错得少 | 幅度随到透镜中心的距离衰减 |

把这一叠词翻成工程语言，还是那三个约束：**几何不许手写**、**起止干净**、**逐帧可复现**。第三条是本仓库的硬纪律；第一条在这一档里比波场档更狠——波场档只让「延迟」退出契约，本档让**场心轨迹、影响半径、每个元素每一帧的位移方向**全部退出契约，只剩图上两个真实元素的 id。

**玻璃的观感不归这一档**。半透明、渐变、高光与色散由 SVG 自己画（`<linearGradient>` / `<radialGradient>` / `<filter>` 经净化保留，见 `references/extensions.md`），或干脆贴一段离线渲好的视频素材（`references/imagery.md`）。视觉质感是素材管线的活，档位只负责确定性的位移场。

## 二、域地图：最后一个空白是方向的时间域

| 档 | 消费的量 | 从哪读出来 | 收尾在哪 |
|---|---|---|---|
| `to` / `morph` / `draw` | 位置 / 形状 | 作者写在补间里 | 终点 |
| `spring` | 阻尼 | 作者选曲线 | 终点 |
| `momentum` | 速度包络（做形变） | 作者给距离 | 终点 |
| `drag` | 相位（一条链共享曲线） | 链序 `φᵢ = i·φ` | 全链一起落定 |
| `step` | 时间量化 | 帧号 | 终点 |
| `hold` | 静止 | 无 | 原位 |
| `stagger` / `decode` | 时序 / 锚点 | 序号 + 分配曲线 | 逐个留在终态 |
| `arc` | 空间曲率（**单个**元素的两条轴） | 作者给幅度 | 终点 |
| `organic` | 值域不规则 | 不公度谐波 | 精确回原位 |
| `trail` | 时间叠加 | 层间 `lag` | 影子收干净 |
| `wave` | 距离 → 波前 → 延迟 | 元素到**固定**震中的欧氏距离 | 每格回原位 |
| `flow` | 一条 path 的弧长 + 切线 | 曲线自身的形状 | 曲线算出的新位置 |
| `lens` | **方向的时间域** | **场心当前位置与元素中心的瞬时连线** | 精确回原位 |

它们有一条从没人写破的共同前提：**一个元素的位移方向在整拍里是定死的**。`wave.radial` 的方向由一个固定震中给出（恒为从那一点向外）；`flow` 的方向由曲线给出，但每个元素只走自己那一小段弧；`arc` 是单个元素两条轴的合成。`params` + `bind` 确实能写出一条随时间变的算术式，但那条式子是作者手写的第二份几何：改图里一个点的坐标，成片纹丝不动且零报错。

**所以这一档不是「第十五条位移曲线」，是补上方向的时间轴。** 与 `wave` 正交：`wave` 增加的是**延迟的空间来源**（谁先动），`lens` 增加的是**方向的时变来源**（此刻往哪走）；两者都在拍末精确回原位。与 `flow` 正交：`flow` 整拍都在走并且落在一个新位置，`lens` 是一次扫过、读完回到原状。与 `organic` 也正交：后者是时间上不公度的多谐波叠加，方向仍是配置里定死的一根轴。

## 三、几何：两个真实元素 → 场心轨迹 → 瞬时方向场

难点不是「让几个元素躲开一枚移动的圆」，而是**场心与半径不许手写**：作者一旦能填坐标或半径，那串数字就是几何的第二份真源。解法是让生成期直接从 SVG 里量：

```
L₀   = center(glass)                        透镜元素的包围盒中心（场心起点）
L₁   = center(to)                           终点元素的包围盒中心（场心终点）
R    = max(w,h)/2 of glass bbox            影响半径，唯一真源是透镜元素自己
cᵢ   = center(cells[i])                     每个元素的包围盒中心（图上真实元素）
L(t) = L₀ + (L₁ − L₀)·t/D                  场心匀速扫过（D = 拍长）
u(t) = sin²(πt/D)                          时间包络：u(0)=u(D)=0，且端点导数为 0
vᵢ(t)= cᵢ − L(t)                           元素到场心的瞬时向量
rᵢ(t)= |vᵢ(t)|,  qᵢ(t) = rᵢ(t)/R
K(q) = (1 − q²)²,  q∈[0,1)，否则 0        紧支撑 bulge 核：q=1 处值与导数精确归零
ûᵢ(t)= vᵢ(t)/rᵢ(t)                         **瞬时**方向单位向量，随场心旋转
Δᵢ(t)= amplitude · u(t) · K(qᵢ(t)) · ûᵢ(t)  bulge 向外 / pinch 向内
```

`ûᵢ(t)` 是整条式子的关键：场心在动，同一元素到它的连线方向就在转。取 `t=0.2s` 与 `t=0.5s` 读同一个元素的 `Δ`，两个向量不共线——这在前面十三档里一次都没发生过。

包围盒走共享的 `_cam_crop._box`（与空带/越界体检、运镜取景、波场档量距离同一份口径），祖先的 translate/scale 由 `_wave.affine_to` 复合；旋转/斜切读不准就判废并出声，不猜一个中心。目标元素内部不再折 transform——那要在这里复刻第二套仿射栈，与「真源不分家」相冲。图元可以是 `rect` / `circle` / `ellipse` / `line` / `polygon` / `polyline` / `path` / `text` / `image`，或包住这些图元的一层 `<g>`。

## 四、六条设计决定，都是被成片纪律逼出来的

**1. 几何一个字都不进契约。** `cells` 只写「哪些元素参与」，`glass` 与 `to` 只写「哪两个真实元素当量测锚点」，`amplitude` 是唯一的幅度旋钮。作者一旦能手写场心坐标或半径，挪动图里一个点，成片里的折射仍停在旧位置且零报错。与波场档的「延迟不进契约」、流线档的「相位不进契约」是同一条纪律的第三次落地：**改图即改编排**。测试里挪一个元素、改一次透镜半径，产物必须跟着变，且只有该变的部分变。

**2. 方向必须是 t 的函数。** 这是本档存在的全部理由，也是它区别于 `wave.radial` 的唯一硬判据：生成期取各元素在 `L₀` 与 `L₁` 两端读到的 `û` 夹角，要求至少一处方向转角 ≥ 6°。所有元素恰好排在透镜轨迹那条直线上、或远在轨迹延长线一侧时，方向恒不转，读成「一组被固定震中推开的点」——那就是 `references/wave.md`，按文件拦，不是参数越界。

**3. 端点精确归零，不是「接近 0」。** `u(t)=sin²(πt/D)` 在 `t=0/D` 处解析值为 0，但浮点 `math.sin(math.pi)` 不是精确 0；`state_at` 对端点与拍外显式短路返回 `0.0`，并把负零归一，避免 `-0.0` 与极小残差写进产物。于是 `state_at(0) == state_at(D) == 0`，**收尾态 = 起始态**，跨段接续没有残留姿态可折。这一点与波场档的紧支撑脉冲同语义，与流线档落在新的几何位置相反。

**4. 核在 R 处值与导数都归零。** `K(q)=(1−q²)²` 让影响半径边界不出现硬切：靠近边界的元素位移平滑趋零，圈外的元素**精确 0**（不是「很小」）。若用 `1−q` 这类带尖角的核，场心扫过格子阵时边界上会读到一次速度突变，成片里是一闪。

**5. 元素不许压在透镜轨迹上。** `û = v/|v|` 在 `r→0` 时未定义，而 `K(0)=1` 恰是峰值——一个正好在轨迹上的元素会被以最大幅度甩向一个算不出的方向。生成期按点到线段的解析距离逐个拦，要求 ≥ `max(1, 0.05·R)`，报错直接说清「离轨迹只有多少、要求多少」。与波场档拦「格子与震中重合」同一类。

**6. 生成期采样成离散 `tl.set`。** 沿用 `morph` / `momentum` / `drag` / `step` / `organic` / `trail` / `wave` / `flow` 的老路：渲染端零脚本、零 `onUpdate`、零依赖，成片里是一串确定的数值，逐帧 `seek()` 下每一帧都是时间的纯函数。渲染端按位移场实时求值、或用 CSS `filter: url(#displacementMap)` 让浏览器逐帧重算，都会让第 N 帧与直接跳到第 N 帧对不上，且 SVG filter 的采样在不同浏览器版本间不保证一致。

**跨段接续**：每个元素收尾都精确回 0，没有残留。`_stage_carry` 仍必须**显式认这一拍**并返回空态，不能靠「这一拍没有 `set`/`to`、恰好 no-op」的巧合——将来给这一档加任何终态，那条巧合就会变成页界处一次静默的闪。

## 五、契约与旋钮

一拍写 `lens`，整段负责全部参与元素。五个键，参与元素 2～12 个：

| 键 | 默认 | 读什么 |
|---|---|---|
| `cells` | 必填 | 2～12 个有序 `#id`，图里真实存在的一组元素；`cells[0]` 必须等于 step 级 `target` |
| `glass` | 必填 | 单个 `#id`，透镜元素；生成期从它读场心起点 **和** 影响半径 `R`，不写坐标 |
| `to` | 必填 | 单个 `#id`，场心终点元素；生成期只读它的包围盒中心 |
| `amplitude` | 必填 | 峰值位移（SVG 用户单位，非零有限数）；实际峰值由几何乘核决定，不必精确达到它 |
| `mode` | `bulge` | `bulge` 向外推（凸透镜放大感）/ `pinch` 向内吸；两者逐帧精确反向 |

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#d1", "duration": 1.2,
   "lens": {"cells": ["#d1", "#d2", "#d3", "#d4"], "glass": "#glass",
            "to": "#to", "amplitude": 60, "mode": "bulge"}}
]}}}
```

图里要有一枚有宽高的透镜、一个小锚点、以及分列轨迹两侧且离轨迹够远的一组元素。`cells` 顺序随作者写（只决定产物里 `tl.set` 的写入顺序，不影响位移场）：

```svg
<circle id="glass" cx="150" cy="367" r="100"/>
<circle id="to"    cx="830" cy="367" r="6"/>
<rect id="d1" x="340" y="327" width="20" height="20"/>
<rect id="d2" x="420" y="387" width="20" height="20"/>
<rect id="d3" x="480" y="327" width="20" height="20"/>
<rect id="d4" x="560" y="387" width="20" height="20"/>
```

这五个图元不用画成玻璃的样子：`#glass` 只贡献 `L₀` 与 `R`，真要半透明高光，另画一层带渐变/滤镜的元素叠在上面即可（它不参与折射，也不会被这一档改动）。

**互斥**：`lens` 与 `from` / `to` / `set` / `draw` / `morph` / `count` / `type` / `momentum` / `drag` / `step` / `organic` / `trail` / `wave` / `flow` / `swarm` 同拍即 error——两条时间线抢同一条 transform 通道，GSAP 后写的那条静默覆盖前一条。不收 `stagger`（把一个场拆成各自起跑）、`repeat` / `yoyo`（包络在收尾精确归零，重放会半路截断）、拍级 `ease`（包络是生成期算死的 `sin²` 窗，不是缓动），不能打在 `#cam`，`glass` / `to` 不能是 `cells` 之一，两者也不能是同一个元素。

## 六、生成期会拦什么

| 现象 | 级别 | 怎么消 |
|---|---|---|
| 未知键 / `cells` 数越界、重复、含 `.class` / `glass` / `to` 非法 / `amplitude` 为零或非有限 / `mode` 非法 | error（契约层） | 只认五个键；锚点必须单个 `#id` 且不在 `cells` 里 |
| `cells[0]` ≠ step 级 `target` | error（契约层） | 折射头就是这一拍的目标，接续烘焙与按文件拦只认 `target` |
| 与别的「演」同拍 / `stagger` / `repeat` / `yoyo` / 拍级 `ease` 挂在 lens 上 / 打在 `#cam` | error | 删掉一边；要逐个出现用 `stagger`，要按距离传播用 `wave` |
| `cells` / `glass` / `to` 在 SVG 里找不到 | error（生成期，按文件拦） | 落空一个不会报错，只会让那一片区域静默不动 |
| 包围盒读不出 / 祖先带 rotate、matrix、skew / 透镜退化成一个点（R=0） | error（生成期，按文件拦） | 改成可量几何的图元或包一层 `<g>`；把透镜画成有宽高的圆或矩形 |
| 两个锚点几乎重合（行程 < 8 个 SVG 单位） | error（生成期） | 把 `to` 画远一些，否则 24fps 下一帧挪不到一像素、方向转不出来 |
| 元素离透镜轨迹太近（< `max(1, 0.05·R)`） | error（生成期） | 把元素挪开轨迹；`û` 在 `r→0` 未定义而那里恰是峰值位移 |
| 所有元素的方向转角都 < 6°（方向不转，退化成 `wave.radial`） | error（生成期） | 把元素排到轨迹两侧，或把两个锚点画到别处 |
| 透镜没扫到任何元素 / 只有一个元素被折射 | error（生成期自查） | 峰值位移由几何决定，按帧实采判；把元素挪进影响半径里、或把透镜画大一点 |
| 段首有位移 / 收尾没收回 / 拍外还在动 / `bulge` 与 `pinch` 不精确反向 / 采样网格不递增 | error（生成期自查） | 正常配置不会出现；出现即说明位移场被改坏了 |
| 拍长 < 0.12s / 帧时刻撞进同一个 0.01s 格 | error（生成期） | 加长 `duration`；否则产物静默少一帧 |

## 七、判据落在哪

`tests/test_lens.py` 一个文件压完 18 条，判据全部**从产物里抠补间来读**，不在 Python 侧另写一份「应该生成什么」的实现。

| 组 | 钉住什么 |
|---|---|
| 信号 | 纯函数（正序/逆序/乱序一致、窗口外夹回端点）、**同一元素方向角在拍内跨度 ≥ 6° 且不共线**、端点精确归零且无负零、核与包络紧支撑、圈外精确 0、bulge / pinch 逐帧精确反向 |
| 几何 | 场心两端 / `R` / 元素中心只从 SVG 量出；方向不转、压在轨迹上、行程不足、`R=0`、锚点落空、`_animate.check_animate` 按文件拦 |
| **改图即改编排** | 挪一个元素 → 产物里只有它的位移序列变，其余不变；改透镜包围盒 → `R` 变、整组峰值一起变 |
| 网格 | 采样带两端、帧时刻严格递增且锁两位、条数 = (帧数+1)×元素数、写入顺序是 `cells` 序、短拍与非法 fps 被拒 |
| 契约 | 红线、与其余十四种「演」互斥、不收错峰/重放/拍级缓动、相机层与折射头对齐、绕过契约层的坏值在生成期炸 |
| **产物级对账** | 从 HTML 抠出的 `tl.set` 序列，锚点、帧数、逐元素选择器与逐帧变量必须与 `_lens.frames` 逐项相等；两画幅各验，两次生成字节相同；`amplitude` / `mode` / `cells` 各自真的改产物 |
| 作用域与接续 | 没写 lens 的页零新增补间；`_stage_carry` 显式认这一拍并返回空态，四个元素在接续页的 transform 为零 |

「方向的时间域」是本档独有的一条判据：既有档位要么根本不读 SVG 坐标、要么只读一次（波前距离、弧长投影），没有哪一档需要读**场心在两个时刻的两个位置**才能判断这一拍成不成立。

## 八、什么时候不要

- **一组元素要逐个出现并留在画面上**：用 `stagger`；要逐行锁定结论文字，用 `references/decode.md`。透镜档演完全部元素精确回原位，读完就散。
- **一个扰动从某处按距离扩散、每个格子波过回原位**：用 `references/wave.md`。那是延迟的几何来源，方向由固定震中一次定死。
- **要一整片元素沿画好的曲线持续走、各处朝不同方向拐弯并落在新位置**：用 `references/flow.md`。流线档是输运，本档是一次扫过。
- **要主体带动一条真实元素的链、全链一起落定**：用 `references/drag.md`。本档没有链序，每个元素只听自己到场心的瞬时连线。
- **要到位停住 / 安静落位**：用 `.out` 档或 `spring`。本档整拍都在扫，收尾确实干净，但中途不该背着一次折射去落位。
- **要液态玻璃的半透明、渐变、高光、色散**：那是 SVG 素材自己的活（见第一节），本档不画质感，只算确定性位移。要更真实的折射可以贴一段离线渲好的视频素材。
- **文字 / 数据图 / 只有两三个元素**：本档只写 `x` / `y`，逐字揭示与数字滚动各有自己的整段语义；两三个点排不出方向场，读成「一起斜着走」。
- **一屏同时动的不超过三处**：一开 lens 就是一整片元素在动，别再叠一层 `organic` 呼吸或 `wave` 涟漪。先问 `--perceptual` 的四道验收够不够。
