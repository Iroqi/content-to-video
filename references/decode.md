# 第 3 步 · 解码式揭示：文字从未定到落定

`images.json` 的 `type` 除了"从空串渐长"，还有一档**整行先在场、逐格/逐组锁定**：
文字先以占位噪声占住每一个格子，随旁白从左到右一格一格锁成真字。这是代码绘制
的 motion graphics 里最认得出的一拍（Opus 5.5 那类片子里叫 decode / scramble），
也是本仓库此前缺的那一态——缺省 `type` 只有"有 / 无"，句子是**还没说完**；
解码档多出"**还没定**"，锁定边就是结论揭晓的那一瞬。

该不该动、动多快 → `references/motion.md`「四职务」；一组元素的错峰 →
`references/stagger.md`「哪些地方不给锚点」；标题为什么不能缩放 →
`references/look.md`「三条换版式时会坏的」。

## 一、这一拍替观众做什么

只说得出"好看"的那条就该删（见 `references/motion.md`「四职务」）。解码档占两职：

| 职务 | 回答 | 落在画面上 |
|---|---|---|
| 引导视线 | 现在该看哪里 | 同屏只有"正在锁定的那一格"在变，视线被钉在读到哪 |
| 推进叙事 | 接下来发生了什么 | 未定 → 已定，正好对上"结论/数据终于揭晓" |

它**不**承担"操作反馈"（成片没有鼠标）、也不做"呼吸/漂浮"——未定格的噪声只在
锁定推进时翻一批，不逐帧闪：成片逐帧 seek 下每帧都变会读成噪点，那是与口播
无关的墙钟动画。

## 二、怎么写这一拍

`type` 里加一个 `decode` 即可，节奏仍走 step 级 `duration` / `ease`：

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 2, "target": "#verdict", "type": {"decode": true}, "duration": 1.2}
]}}}
```

要换锁定方向就把它写成对象（四枚锚点见第五节）：

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 2, "target": "#verdict", "type": {"decode": {"from": "end"}}, "duration": 1.2}
]}}}
```

正文取自那条 `<text>` 自己现成的 `textContent`，与缺省档同一前提——**不要**为了
解码另写一份文案，也不用给图中元素加起始样式。`at` 跟着 manifest 的句子走，锁定
起点就踩在说到结论那一句的重音上。

`canvas_kit` 里它是**节点级**调档（与 `chunk` 同级），一页里只有结论那句该锁就
只给那一句写 `decode: true`；写进 `type` 契约会整页跟着变。换方向写
`"decode": {"from": "end"}`，与 `chunk` 可以同时给，两者都是同一层旋钮。

```json
{"kind": "text", "id": "verdict", "x": 120, "y": 400,
 "content": "同比增长 128%", "type": true, "decode": true}
```

## 三、三条红线

判据在 `tests/test_type_decode.py`：把产物里那段 JS 抠出来，在 Node 里按进度
重放 `onUpdate`（与按单元跳格档同一套办法），逐帧比对文本。

1. **逐帧可复现**。噪声是 `(格号, 已锁定单元数, 原字符码点)` 的确定性哈希，
   产物里不许出现 `Math.random` / `Date` / `performance`。渲染端逐帧 seek 时
   `onUpdate` 按代理量重算，同一时刻两帧必须给出同一行字——墙钟一进来这条
   就断，而且断得没有报错，只是两帧画面不一样。
2. **锁定不回退**。已锁定的单元直接取原文且不再被改写，只有未锁定的格子
   在锁定推进时换一批噪声（`n` 数的是**单元**；缺省逐格档里它恰好等于格数）。
   弹一下又弹回去是"展示变化"的反例（见 `references/motion.md`「四职务」），
   锁定的语义就是**定住**。
3. **末帧钉死**。缓动停在 `N − 1e−13` 时 `floor` 会少一单元，所以 `onComplete`
   无条件写回原文，`onUpdate` 里也把 `n` 夹到 `N`。末帧差一个字，前 1.2 秒
   全白演。

还有一条不是红线但会坏事：**整行不重排**。噪声分宽/窄两栏
（`_images_schema.TYPE_DECODE_WIDE` / `TYPE_DECODE_NARROW`）：原文是全角格就
用全角汉字数字、半角格用半角大写字母数字、空白原样保留。字符数恒等、每格
宽度类别不变，于是解码途中行宽不收缩、落定时不撑开——文字盒左缘站定不动。
把 CJK 格换成半角 ASCII，观众看到的是"字还没定，整行先抖"。

## 四、哪些地方不给解码

- **标题与副标题**：它们走揭示边，字盒左缘站定、不缩放；给标题加一层解码是
  同屏第二件事，读序会被抢。
- **字幕换句**：位移只写在列容器上，行自己一条补间都没有；逐格锁定会把每句
  变成一次独立的动画。
- **正序叙述的段落**："第一步、第二步"的先后是内容排的，不是排版排的，未定态
  反而让人以为前一步还没发生。
- **一屏要读三件以上的事**：同屏同时动的不超过三处（见
  `references/motion.md`「三条减法」），解码已经占了视线那一处。
- **揭晓之后还在场的数字**：结论亮完就停，别让它继续翻——那是稳态循环，
  不是落定。

## 五、两个正交旋钮：一次锁多少、从哪头先锁

`chunk:"word"` 管"一次锁多少"，`decode` 管"没锁的那些格子显示什么"，
`decode.from` 管"从哪头开始锁"——三件事各自独立，可以同写：

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 2, "target": "#verdict",
   "type": {"decode": {"from": "center"}, "chunk": "word"}, "duration": 1.2}
]}}}
```

| from | 锁定顺序 | 用在哪 |
|---|---|---|
| `start`（缺省） | 按读序从左往右 | 顺着旁白逐字揭晓 |
| `end` | 从结论往回卷 | 答案先落定、前提再补上（"128%" 先亮） |
| `center` | 从核心长出来 | 中心词是题眼，两侧是修饰 |
| `edges` | 两端向中线合拢 | 两个条件同时收束到中间那个判断 |

白名单与 `stagger.from` 同源（`_images_schema.STAGGER_ANCHORS`，见
`references/stagger.md`「从哪儿开始动：锚点」），不另抄一份字面量。距离相同时
按下标兜底，排序不依赖 JS 引擎的稳定性——逐帧 seek 要的是**确定**的。

`chunk:"word"` 时一次锁一整个语义单元，组边界与按单元跳格档共用同一份切分
（`html_renderer._TYPE_UNIT_SPLIT_BODY`）：不给同一句话准备两套"哪儿算一组"的
规则。短句用缺省 `char` 就够；字多的结论句再按语义单元跳，读起来才不是逐字蹦。

`decode` 与 `stagger` 仍是两件事：`type` 整段负责一个 `<text>`，错峰是"一组
元素"的事。两者只是共用锚点白名单，不要叠在同一拍上。
