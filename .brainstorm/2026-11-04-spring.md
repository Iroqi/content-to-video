# 受控弹簧：把阻尼比带进逐帧可复现时间线

日期：2026-11-04 · 分支：`feat/opus-spring` · 落点：`_ease.py` / `html_renderer.py` /
`references/spring.md` / `tests/test_spring_ease.py`

这一轮不新增一个"看起来更炫"的动效部件。先把代码绘制动效的工程纪律拆开，对照本仓库
已经接住的部分，找出**真正缺的那一层**，再把它做成能被门禁钉住的东西。

---

## 一、对标：代码绘制动效的工程纪律

这类作品的技术路径是"用代码写 HTML/CSS/Canvas，再由渲染器逐帧抓成 MP4"；本仓库本来就
走同一条（GSAP 时间线 → headless Chrome → MP4）。所以这一轮对标不是照搬某个配色或版式，
而是**把同一套工程纪律补齐**。公开拆解与既有实现里反复出现的几条：

| # | 原则 | 一句话 |
| --- | --- | --- |
| 1 | **确定性 / `seek(t)`** | 一切画在 `seek(t)` 里算完；同一 t 永远同一帧。禁 CSS transition、timer、帧间状态继承、未播种的随机数 |
| 2 | **闭式弹簧** | 弹簧用 closed-form step response，不数值积分；"frame 84 不需要先算 0..83" |
| 3 | **阻尼比带** | ζ=1 零过冲、0.7~0.85 轻微过冲、0.4~0.6 明显过冲、<0.3 多次折返 |
| 4 | **分色纪律** | 位置与尺寸可以弹，opacity 与颜色永不弹（分色规则） |
| 5 | **物体连续性** | 场景之间一个形状变形贯穿，no cuts / no crossfades；转场从画面里已有的元素长出来 |
| 6 | **只动合成层** | 只动 transform / opacity / clip-path；动 width/height 会触发重排 |
| 7 | **节奏对比** | 快切对抗停顿；揭示前留 300~600ms 静止；hold 期间 2% 慢推 |
| 8 | **tokens 单一真源** | 一张 EASE/MS/STAGGER 表，禁内联数字；按职能选曲线而不是一把弹簧走天下 |
| 9 | **字体层级 / HUD** | 一条主线 + 小标签 + 明确读序；观众随时知道在第几章 |
| 10 | **禁用清单** | 禁粒子爆炸、glow、无意义 3D、模板感渐隐、dead beats |

| 8 tokens 单一真源 | `_template.py` + `check_numbers.py` 双向锁 + `--set` 探索旋钮 | 已成 |

| 6 只动合成层 | `_css_guard.py` 管 CSS ↔ GSAP 抢 transform | 半个：只管了 transform 冲突，没管补间触发布局 |

**结论**：缺的是 **2 / 3 / 4**——弹簧物理这一层。仓库所有落位曲线都是 `power*.out` /
`expo.out` / `sine.inOut` 这类**多项式与指数衰减**：首帧速度靠放大 `y` 硬凑（"行程预算"
因此才存在），收尾是纯数学衰减，没有惯性。弹簧物理补上的正是"带着惯性
走、在落点上稳住"这一态。

同时注意：原则 1 与原则 2 是**同一条根**。`params` 白名单禁 `random` 的理由（逐帧 seek
下靠历史状态算出来的第 N 帧，和直接跳到第 N 帧对不上）与逐帧可复现必须采用闭式弹簧、拒绝数值积分
的理由一字不差。所以引入弹簧不是"加个花活"，是把仓库已有的确定性纪律**推广到缓动层**。
这是本轮最硬的设计论点，也是它值得做的原因。

## 三、被否掉的三个方案

**A. 直接放行 `back.out` / `elastic.out`。**
最省事，也最错。这两族峰值过冲 9.98% / 20.44%，且 `bounce` 尾段多次折返；仓库
`reject_overshoot` 就是为它们写的。放行等于把已有红线拆了，换不到"质量"，只换到抖。

**B. 照搬常见区间 ζ ∈ [0.7, 0.85]，做一条标准阶跃响应。**
实采（40px 行程 / 0.5s / 30fps）直接否掉：标准响应 `x'(0)=0`，ζ=0.80 首帧只有 3.3px、
ζ=1.00 只有 2.2px 且走完 90% 要 66% 时长——四档里三档过不了本仓库自己的行程预算。
"起步慢"是二阶系统阶跃响应的固有性质，不是参数没调好。

**C. 把弹簧做成模板默认值，替换某一档 `titleEntrance.rhythm`。**
会同时改掉四份 golden 快照和全片观感，且**违背语义**：入场是从静止起跑，弹簧是承接
（"something a finger throws"）。正确的边界是让作者按这一拍的职能显式选，而不是把新
曲线铺到所有片子上。

**D（顺带否掉）**：做"只动 transform / opacity / clip-path"的生成期门禁。
查了现网：`gen_hyperframes.py` 的柱状图示例合法地补间 `{"to": {"height": 320}}`（SVG
`<rect>` 的几何高度，不是 HTML 布局）。一刀切禁 `height` 会打断一个真实用法，而要把
"SVG 几何属性"与"HTML 触发布局的 CSS 属性"分开判，收益边界模糊。本轮不做，留作下一轮。

## 四、选定方案与数学

**承接语义**：这一拍接着上一拍来，`x(0)=0, x'(0)=v₀=β·ω`（β=0.85 内部常量）。
解标准二阶方程 `x'' + 2ζω·x' + ω²(x−1) = 0`：

```
ζ<1:  x(p) = 1 − e^(−ζωp) · [cos(q p) + ((ζω − v₀)/q) · sin(q p)],  q = ω√(1−ζ²)
ζ=1:  x(p) = 1 − e^(−ωp) · [1 + (ω − v₀)p]
ω     = −ln(ε)/ζ,  ε = 0.004     （末帧前衰减到 0.4%）
f(p)  = x(p) / x(1)              （把末帧精确钉在 1）
```

`f` 是 p 的纯函数：无积分、无帧间状态、无墙钟。`f(0)=0`、`f(1)=1` 精确——跨段接续时
末帧差 0.4% 就会被读成回弹，除法把这件事消掉，代价只是整条曲线被抬了不到千分之五。

**ζ 带裁剪到 [0.80, 1.00]**：带初速时 ζ=0.70 峰值过冲 9.2%（≈`back.out(1.7)`），
撞"落位精确"红线；0.80 是 3.3% 的实测分界。缺省 ζ=1.00（临界阻尼、零过冲），与仓库
既有红线一致；要带轻微过冲得**显式**降 ζ。

**只暴露一个旋钮 ζ**。初速系数、ε、ω 都是内部结构，不进 `images.json`——与
`imageEntrance.arc` "幅度只有一个真源"、节奏"两维各走各的旋钮"同一套克制。

## 五、最隐蔽的一处：注册完备性

`spring` 不在钉固的 GSAP 3.14.2 core 里，是生成期调 `gsap.registerEase` 注册的扩展档。
实测（`/tmp` 里对钉固 bundle 逐条试）：

```
未注册                    parseEase("spring(0.8)")  → undefined（GSAP 静默回落缺省缓动）
注册了裸 "spring" 之后     parseEase("spring(0.9)")  → 拿到裸 spring 的函数，ζ 被丢掉
注册了精确 "spring(0.8)"   parseEase("spring(0.8)")  → 0.9502…（正确）
```

第二种最坏：作者写 `spring(0.9)`，成片演的是 ζ=1，且**一声不响**。这正是 `_ease.py`
模块头反复防的"目录放行、采样器不认"的同类失效。所以：

- `EASE_FAMILIES` 保持"GSAP core 目录"的纯粹语义不变，另立 `EXTENSION_FAMILIES`；
  顺带避免污染 `test_ease.py` 里对目录的遍历断言（那条会给每个族试 `.in/.out/.inOut`，
  而弹簧没有方向）。
- 生成期**扫最终 `gsap_code`**（模板派生时间线、`--set`、作者写的 `animate.steps` 都已
  落进这段文本），按实际出现的完整串精确注册，不注册兜底裸名。
- 产物里没写 spring 时**一行都不注入** → 四份 golden 一个字节不变。
- `--allow-ease` 宽松档不把 spring 当"未知族名"放行成静默退化。

## 六、判据设计

六条，见 `references/spring.md「判据落在哪」`。其中两条是方法论上的坚持：

- **行程预算用同一把尺**：新档不能因为"是弹簧"就豁免首帧 4px / 末段 50%。第一节的
  实采表既是设计依据，也是判据——它证明了"为什么必须是承接初速"。
- **产物级重放**：照 `test_type_decode.py` 的办法，把产物里那段注册 JS 抠出来在 Node
  里 stub 掉 `gsap.registerEase` 后重放，逐点比对 Python 曲线。Python 里再写一份 JS
  实现只会变成两份互相对照的实现，一起错的时候测试照样绿。

## 七、迭代记录

1. **第 1 轮**：`_ease.py` 加闭式解 + 契约；`html_renderer.py` 加条件注册 + 分色门禁。

   承接初速；再发现 ζ=0.70 带初速时过冲 9.2% → 下界收到 0.80。两次都是**被仓库既有
