# 第 3 步 · 配图：先接住想看的画面，再选形式与素材

## 先答这一问：说不出名字的画面

使用者往往只觉得「画面该是某种感觉」，却说不出该叫什么、该用什么。这一节只答
这件事：**挑一句最接近的说法就行，剩下的交给这份 skill 去定**。答完往下走
「两种形式的统一规则」。

> 使用者读到「大多数时候，答案是：什么都不用做」就可以停。后面「给执行者」
> 那一节是给按这份 skill 干活的 agent 看的，里面的词不用记、不用选、也不用填。

### 不用你决定的四件事

- **不用选库、不用选渲染方式**，也不用知道画面是怎么一帧一帧生成出来的。
- **不用装东西、不用写配置、不用给技术词**。说清观众该看到什么就够了。
- **说不出名字很正常**。下面左列就是给你挑的，挑最接近的一句；挑不出来也有兜底。
- **拿不准时只回答一个问题**：「你要的是画面自己在动，还是有一段现成片子要放进去？」除此之外不该再追问你任何选型问题。

这四句不是客套。成片的时间轴由配音的句子长度定死，画面每一帧都得能按时刻复现；
所以「用什么库」这类问题本来就不该由使用者回答——答错了不是风格不对，是成片根本出不来。

### 你会怎么说 → 观众看到什么

| 你会这么说 | 观众看到的效果 | 你只需给 | 什么时候别这么做 |
| --- | --- | --- | --- |
| 「像手画的 / 铅笔草图 / 别太规整」 | 边缘有点抖，还是原来那张图 | 一张画好的图，或什么都不给 | 图里文字多时别用，抖过会糊字 |
| 「像老游戏 / 8-bit / 马赛克感」 | 颜色压成几档、边缘变硬 | 一张画好的图 | 有渐变、细线或数据标注时别用 |
| 「纸面 / 版画 / 干净的手绘线」 | 线略微不均匀，但不抢内容 | 一张画好的图 | 要严谨对账的数据图别用 |
| 「要个会转的东西 / 产品转一圈」 | 一段自己会动的画面 | 一句话描述 + 这一段讲多久 | 要跟旁白逐句精确对上时别用 |
| 「流光 / 粒子 / 液态 / 光斑」 | 一层连续流动的质感 | 同上 | 要观众读出准确数值时别用 |
| 「我有一段现成视频 / 录屏」 | 素材原样放进去 | 文件本身 | 原声和口播抢同一段声音时先想清楚 |
| 「字要跟着节奏 / 逐个跳出来」 | 文字一行行落定 | 什么都不用 | 只有一行字时别用 |
| 「数字自己长出来 / 按远近扩散」 | 数据一项项落定，或一圈圈荡开 | 什么都不用 | 元素只有两三个时别用「荡开」 |
| 「要个会走路的小人 / 卡通角色」 | 见下一段的劝退 | — | 别硬做 |
| 「随便 / 你看着办 / 高级一点」 | 默认版式，干干净净 | 什么都不用 | — |

图从哪来、图里要不要放字，往下「两种形式的统一规则」第 1 节就答这件事。
左列任何一句都不需要你补技术词；补了反而是把活揽回去了。

### 大多数时候，答案是：什么都不用做

表后半段那几句——字逐个跳、数字长出来、随便你看着办——**本来就在默认能力里**，
不需要额外装什么，也不需要额外回答什么。这张表最重要的作用不是把你导向某个工具，
而是别让你为一个默认就能解决的问题去折腾一遍。

两处要直说的边界：

- **会走路的小人 / 卡通角色先劝退**。成片是逐帧取出来再编码的，没有骨架也没有状态机；
  真要角色动起来，就按「要个会转的东西」那条，在管线外渲成一段短片再放进来，
  别指望画面里实时驱动一个角色。
- **一段自己会动的片子，没法同时按旁白逐句改画面**。要精确对拍，就别选视频素材那条路。

兜底规则只有一条：**没匹配上任何一行，就走默认版式**——不追问、不替你猜风格、
不临时加东西。「随便」不是需求没说清，是一个合法且常见的答案。

## 给执行者：这些话对应哪条路

> 这一节不是给使用者看的。上面那张表**不许出现选型词**：库名、渲染方式、
> 预设名、配置文件名，一次都不许。使用者要的是观感，实现由这层翻译掉。

| 使用者的话 | 归到哪条路 | 具体怎么落，见 |
| --- | --- | --- |
| 像手画的 / 像老游戏 / 纸面版画 | 画风后处理：只加工已画好的图，不改编排 | `references/extensions.md`、`references/canvas.md` |
| 会转的东西 / 流光粒子 / 现成视频录屏 | 视频素材：在管线外渲成短片，当配图挂进去 | 本文件「两种形式的统一规则」 |
| 字跟着节奏 / 逐个跳 | 现有档位：逐行落定 | `references/decode.md`、`references/stagger.md` |
| 数字长出来 / 按远近扩散 | 现有档位：计数与波场 | `references/motion.md`、`references/wave.md` |
| 一整片东西顺着一条弧线流过去 / 像被水流带着拐弯 | 现有档位：曲线流场 | `references/flow.md` |
| 像隔着一块玻璃看过去 / 透镜扫过时底下的字被推开又弹回 | 现有档位：瞬时折射场 | `references/lens.md` |
| 一整片点自己散开 / 像一群鸟互相避让 / 元素彼此推挤着盘旋 | 现有档位：邻域相互作用场 | `references/swarm.md` |
| 会走路的小人 | 劝退，改走视频素材 | 本文件「两种形式的统一规则」 |
| 随便 / 你看着办 / 没匹配上 | 默认路：不触发任何额外处理 | — |

三条硬约束：

1. **换画风不动编排**。画风只加工图，编排按图里的元素寻址；换过画风之后，
   原来那一套逐拍动作必须照常生效。做不到这条，说明耦合错了层。
2. **视频素材与逐拍编排互斥**。别把一段自带动势的片子塞进还要跟着旁白变画面的段里。
3. **没匹配上就走默认**。不许为了「显得做了点什么」而替使用者挑一个工具。

这一节只负责把人话翻成路线，具体契约、参数、命令都在指过去的那几份文档里。
把 `references/extensions.md` 整份删掉，使用者部分仍然读得通、走得下去；底层换工具时，
这一节一个字都不用改——技术细节必须是**可删的二跳**。

### 怎么算这层做对了

- 一个只会说「我要手绘感、别的你看着办」的使用者，能否不问任何技术名词就拿到成片？
- 使用者说「要个会转的东西」时，执行者是否不问「用哪个库」就自己落到视频素材？
- 删掉维护者文档，使用者部分是否完整；换掉底层工具，这份是否零改动？
- 这层有没有让任何一步变长：不新增必填项、不新增要装的东西、不新增要回答的问题？

## 两种形式的统一规则

### 1. 先选“表现方式”，再选素材来源

| 内容特征 | 首选方式 |
|---|---|
| 画面里**不需要出现可读文字**：抽象概念、原理、氛围、场景 | **ImageGen 生图** |
| 画面里**必须有准确文字/数字**，或必须精确矢量几何、严谨数据 | **SVG 矢量示意** |

**分界线只有一条：图内要不要文字。** 要（标签、步骤名、数值、图例、公式）→ SVG；不要 → ImageGen，哪怕内容复杂——生图文字崩率高。**只有 SVG 能"演"**：ImageGen 图是静帧，只能当素材贴进画面（入场收拢之后不再动）。数据图与公式一律 SVG：刻度、柱长、扇区角度自己算自己标（自查见 `canvas.md`「数据图的几何自查」）；要跟旁白逐拍走只用 SVG 并写 `animate`（`references/motion.md`）。

按**信息结构**定形式：

| 信息结构 | 首选形式 | 形式 |
|---|---|---|
| 数值比较 / 占比 / 趋势 / 双变量关系 | bar / pie / line / scatter | SVG |
| 时间演进（要标年份） | 时间线 | SVG |
| 步骤 / 机制流程（要标步骤名） | 流程图 | SVG |
| 层级 / 关系 / 系统结构（要标节点名） | 树状图 / 网络图 / 架构图 | SVG |
| 几何 / 空间关系，**不带文字** | 生图（isometric / 3D 风格词） | ImageGen |
| 外观、场景、氛围 | 图片 | ImageGen |

能不用文字说清楚就别写文字，交给生图（省一次重画、免掉图内文字对比度自查）。图只承担**增量信息**：标题和 verse 已说清时不画，不为"高级感"堆 3D / 仪表盘 / 拼贴。

### 2. 统一使用同一个内容画布

- 内容画布（真源见 `canvas.md`「画布几何」）：竖屏 980×735、横屏右侧槽位 1067×800（4:3 按整数像素取整）。**两个画幅的图槽都是 4:3 横版**——竖屏成片的图也是横图，别按竖屏比例出图。
- 配图规格两条：**按 4:3 出图**、**像素要够铺满**。渲染端是 `object-fit: cover`——**裁边铺满，不是 contain 留黑边**：比例不一致的部分对称裁掉，裁哪块由 cover 定不由你定；只保证填满、**不保证清楚**——放大超过 1.25 倍（`_media_size.UPSCALE_WARN`）打 `[warn]` 点名哪段、素材多大、要放大几倍，超过 2.0 倍（`UPSCALE_SEVERE`）直说细节基本没了；cover 裁掉超过 20% 画面（`_media_size.CROP_WARN`）另有一条 warn 说明裁掉多少、去哪换档位。**别把这些 warn 当噪音**：它们是"这一段成片是不是糊的、构图是不是被切了"唯一的机器证据，生成期就喊。ImageGen 图按最接近 4:3 的档位出；**SVG 不验尺寸**（矢量放大不失真）。
- **整页画布（`layout:"canvas"`）是唯一例外**：铺整个画面，尺寸对账按整幅算（规格见 `canvas.md`「整页画布」）。
- **只有槽位版式的 SVG 查比例**：SVG 是矢量的，`cover` 裁边不会让它变糊，所以像素够不够只管栅格图；但"画在里面的字"会在裁边时被切掉，而 HTML 里它还在。比例与槽位框不符由生成期 `slot_svg_ratio_errors` 拦（`hyperframes check` 对此只报一句 `container_overflow`，看不出该改根节点还是改内容），`--draft` 下降 warn。

### 3. 统一的制作流程

选形式 → 生图/画 SVG → **预处理**（去水印 → 裁成槽位比例）→ 落 `images/` 并写 `images.json` → **人工审关键帧**（主体、构图、文字可读性、与旁白关系）。预处理是入库前的标准动作，不是看到成片不对再补救。

### 4. images.json 是唯一统一入口

两种形式都映射到同一份 `images.json`：

```json
{
  "seg1": {"src": "images/seg1.png"},
  "seg2": {"src": "images/seg2.svg"}
}
```

字段（封闭键集：写清单外的键不生效且 `_normalize_images` 打 `[warn]` 点名，`_` 开头的键按草稿处理、放行但同样不生效，裸字符串路径 `{"seg1": "images/seg1.png"}` 直接报错）：

- `src`：必填，相对 HTML 输出目录的媒体路径。
- `type`：可选，`auto`/`image`，缺省 `auto`（按扩展名判；`.gif` 走 `<img>`，与 ImageGen 图同档）。
- `animate`：可选，**仅 `.svg`**，编排块（见 `references/motion.md`「契约」）。写了才净化内联、由 GSAP 逐句驱动；不写就是普通 `<img>` 静态图。两页都是整页画布且同一张 `src` 时，后一页自动接续上一页演完的画面（没有开关，见同文件「跨段接续」）。
- `media_start`：可选，**仅 video**，从源片第几秒起播（缺省 0）。可用长度是"片长 − media_start"：起播点越过片尾时这一段**整段没有画面**（生成期 exit 1）；不够这一段长打 `[warn]`（末帧停在画面上），超出则尾部被截断。
- `provider`/`license`：可选，素材来源记账（生图记录生成工具与授权）；二次整理保留旧值不要覆盖，画面不读。

### 5. 没有生图能力时：走无图降级档

宿主没有 ImageGen（或这一段确实不该配图）且**连 SVG 也画不出来**时，槽位段缺图会留一块空图槽——既不是图，也不像留白，成片读起来像渲染失败。加 `--slot-no-image` 撤掉图槽，把空间交给句子流：

```bash
python scripts/gen_hyperframes.py -m hf-project/timing_manifest.json \
  -o hf-project/index.html --images hf-project/images.json --slot-no-image
```

| 影响范围 | 行为 |
|---|---|
| 槽位段**没图** | 不生成图槽，卡片挂 `text-only`，句子流铺满内容区（竖屏窗口高从 280px 放宽到内容区上沿，实测 1076px） |
| 槽位段**有图** | 照旧出图槽——这一档不会把作者画好的图变成"不显示" |
| agenda 页（开屏/结尾） | 本来就不出图槽，**不受影响** |
| 满幅页（`canvas`） | 缺图在生成期就拦下（那页没有图就只剩一条字幕），这一档不放行 |

日志会打一行 `[notice]` 点名哪几段进了降级档，缺图那条 `[warn]` 照旧保留（作者可能只是漏配）。**这仍然是降级，不是推荐**：画面明显素一些，横向画幅还会空出右半边。能用 SVG 就用 SVG（矢量图不吃生图配额，还能进导演档演起来）；这一档只保证"没有生图能力也能出一版能看的成片"。

## ImageGen 素材：生图

### 生图规格与 prompt

**三档尺寸，选 `1536×1024`**。能力端只有 `1536×1024`（横）/ `1024×1024`（方）/ `1024×1536`（竖），**没有 4:3 档**，而两个画幅的图槽都是 4:3 横版：横图约裁 11%，方图裁 25%、竖图裁一半——生成期按段打 `[warn]` 点名哪段裁了多少。

每段一张图，同一批保持同一背景明暗与风格词。Prompt 先写"讲什么"再写"怎么画"（主体/场景 → 核心动作或结构 → 视觉关系 → 风格 → 背景与色调）。`diagram / chart / schematic / infographic` 这类词会把轴标签和文字带进来，末尾补 `no text, no labels, no letters, no numbers`。出图后**逐张看有没有崩字**——生图文字崩率高（错字、缺笔、乱码），崩在图里的字改不动。

### 水印：逐张看，平滑背景补、复杂纹理裁

水印**因模型而异，没有通用的关闭开关**（`footnote` 之类的参数传不传都一样）。所以只能**出图后逐张看右下角**：盖了就在**入库前处理掉**，与"裁成 4:3"合并为同一步预处理。

**背景平滑的用印章式补，别裁**——从水印正上方裁一块同尺寸的干净区域贴回原处，构图一点不损失（实测水印区残留从 65 降到 1）：

```bash
# 例：水印 bbox 左上角 (1206,956)、尺寸 288×34；取样区取它正上方同一块 (1206,922)
ffmpeg -i in.png -filter_complex \
  "[0:v]split=2[a][b];[a]crop=288:34:1206:922[c];[b][c]overlay=1206:956" out.png
```

**补之前先判背景平不平滑**——纹理不一致会留一块补丁，比水印本身更显眼：

```bash
# YAVG < 40 → 印章式安全；≥ 40 → 别补，走下面的裁切
ffmpeg -i in.png -filter_complex \
  "[0:v]crop=288:34:1206:956[a];[0:v]crop=288:34:1206:922[b];\
[a][b]blend=all_mode=difference,signalstats,\
metadata=print:key=lavfi.signalstats.YAVG" -f null - 2>&1 | grep YAVG
```

**裁掉是兜底**：复杂纹理（密集图案、人脸、文字密集区）或判据说别补时才走——先裁水印、再裁比例，一次裁好保住主体。裁完按上面的算术重算，别让图掉进放大告警。

### 选图标准

- 主体与段落讲的是同一个人、产品、地点或事件。
- 长边低于约 1200px 时进成片容易发虚。
- **入库前裁成 4:3**（先去水印），保留哪块主体由人判断（`cover` 只认框的中心）。

### 透明通道：ImageGen 也能直接贴背景（无需抠图）

带 alpha 的**透明 PNG / WEBP** 与 SVG 等价：渲染端把它当 `<img>` 放进同一张场景图，透明处透出主题渐变与 `--seg-accent` 辉光，不必抠图。边界：

- **透明只在同一个 scene 内成立**：渲染一次性把背景+前景合成成帧，没有第二次 overlay 的机会。
- **契约层不校验像素**：前景被填了不透明底色就会盖死画布。看到前景盖背景，回查出图端有没有填底色。
