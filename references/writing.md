# 第 1 步 · 写稿：字段规范与内容类型写法

`segments_source.json` 的字段语义与缺省兜底，加几种常见内容类型怎么写。

## 先定编排：哪些段值得交给 canvas

写稿时就挑出哪几段写 `layout:"canvas"` 交给导演逐拍演，剩下的交给槽位版式管构图。导演档 = 该段 SVG 净化内联成活 DOM，由 GSAP 按 `timing_manifest` 句子时间轴逐拍驱动（写法见 `references/canvas.md`「SVG 动画：两档」）。

**值得演**（旁白里有顺序、有过程、有"变化本身"）：

- 推导或机制一步步走：公式代入、流程逐格、因果链一节节接上
- 数据在长：坐标轴描出来（`draw`）、柱形升起、数字滚到目标值（`count`）
- 形状之间要"变"而不是"换"：分布从尖到平、同拓扑 `morph`
- 讲到哪推到哪：对 `<g id="cam">` 补间的运镜
- 一句话里多个对象逐个点名：`stagger` + class 目标

**明确不值得**（老实交给模板，别为"高级感"演）：

- 真实人物 / 产品 / 地点 / 事件现场 → 生图；ImageGen 图进不了导演档
- 抽象概念意象、氛围、场景，且图内不需要可读文字 → 生图一句 prompt 的事
- 一句话就能讲清的静态事实 → 图只是装饰

选了"演"就一起认领：① 整页画布**没有模板兜构图**，及格线变成"暂停一帧还成立"（判据在 `references/canvas.md`「整页画布的密度与层次」）；② 导演档**只管"什么时候出现"**，几何自己算、画错了没有门禁替你发现（见 `references/canvas.md`「数据图的几何自查」）。

## 字段规范

**字段集是封闭的**。每一层只认本文件列出的键（顶层 / `segments[]` / `dialogue[]` 每轮 / `speakers` 条目，清单在 `_source_schema.py` 的 `SOURCE_KEYS` / `SEGMENT_KEYS` / `TURN_KEYS` / `SPEAKER_KEYS`）。多写一个键，`validate_segments_source()` 报错并列出本层合法清单。别拿稿件当记事本写 `_note`，备注放外面。

对话轮次只认 `speaker` / `text`。给单句换音色写不通——音色只能按说话人在 `speakers` 里声明（见「对话字段（顶层）」）。

### 段落级字段（segments[] 内）

- `id`（可选）：稳定标识，用作 `images.json` 键与配图文件名。缺省按数组顺序取 `seg1`/`seg2`…。显式 id 必须以 `seg` 开头，字母开头、仅字母/数字/`-`/`_`、1–64 字符，跨段唯一；`opening`/`closing` 为结构性页保留。改顺序、删/插段时，显式 id 让已定稿配图不用重命名。
- **`title`（必填）**：画面标题，要短、直接。**优先一行内，最多两行**：**竖屏**标题区定高，超两行直接裁掉；**横屏**不钳行数，只按长度降字号（阈值见 `references/rendering.md`「画面结构」）。段落 `layout:"canvas"` 时标题不上画面，这两条钳制与它无关。段落顺序就是数组顺序，不在 `text` 里写"第N条"。
- **`tagline`（可选）**：标题下方小字（公司/机构名、章节名、发言人、来源书名、概念分类），由前置的整理信源时写入。内容段省略或留空时 pipeline 兜底为"补充阅读"，**保证画面不因字段缺省静默消失**；opening/closing 的 tagline 按顶层字段规则，缺省不显示 kicker。
- `accent`（可选，有默认值）：段落强调色，缺省沿**情绪色温弧**按段序取（见下条）。只接受 `#rgb`/`#rrggbb` 与 CSS 标准色名；`rgb()`、`var()`、拼错色名在契约层直接报错。它会拼进成片 HTML 三处上下文，属不可信数据。

  **缺省色温弧**（不写 `accent` 时的取色规则，真源 `_theme.arc_accent_indices`）：色板按段数排成一条有方向的弧——

  | 段数 | 取到的色 | 读法 |
  | --- | --- | --- |
  | 3 | 天蓝 → 蓝绿混 → 金黄 | 冷开场、过渡、峰值收束 |
  | 4 | 天蓝 → 青 → 橙 → 金黄 | 峰值落在收尾段 |
  | 6 | 天蓝 → 青 → 橙 → 金黄 → 粉 → 红 | 走满整条弧，红收尾（最强语气） |
  | ≥7 | 整条弧等分，相邻段取中间混色 | 段数再多也不会撞成同色 |

  **把最需要"分量"的那一段放在峰值位**（3 段是第 3 段，4 段是第 4 段，6 段是第 4 段）；开场自动拿到最冷的调子，正读作"先讲背景"。

  要自己钉一支色就写 `accent`——显式值**不参与弧**、也不把弧拉长，其余未写的段照旧铺弧。
- `layout`（可选）：**不写 = 槽位版式**（标题区 + 配图槽 + verse 句子流）；写 `"canvas"` = **整页画布**（配图铺满整个画面，渲染器不生成标题层与句子流层，标题和上画面文字全由配图自己画）。穿插节奏与选型判据在 `references/canvas.md`「整页画布」。三条后果：① 该段**必须有配图**，没图就只剩进度条空帧，直接报错；② `title` 仍必填，但只喂开屏/结尾 agenda 行，**不再出现在该段画面上**；③ 该段口播**没有 HTML 字幕层**（DOM 不生成），要句子出现在画面就得自己画进 SVG（导演档 `type`/`at` 能逐拍揭示，见 `references/canvas.md`「SVG 动画：两档」）——静音/听障观看时观众只剩画面，口播关键句务必画进图里。双人对话别放进整页画布，否则轮次信息只剩声音。
  取值只有 `"canvas"` 给内容段：`"agenda"` 是结构性页那一档，内容段手写它契约层直接报错（那页的行是从全片其它段投影出来的）；大小写或空格写错同样报错——静默退回槽位版式会让画里的标题和 HTML 标题同框。结构性页漏盖 `layout` 时按 id 兜回 agenda。结构性页换版式用顶层 `opening_layout` / `closing_layout`（不写 = pipeline 盖 `"agenda"`；手写 manifest 时可直接写 `"canvas"`）。几何与对比度见 `references/rendering.md`「画面结构」与 `references/canvas.md`「整页画布」。
- `speed`（可选，有默认值）：段落级语速，覆盖全局 `--speed`。
- `voice_id` / `voice_style`（可选，有默认值）：内容段音色与语气，覆盖全局；正文换音色靠它。`voice_id` 必须取预置音色表里的 ID（见 `references/tts_pipeline.md`），写错直接报错；两者都参与句子音频指纹，改音色后 `--resume` 重合成受影响句子。对话段落别在这里指定，音色归 `speakers` 注册表。opening/closing 是自动造的结构性页，**不支持**这两个字段，换开场音色用全局 `--voice-id`。
- `text` / `dialogue`（**二选一，必填其一**）：
  - `text`（字符串）：单人独白，管线自动分句。
  - `dialogue`（数组）：**双人/多人对话段**，`[{speaker, text}, ...]` 按轮次交替发言。要求：① 顶层必须声明 `speakers` 字典，每个 `speaker` 值都要在其中；② 每轮 `text` 非空且**须含至少一个可成句的字符**，纯空白/纯标点分句后为空直接报错。建议每轮以终止标点收尾——整轮一个终止标点都没有会被当一句合成，长串不分句拖长字幕 cue。
    ```json
    {
      "speakers": {
        "host":  {"voice_id": "茉莉", "label": "主播"},
        "guide": {"voice_id": "苏打", "label": "讲解", "voice_style": "耐心讲解，逻辑清晰"}
      },
      "segments": [
        {
          "title": "反向传播算法",
          "tagline": "深度学习基础",
          "dialogue": [
            {"speaker": "host",  "text": "反向传播听起来很复杂，能简单说说吗？"},
            {"speaker": "guide", "text": "简单说，就是把预测误差从输出层往回传，一层层告诉每个参数该怎么调整。"}
          ]
        }
      ]
    }
    ```
    一轮轮的说话人按顺序拼成该段完整句子列表，字幕与时间轴共用同一序列；**每轮用 `speakers` 里声明的音色合成，互不影响**。说话人还以**行首标签**进画面：manifest 存句子级 `speaker` 与 turns，渲染端在**轮次切换的首句**行首挂标签（同一人连说三句只挂第一句）。`label` 因此是**上墙文字**：单行、不收分号、**最多 6 字**（`_source_schema.SPEAKER_LABEL_MAX_CHARS`，两画幅同值）——它跟正文抢同一行字幕，再长就把正文挤到第二行顶掉下一句。超限契约层直接报错（label 是作者自起的短名：「主播」「讲解」「嘉宾」）。没写 `label` 按**回退后的 speaker 名**判，speaker 名也别起太长。音色搭配见 `references/tts_pipeline.md`。
- 分句与句长（`text`/`dialogue` 共用）：断句只认终止标点，逗号不切句（认哪些以 `scripts/_text.py` 的 `split_sentences` 为准：中文 `。！？；`、ASCII `;` 与换行都切；ASCII `.!?` 需后随空白或文末，不误切小数点、`Mr.`、`U.S.`）。**句末的引号跟着句子走**（`张三说："好的。"然后走了。` 切成两句，第二句不会以孤立引号开头），引号配对按嵌套深度算，双语混排的 `（他说：“走。”）` 也能正确收口。
  **句长两档，都不拦截**。超过 **45 字**逐句打 `[warn] 第 N 句长达 …`（整句写进一行字幕，CSS 折成好几行占掉句子流窗口，念出来偏喘）；**32–45 字**按段汇总打一条 `[hint]`（只提醒"还能再断一句"；按段计数不逐句刷屏）。两档根治方式相同：写稿时在逗号处拆句。
  切完还有**反向合并**：不足 **5 字**的片段并到下一片段，凑够 **8 字**才独立成行；句尾还没凑够并进上一行。`停。别动。` 是一行，`停。往左边走三步再停下。` 也是一行。阈值按**字符**数不分中英，尤其容易吃掉中文强调短句——**想让一句话独占一行字幕，它得满 5 字**。
- 上墙的一行只承载一个事实，所以**不收分号**：这些字段直接印成画面一行，写了 `；`/`;` 契约层当场报错并打回原文（判定在 `_validate._validate_display_text`，名单是 `_source_schema.ON_SCREEN_TOP_KEYS` 与 `ON_SCREEN_SEGMENT_KEYS`）。哪几个算上墙不必背——报错按字段名点名：顶层 `*_title` + `opening_tagline` / `closing_tagline` / `cta`，段落 `title` / `tagline` / `takeaway`。**口播四字段不受此限**：`opening`/`closing`/`text`/`dialogue` 可以写分号（分句器把分号当终止标点，念出来本来就是两次停顿）。
- `takeaway`（可选，仅内容段有意义）：一句话要点总结，显示在**结尾 agenda 卡**对应行，缺省回退该段 `title`。写观众该带走的那句话，**单行**字符串（agenda 每段一行），含换行契约层直接拒绝。

### 开场/结尾专用顶层字段

- `opening_layout` / `closing_layout`（可选）：把那一页从 agenda 投影卡换成**整页海报**。写 `"canvas"` 时走内容段整页画布同一条路；下面几条 agenda 字段照旧写，仍是数据源，只是不上那一页画面——标题和要点得自己画进图里。不写 = `"agenda"`，判据见 `references/canvas.md`「整页画布」。
- `opening_title` / `closing_title`：agenda 卡大标题。`opening_title` 缺省回退顶层 `title`，再缺省"本期内容"；`closing_title` 缺省"小结"。写稿时按主题显式设置。
- `opening_tagline` / `closing_tagline`：卡标题上方的等宽小字 kicker（如 `AI WEEKLY · 2026-W38`）。缺省空字符串 → 不显示（与内容段 tagline 兜底不同）。
- `cta`（可选）：结尾卡尾行，带 `→` 前缀。**至多一条**，行动号召或下期预告二选一；**单行**，含换行契约层拒绝。缺省不显示。
- `opening` / `closing`（口播正文）：**不写就没有这两页**——agenda 卡只在该段有口播句子时才生成，不写时成片从第一个内容段直接开场。键名写错同样"没有这一页"（`closing_text`）；这一页缺省而稿件里还有 `opening_*`/`closing_*` 字段时，组装阶段向 stderr 打 `[warn]` 点名跟着失效的键。`opening` 建议一次说完"主题 + 为什么值得看"；`closing` 建议"回顾主线 + 一句收束"。

agenda 卡行为：开屏行 = 各内容段标题 + 预计时长（`m:ss`）；结尾行 = 各段 `takeaway` + 至多一条 `cta` 尾行（`takeaway` 缺省回退标题）。总行数硬上限：两画幅统一 **7 行**（`_template.py` 的 `agenda.maxRows`）。超上限**静默截断、要点优先**：先整条丢 `cta` 尾行，正文仍超才裁尾丢正文行；不放"另有 N 条"提示，四种丢弃都只向 stderr 打 `[warn]`。四种里含两种 `cta` 无处可画（没有 closing 段 / `closing_layout:"canvas"`）。所以内容段数量就是写稿约束：两画幅最多 7 段，≤6 段才放得下 `cta`。

agenda 行**单行不换行**。超长两道闸：Python 侧 `nameTrim` 竖屏 20 字 / 横屏 26 字，按**字数**硬截断——切掉的字直接不上画面、**没有省略号**，只打 `[warn]` 报出切掉的尾巴；第二道才由 CSS 补省略号（只处理截断后仍超列宽的半角/混排字宽偏差）。竖屏实测安全线：`takeaway`/`cta` 约 17 个汉字以内。写长了先看渲染日志那条 `[warn]`，再在预览里翻到结尾卡核对。

agenda 大标题（`opening_title`/`closing_title`）长度守卫，两画幅行数预算不同。**竖屏**留两行余量：标题在单行容量（约 11 字）到两行容量（约 22 字）之间自然折行、字号不动，**超两行容量才降字号**硬压进两行。**横屏锁一行**：agenda 卡行距更紧，整列预算按单行标题排，超单行容量（约 18 字）立刻降字号硬压进一行。字数是按当前模板字号折算的粗估，以渲染日志为准；两者都只在**降字号**时打 `[warn]`，竖屏 12–22 字那段折行区间安静放行——别把"没告警"读成"没折行"。

### 对话字段（顶层）

- `speakers`（仅对话段落需要）：说话人注册表，对象格式 `{speaker 名: {voice_id, label?, voice_style?}}`。任何段落用到 `dialogue` 时必需，且每个 `dialogue[].speaker` 都要在此声明。
  - `voice_id`（必填）：预设音色，取值见 `references/tts_pipeline.md`。
  - `label`（可选，**上墙文字**）：说话人显示名，缺省回退 speaker 名本身。受上墙三道管：**单行、不收分号、最多 6 字**，超限契约层直接报错（写法与后果见上面 `dialogue` 条目）。
  - `voice_style`（可选）：语气风格描述，覆盖全局 `--voice-style`。

### 语速默认值

`opening`/`closing` 段落默认语速 **`1.2`**（比正文慢一点，更像正常讲解节奏），可用 `opening_speed` / `closing_speed` 顶层字段覆盖。正文段落未单独指定 `speed` 时跟随全局 `--speed`（倍率语义与默认值见 `references/tts_pipeline.md`）。

## 内容类型举例

内容段不分章节 / 叙事模式，所有文字统一走 verse 句子流字幕，段内不另设正文卡 / 要点条 / 徽标。**全稿禁 emoji**：title、tagline、口播 text、takeaway、cta 一律不放（分类标签用 `tagline` 写文字）。

- **承接句**（段落切换唯一的听觉线索）：转场只有换页 wipe/line（见 `references/rendering.md`「动画」），每个内容段第一句必须完成"从上一段到这里"的桥接。句式贴内容、禁整期同款复读：回顾式（"看完 X 的发布，另一家也没闲着……"）、递进式（"如果说 X 解决了'能不能'，那 Y 决定的是'好不好'……"）、设问式（"那普通用户能感受到什么变化？"）、场景式（"把镜头拉到用户这边……"）。
- **首次引入故事/案例**：先用一两句交代"人物是谁、在哪、之前发生了什么"再进情节。反例："他伸手去拿第二柄剑，没想到重达七八十斤，直接脱手……"（观众不知道这是谁）；正例："金庸笔下，剑魔独孤求败晚年埋下三柄剑。杨过来到剑冢，先取第一柄……"（两句铺垫情节就立住）。铺垫只限信源里有的信息，不得为顺溜编造前情。
- **产品评测 / 开箱**：按"外观 → 核心体验 → 优缺点 → 总结"走。配图：真实外观用生图（产品名+型号）；参数对比用 SVG（跑分柱状图）；抽象体验（"上手曲线"）用生图。
- **周报 / 工作总结**：从一周记录里挑 4–6 个值得让团队/老板知道的要点，新闻播报口吻。数据类进展配 SVG 数据图。
  ```json
  {
    "opening": "大家好，这是我这一周的工作播报。",
    "segments": [
      {"title": "AI 助手接入新模型", "tagline": "本周进展", "text": "这周把助手接上了新模型，摘要和翻译的准确率都明显提升。"},
      {"title": "修复长文截断问题", "tagline": "本周进展", "text": "上周反馈的长文截断也定位到了，是分块边界的问题，这周已经修好。"},
      {"title": "下周计划", "tagline": "展望", "text": "下周计划把多轮对话的上下文再拉长一倍，并补一组回归测试。"}
    ]
  }
  ```
- **播客 / 视频节选摘要**：从转写稿挑 5–8 个最有信息量的观点/金句意思（不逐字复述），做成"3 分钟看完这期播客说了什么"。原节目是"主持人 + 嘉宾"对谈时用 `dialogue` + 顶层 `speakers` 更贴近原味。
- **书评 / 影评**：按"核心观点/情节脉络 → 亮点 → 局限 → 值不值得看"组织；配图走生图（书封/海报风格意象图）。
- **财报 / 数据报告解读**：逐段完整讲解，**SVG 用得最多的场景**——每提到一个具体数字（营收、增长率、占比）就配一张对应柱状/折线/饼图，不配"看起来像财报"的意象图或无关公司照片。
  ```json
  {
    "segments": [
      {"title": "营收同比增长", "tagline": "2026 Q2 财报", "text": "本季度营收同比增长百分之十八，主要靠海外市场放量。"},
      {"title": "用户构成变化", "tagline": "2026 Q2 财报", "text": "用户构成上，企业客户占比从三成升到四成。"}
    ]
  }
  ```
  这类图都是**手绘 SVG**：`images/segN.svg` + 一条 `src` 映射就是全部，刻度/柱长/扇区自己算并自查（见 `references/canvas.md`「数据图的几何自查」）；要不要换整页画布见同文件「整页画布」。

**怎么选**：先问两个问题——① 目标是从很多候选里**挑重点**，还是把材料**讲完整**？② 每个点要不要配真实数据（→ SVG）、抽象示意图（→ 生图）？选型细则见 `references/imagery.md`。答完这两问，写法就跟「字段规范」一致，不需要为每种内容类型学一套新规则。
