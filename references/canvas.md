# 第 4 步 · 怎么画：方式 C 的 SVG

本文件只讲**这张手写 SVG 怎么画才合格**：根节点尺寸、要不要铺满幅底、图内文字对比度、整页画布的密度层次，以及画完之后自己动手量的那几把尺。选不选这条路见 `references/writing.md`「哪些段值得交给 canvas」和 `references/imagery.md`「先选“表现方式”，再选素材来源」；位图与视频路线的规格、落盘与音轨在 `references/imagery.md`；**让它跟着旁白逐拍动起来**见 `references/directing.md`。

> **动笔前先读这五节**：「画布几何」「不铺满幅底」「图内文字的对比度」「数据图的几何自查」「文字与尺寸」。管线和 `hyperframes check` 都看不见图里画得对不对——画错不会有任何报错，只会在成片上看出来。整页画布（`layout:"canvas"`）再加一节「整页画布的密度与层次」：槽位版式有模板兜构图，画布没有，暂停一帧还成立才算及格。
>
> **按症状查**：`references/rendering.md`「画面翻车速查表」里与图内文字、压字、起止帧有关的条目。



## 方式 C：SVG 矢量示意图

方式 C 用于“信息本身应该被画出来”的内容：**数据图、公式、示意图现在都走这同一条路线**。库替你算的那部分没了——刻度分档、比例映射、数值定位全变成手工活，而且没有任何一道门禁量得到画错的比例。

**定位：图内必须出现准确文字（术语、步骤名、数值、图例）或必须是精确几何关系时的首选。** 不带文字的画面一律先试 B——SVG 改方向就是重画一遍，而生图换一句 prompt 就行。

承担文字示意时它仍是表现力上限最高的一种，**不等于"简笔线框图"**：渐变、光影层次、等距视角、装饰细节都可以把示意图提到成片质感；如果发现自己在画单色方块加直线，就是画得太素了。但别把这份力气花在"画一个 3D 分子结构"上——那不带文字，是 B 的活。

数据与公式的红线——数据必须直接来自信源或可追溯的数据源：

- 不为“好看”改数字；估算值必须在画面或文案里标明，不得画成事实。
- 不使用误导性比例（截断坐标轴、面积失真对比等）；不隐藏或省略单位。
- 不编造不存在的数据点、关系或会改变含义的关键关系。

四条获取路径：

- **官方 registry 的现成块**（先搜再手画）：`npx hyperframes catalog --query "<想要的效果>"` 搜、`hyperframes add <name>` 装；库里有数百个现成的图与动效块（柱状图竞赛、kinetic type、转场等），而官方 CLI 把"动手写之前先搜一遍"写成强制约定。**查询必须写英文**——索引是英文的，中文查询返回空，且不会提示"这是查询语言的问题"，看上去就是"没有这个块"。代价说在前面：那些块是 HTML/JS 片段，而本技能的时间轴与版式是自己的——整页画布吃的是净化内联 SVG、由导演按句驱动（见 `directing.md`「SVG 动画：两档」），所以拿来的块要么落在槽位/装饰这类不进导演的位置，要么重写成导演能驱的形态，并复验决定性（不许墙钟动画与 `Math.random`，判据见 `references/rendering.md`「动画」）。
- **手绘 SVG**：按该段内容自己写 `.svg` 放入 `images/`，适合该段特有的机制/结构。
- **SVG 图库 / 现成素材**：品牌 logo、通用图标优先用成熟的开源 SVG 库（如 simple-icons、lucide、tabler）或开放许可素材，而不是凭印象手画一个“长得像”的；同一期用同一套图标库、统一线宽风格，来源与 license 记进 provenance。
- **SVG 动画**：有两档——**氛围循环**（墙钟，`<img>` 载入）和**时间轴同步的「导演」**（净化内联，由 GSAP 逐句驱动）。选型、写法与各自的代价见 `directing.md`「SVG 动画：两档」。一句话分界：只要”画面得对上某句话”，就用导演，别用墙钟循环。

映射都走普通 `src`：

```json
{
  "seg4": {"src": "images/seg4.svg"}
}
```

外部 SVG 以 `<img>` 载入（内部脚本不会执行），但仍只从干净知名来源获取，不引入来源不明的素材。

### 画布几何：根节点尺寸按版式分两种

**先看这一段是哪种 `layout`，两种的根节点尺寸不一样，写错会被门禁判 error。**

| 版式 | 根节点尺寸（竖屏） | 横屏 | 比例 | 门禁 |
| --- | --- | --- | --- | --- |
| 槽位（不写 `layout`，默认） | 980×735 | 1067×800 | 4:3 | `check_svg.py`（默认档） |
| 整页画布（`layout: "canvas"`） | 1080×1440 | 1920×1080 | 3:4 / 16:9 | `check_svg.py --layout canvas --aspect ...` |

**槽位版式写 4:3**，写死在根节点上：

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="980" height="735" viewBox="0 0 980 735">
```

- 内容画布竖屏 980×735、横屏 1067×800 **都是 4:3**，所以照上面的竖屏尺寸画一份就两画幅通用，不必出两张。
- 画布是 `cover` 铺满（见 `references/rendering.md`）：viewBox 不是 4:3 时短边对齐、长边居中裁掉，贴边的图内文字、图例、卡片描边会缺一块，内置动画还会露出位移被切的痕迹。要改就改根节点的画布尺寸再重排内容，**别靠缩内容凑比例**。
- 图库来的图标（simple-icons / lucide / tabler 多为 24×24，即 1:1）**不能整幅当配图**，只能作为 4:3 画布里的一个元素套进 `<g transform="translate(…) scale(…)">`，四周留出与同段其他图一致的边距。

**整页画布写当前画幅的原生尺寸**（竖屏 1080×1440、横屏 1920×1080），不是 4:3——它铺的是整个画面，压根不进那个 4:3 图槽。照 980×735 画会被 `check_svg --layout canvas` 判"根节点比例不是 3:4"而拒收。这两个尺寸是 `scripts/_template.py` 里 `canvas.vertical` / `canvas.landscape` 的值（`check_svg` 与 `canvas_kit` 读的是同一份），改版式时它们一起动。

- 整页画布没有第二条路：它不 `cover` 裁切，是整幅铺满，viewBox 与画幅不一致时整张图被拉变形。
- 尺寸真源在模板里，**别在 SVG 里手写 px 当权威值**。用 `python scripts/canvas_kit.py --aspect portrait -o …` 出图，它按模板尺寸出并自带 `check_svg` 画布门禁自查。
- **图内两行文字压字只有 `hyperframes check` 能量到**（Layout 阶段的 `content_overlap`）。最常踩的一处：`canvas_kit` 的 `bars` 把数值标签写在 `base_y + label 档字号`（竖屏 32px、横屏 28px，取自 `canvas_kit.TIERS` 的 label 档），你在同一块面板下方另起一行说明文字时，两行很容易只差十来个像素。留够一行字号（`TIERS` 里最大那档的 1.2 倍以上）的间距。`check_svg` 静态查不到这件事——它不解析图内元素的两两关系。

**这两条管线都不检查**：`gen_hyperframes.py` 只校验文件存在，量不到根节点比例。画完跑 `python scripts/check_svg.py images/`（整页画布加 `--layout canvas --aspect portrait|landscape`，**档位与 `--layout` 必须与稿件对得上**，否则判的是另一套标准）。它报出来的每一条都自带口径与免责——例如对比度那条会说明"压在自画的浅色底板上时不成立"——照它说的改即可，不必回头查文档；本文件只写它**管不到**的那部分。图内文字是否真的溢出、**图内文字之间是否互相压字**、数据图的刻度与比例是否画对，它都查不到——压字那条只有 `hyperframes check` 的 Layout 阶段能测（它对净化内联的 SVG 逐帧量），仍要自己盯，见下面几节。

### 不铺满幅底：配图直接画在页面上

根节点下**不要写铺满 viewBox 的背景 `<rect>`**。"框"有两处来源：自铺的满幅面板（比页面渐变更亮更蓝，四边那道色差就是框），以及 CSS 给槽位的 1px accent 内描边与外发光——后者 SVG 配图会自动挂 `bare-media` 撤掉。两层都没了之后，透明处透出的是主题渐变和该段 `--seg-accent` 的氛围光（`.seg-card::after`），示意图直接落在页面上，还自动染上本段主色。

- **图内留白从此算版式**。有框时左边距随便留；没框之后图内第一行文字与页面标题的起始轴线直接可比——竖屏槽位左边缘正落在 `segCard.padding` 的 50px 轴上，图内再缩进 60 就是 110px，明显不同轴。要么缩进收到 0（贴边不被裁，靠的是上一节那条 4:3 + `cover`），要么明确当图例、不追求对齐。下笔时就得定，框不再替你兜着。
- **图内文字只在起指示作用时才写**：轴标签、刻度、单位、数值、图例、步骤名，判据是"不写这行字这张图就读不出来"。没有要指示的就不留字。**标题不在其中**——卡片标题就是这张图的标题，框一撤，图内那行大字立刻跟它并排比高低。
- **辉光开始参与配色**：面板本来把氛围光挡死了，透明后 `--seg-accent` 直接压在图区中心（竖屏 15%、横屏 13%）。「位图素材」那条"主体与 accent 色保持同色相倾向"从此对 SVG 同样生效，下笔前先看这段用什么 accent；次要文字也要跟着提亮一档，见下一节那张表。
- **局部底板照旧可画**，取消的只是"整幅满铺"这一件事。

**整页画布（`layout: "canvas"`）同一条，而且更吃紧**：别再铺 `#0b1020` 这类满幅底板。这一页底下模板本来就画着背景三层（类名与实现见 `references/rendering.md`「画面结构」），SVG 留透明，那三层就从你画的内容背后透出来。代价与例外：底色从此由 `--theme` 决定，整页画布的对比度门禁也照它算（见下面「图内文字的对比度」，整页画布只 warn）；确实要把整页换成另一种底色（浅色页、照片感场景）才自己画一张满幅 rect，那等于放弃这三层，`check_svg.py --layout canvas` 会 warn 提醒、有意为之就忽略。

### 图内文字的对比度：定色在前，自查在后

**没人会告诉你图内文字看不看得清**：SVG 以 `<img>` 载入，内部文字不属于 HTML 文本流，管线里没有任何一道检查会量它——把标签色换成与背景几乎同色的 `#1a2536`（对比度 1.2:1），从生成到渲染全程零报错。所以取色表把"定色"放在自查之前。

**想要一道真门禁：做一次性内联副本，别改产物**。把 `<img src="images/x.svg">` 那一行替换成该 SVG 文件的**内容**，其余一律不动，对这份副本跑 `hyperframes check`——Contrast 就把图内文字当 HTML 文本来量了。

**副本只用来问门禁，绝不能当产物。** `<img>` 载入的 SVG 按 data 处理，浏览器不执行它的 `<script>`；一旦内联进 DOM 它就是同源的活 SVG，脚本照执行（实测往里注入 `document.title="PWNED"`，内联后标题就变了）。所以渲染与交付用的 `index.html` 必须保持 `<img>` 形态，内联版只活在 scratch 目录里。

**这一条只约束"未净化的普通 SVG"。** 写了 `director` 的那张 SVG 是唯一例外：它交付时就是内联的活 DOM，但内联前必过 `scripts/_svg_sanitize.py` 净化，`<script>`/`on*`/外链已被删干净，脚本无从执行。见 `references/directing.md`「SVG 动画：两档」。

**判定线**（WCAG）：正文与标签 ≥ 4.5:1，图内最大字号那一档（≥24px，或 ≥18.66px 加粗；按上面那条，它通常是图例名或底板上的大字，不是标题）≥ 3:1，低于 3:1 重画。4.5:1 只是及格线——图内小字还要经两画幅缩放和成片压缩编码，次要文字按 ≥ 7:1 取色。

**深色主题取色表**（底 = 页面渐变叠上该段 accent 辉光。**页底**列是不叠辉光的区间，**最坏**列是**全部预置 accent**（色板见 `scripts/_theme.py`）× 全部渐变 stop × 竖屏 15%/横屏 13% 全组合里的最低值）：

| 用途 | 取色 | 对比度 |
|---|---|---|
| 图内最大字号 | `#f2f6fc` | 页底 17.7–18.6，最坏 12.7 |
| 主标签 | `#dbe6f5` | 页底 15.2–16.0，最坏 10.9 |
| 次要说明下限 | `#a8bdd6` | 最坏 7.2，刚好守住 ≥7。旧值 `#8fa6c2` 页底有 7.7–8.1，被暖橙辉光吃到 5.5 就不够了 |
| 不要用 | `#6b7c93` | 页底 4.5–4.7、最坏 3.2，两档都越线 |
| 背景深蓝族 | `#0c1320` `#16233a` `#1a2536` | 1.0–1.3:1，出现在 `fill` 上就是瞎字；不铺满幅底之后它们只属于**局部底板** |

**三条最常踩的**：

- **深色文字只能待在明确的浅色底板上**。符号常写成近黑 `#0c1320` 摆到浅色渐变圆盘上（圆盘上 15.1:1，没问题）——可圆盘一挪、一删、或换了渐变，这行字立刻瞎掉。改任何底板颜色，都要同时复核压在它上面的文字；`fill` 能就近写死就别靠 `<g>` 继承。
- **背景色族不得当文字色**（深色主题下）。同一支深蓝只用于背景与面板。判据是"这个色值属不属于背景族"，不是"看起来有没有对比度"——`check_svg.py` 的家族集就是"深蓝族 ∪ 当前主题渐变的各档 stop"，改主题不用改检查规则。
- **半透明按合成后的颜色算**。`opacity` / `fill-opacity` 会真实吃掉对比度：50% 的 `#dbe6f5` 叠在 `#0c1320` 上合成 `#747c8a`，只剩 4.4:1。要弱化文字就换一个更暗的实色，不要用透明度。唯一的例外是整页画布上导演元素的 `opacity="0"`——那是**起始态**不是弱化（终帧才亮，见上面「初始状态自己画」），`check_svg.py --layout canvas` 不对它报，但 `0.1~0.79` 这些中间档照报，因为亮起来的那一帧本身就偏灰。

**这一节能被机械查到什么程度**：`check_svg.py` 对字面 hex 填充一律按**主题渐变的最坏一档**算一次 WCAG 对比度。槽位版式底色确定，所以低于 3:1 判 error、低于 4.5:1 判 warn，背景族当文字色直接 error。**整页画布只 warn，不 error**——画布上的字很可能正压着作者自画的浅色局部底板，按页底算出来的数对它不成立。渐变底、写在 `class` 里的色、局部底板上的字，它一概管不到：上面这张取色表该自己查还得查，真要量一次照下面那套内联副本 + `check` 的程序办。

### 整页画布（段落 `layout: "canvas"`，结构性页用顶层 `opening_layout` / `closing_layout`）：这一张 SVG 就是整个画面

**什么时候换整页**（选型判据只写在这一节，别处一律指向这里）：

- **内容装不下 4:3 槽位**：数据关系、长时序、多层系统图——槽位就这么大，硬塞的结果是把字号压到「文字与尺寸」那条 26px 下限以下。
- **这一页本身就该是一张海报**：章首、转折、结论、金句。卡片版式是"标题浮在图外"，画布是"标题和要点作为一个整体被看见"，后者那种分量卡片给不了。
- **这一段只需要画面**：过场、留白、真实场景照片（后果见下面照片那一档）。
- **节奏：主动穿插，别把它当应急开关**。槽位版式每个内容段都是同三层（标题区 + 4:3 图 + 句子流），连放五六段就是同一张卡片重复五六次——观众的眼睛会先于内容疲劳。所以内容段 ≥5 段时给 2–3 段换画布，段数少就 1 段，位置挑在章首或转折。**两条边界**：别连着两段都用；旁白最密、最需要观众逐句跟读的那一段**别换**（整页画布连句子流的 DOM 都不生成，换了就是画面上一个字都没有、只有声音）。这一档节奏纯粹是观感，门禁不看段与段之间的关系；它唯一量得到的代价是每穿插一段就多一张要按画幅原尺寸手绘的 SVG。
- **开屏/结尾也可以整页**：顶层写 `opening_layout: "canvas"` / `closing_layout: "canvas"`，那一页走的就是本节这条路。代价是那张投影卡整个不上画面——章节列表、要点总结、`cta` 尾行都没了，标题和该说的话全得画进图里（字号档与留白照下面「文字与尺寸」那一档；注意这类手绘海报 `check` 常常全绿，但图内对比度它数不到，账得照上面那张取色表自己算）。

**什么时候别换**：该段口播要靠字幕跟读（画布不生成句子流层，旁白不会上屏，也没有"页底字幕带"这种兜底）；不想自己把标题画进 SVG（画布不生成标题层，图内标题得你自己画）；一期要出两个画幅却只打算画一张 SVG（画幅各画一张，见下面第一条）。

字段语义见 `references/writing.md` 段落 `layout`；塌成一层之后的版式与门禁变化见 `references/rendering.md`「画面结构」。画这张 SVG 时只有六条和上面的槽位版式不同：

- **几何换成整个画幅，不再是 4:3**：竖屏 `width="1080" height="1440" viewBox="0 0 1080 1440"`，横屏 `1920×1080`。两画幅都要出片就**各画一张**（`cover` 会把不等比那张的图内标题整块裁到画面外，而 `check` 看不见这种丢失，所以 `gen_hyperframes.py` 在生成期按文件验：根标签读不出纯数字 `width/height` 或 `viewBox`、或比例与当前画幅不等比，直接 exit 1）。
- **等比之后还要按画幅原尺寸画，不能靠放大画布凑**：成片把 SVG 按 `画幅宽 ÷ SVG 宽` 整体缩放，图内每个字号都乘这个系数。按 2560×1440 画的 16:9 塞进 1920 画幅，比例对、却缩到 0.75，28px 折算只剩 21px——跌破下面「文字与尺寸」那条 26px 下限就是读不出来，而这一档同样只有按文件量得到（字号写成 px 才能验；写成 `em`/`%`/class 时门禁读不出绝对值，只有图真在被缩小（SVG 宽 > 画幅宽）时才打一条 `[warn]` 让你自己按画幅复核——按画幅原尺寸画时连这条都没有，更要自己盯）。**按画幅原尺寸画就不用猜**。
- **安全边距照页面走**：竖屏四周留 50px、横屏留 96px，图内文字越界就是出血。两处实测翻车值得记住：竖屏一行 `3 h 40 min` 右缘到 1066（上限 1030），横屏一个时刻标签放在 `x=1800` 右缘到 1846（上限 1824）——`text-anchor="end"` 的落点要按量出来的字宽倒推，不是按字符数估。
- **"不铺满幅底"这条在这里更要紧**：留透明才能透出模板那三层背景，自画满幅底板等于放弃它们；理由、例外（什么时候确实该自铺一张）和 `check_svg.py` 的 warn 口径都在上面「不铺满幅底」那一节，这里不复述。
- **图内可以有标题，字号按整页读**（槽位版式那条"图内文字只起指示作用、没有标题这一档"在这里不适用）：实测可用的量级是标题 72–76px、小标题 38–48px、正文 30–40px、kicker/图例 26–28px。字号越大越要自己复查对比度——**这一版的 `Contrast` 门禁数不到你**，取色表照上面那张用。字体名写死（`'Microsoft YaHei','PingFang SC',…`）：SVG 走 `<img>` 载入，读不到页面的 `--ctv-font-*` 变量。也正因如此，生成期会打一条 `[warn]` 报"该段 N 句旁白不会上画面 / 这张 SVG 里有 M 个 `<text>`"：要点有没有真的画进图里，机械判据只有这个数量，剩下的账要自己对。
- **机械劳动可以交给脚手架**：`python scripts/canvas_kit.py --spec spec.json --aspect portrait -o images/seg1.svg` 吃一份元素清单，吐一张**按画幅原生尺寸画的透明底画布** + 一份能直接塞进 images.json `director` 的 steps草稿（`--emit-steps` 另存）。产物一样是制作产物：`-o` 与 `--emit-steps` 落在技能目录内会被守卫拦下，照抄命令前先 `cd` 到项目目录。

    **一份能照抄的完整例子**（竖屏柱状图，实测跑通）。spec的顶层是 `{"aspect"?, "theme"?, "accent"?, "elements": [...]}`：

    ```json
    {
      "aspect": "portrait",
      "elements": [
        {"kind": "panel", "id": "panel", "x": 80, "y": 300, "w": 920, "h": 700},
        {"kind": "text",  "id": "t",    "x": 80, "y": 200, "content": "季度营收", "tier": "title"},
        {"kind": "axis",  "id": "ax",   "orient": "y", "at": 940, "from": 400, "to": 940,
         "ticks": [{"v": 400, "label": "8"}, {"v": 670, "label": "4"}, {"v": 940, "label": "0"}]},
        {"kind": "bars",  "id": "bars", "base_y": 940,
         "bars": [{"x": 160, "w": 120, "h": 210, "label": "Q1"},
                  {"x": 320, "w": 120, "h": 350, "label": "Q2"},
                  {"x": 480, "w": 120, "h": 280, "label": "Q3"},
                  {"x": 640, "w": 120, "h": 560, "label": "Q4"},
                  {"x": 800, "w": 120, "h": 420, "label": "Q5"}]},
        {"kind": "text",  "id": "lab",  "x": 500, "y": 1010, "content": "Q1–Q5", "tier": "label"}
      ]
    }
    ```

    同一份例子也印在 `python scripts/canvas_kit.py --help` 的尾部，`--help` 里另有七种 kind 各一条最小可跑片段。**键集与取值不必背**：写错时脚本报错会当场列出该 kind 的合法键、必填键与枚举取值的实际效果，多个元素的错一次报全——照报错改比回头查文档快。

    动笔前仍要知道两件报错替代不了的事：**`axis` 的 `from` / `to` 是轴两端的像素坐标、不是起止数据值**（竖轴把较大的 y 写在 `from`、数值就朝上长；`at` 是那条轴所在的像素线），以及 **`tier` 只有三档、取自模板槽位字号**（画布档要更大的字就手写 SVG 绕过脚手架）。其余的键与取值，脚本报错里都写着。

    **它收走的只是机械部分**：画布几何、三档字号取自模板 `layout.<画幅>.*.fontSize`、线宽跟进度条、取色过 `_theme` 的对比度压暗、结构底与内容元素的初始 `opacity` 分档（`draw`/`count`/`type` 那三种"起始态由渲染端自己配"的元素**不会**被写 `opacity="0"`，写了就永远不亮）。公共旋钮 `duration`/`ease`/`stagger`/`repeat`/`yoyo` 都能写进元素（`repeat`/`yoyo` 只挂内容元素，`yoyo` 必须带 `repeat`），草稿原样带出。**构图仍归人**——所有坐标由 spec 给，脚本不做任何自动布局。

    两条刻意的取舍：草稿的节拍只用 `at`（句序）不用 `at_time`——绝对秒是按某一版配音手算的、重配音会整体漂移且不报错。产物生成后按 `check_svg` 的 canvas 口径自查一遍，画完还要过的空带/对比度/字号三条它已经先替你量了。`--no-check` 只给有意为之的极简页。

**给上 `--sentences <该段句数>`，草稿才是真能直接用的那份**。不给时自动拍按元素顺序一路 `at=0,1,2…`，内容元素比旁白句子多时最后几拍会落到句序之外，生成期按 `error` 整条拒掉（"at=N 越界：该段只有 M 句旁白"）。给了句数，自动拍的游标按它取模回绕，多出来的元素与前面的同拍一起亮，产出的草稿直接塞进 `images.json` 就能生成；它同时替你把**显式钉拍**（元素里写 `beat`）的越界提前打成 `[warn]`——那才是需要你回头改的地方。`--emit-steps <path>` 另存的草稿是 `{"steps": [ … ]}`（键名 `steps` 的数组就是 `director.steps` 要的那份，直接 `"director": {"steps": <这份数组>}` 即可；不另存时同一份数组也会打向 stdout）。

照片/视频当画布**不做比例与字号校验**（它们没有"画在里面的字"，`cover` 裁边是正常取景），但也要清楚后果：这一版没有标题层，配一张照片或一段视频就等于该段整段时间只有画面和旁白、屏幕上不出现任何标题——所以生成期照样给一条 `[warn]` 让你知情。想留标题就得把这一段的要点画成 SVG；确实要一段"只有画面"的过场，忽略那条 `[warn]` 就行。

### 整页画布的密度与层次：这一页经得起暂停吗

整页画布没有模板兜底（标题区、图槽、句子流各自就位那层没了），**这一页的密度、层次、节奏全是你一个人的责任**。判据不是"画了多少个元素"，是**随便暂停一帧，画面还成不成立**。用 `npx -y hyperframes snapshot --at <秒>` 把整页画布截出来看，比在浏览器里滚时间轴诚实得多。

- **竖向不许有整条空带**（`check_svg.py --layout canvas` 会 warn，阈值 25% 页高）：这是唯一能机械判的一条，因为它对应的失败最典型——标题压在上 1/4、主视觉孤零零挂在中间，中间三十几% 页高横着什么都没有，暂停就是一页空白。分工记法：标题在上 1/4、主视觉占中部并**撑到接近页宽**、注脚与结论压在下 1/4，三段之间用中景元素连起来，别留断带。
- **一页至少三层**：背景层（模板那三层，见上面「不铺满幅底」——它归模板，你别铺满幅底把它盖掉）、中景（主视觉：图、模型、流程，外加它自己的局部底板/面板/分隔带做明度层级）、前景（标注文字、数值、accent 强调）。整页画布的常见病不是画错，是**只画了一层**——单层画面在任何时刻都只有一件事可看，观众读完就只剩空白。中景自己也要有"面板 < 底板 < 页底"三档明度。
- **主视觉要有尺寸下限**：示意/数据图占页宽 ≥70%、占页高 ≥45%。缩在角落的一张画布图比放进槽位更难看，因为周围全是它自己的留白，没有版式替它撑。
- **辅助线要敢用亮档**：轴线、网格、分隔线在 dark 页底上不要低于 `#64748b` 一档，线宽 ≥3px（1080 宽画幅经压缩后，`#475569` + 2px 的实测结果是"根本没有画"）。层次靠**明度差与大小差**做，不靠透明度——`opacity` 一低，对比度门禁与观众一起失去它。
- **字号最多三档 + 一档 accent（脚手架 `canvas_kit` 给的三档取自**模板槽位**字号，竖屏 64/40/32、横屏 62/33/28；上面那组是整页画布的实测量级，比脚手架保守值大，画布档照上面那组走）**：量级照上面那条实测数字（标题 72–76 / 小标题 38–48 / 正文 30–40 / 标注 26–28），最大档与最小档的比值 ≥2，观众才分得出主次。一页里每个元素都染不同颜色不叫层次，叫彩色：一个 accent 负责"现在看这里"，其余走中性灰阶。
- **数信息单元**：这一页有几个独立可看的东西（一块图、一行结论、一组标注各算一个）？**少于 3 个就别当整页画布做**——那它本质是字卡，按海报的标准重写（金句 + 大字），或者退回槽位版式让模板去承担构图。
- **导演页还要看"起始帧"**：终帧密度达标不等于开头不空。逐拍揭示意味着前 1 秒画面是空的，而整页画布现在**没有转场遮这一下**（见 `references/rendering.md`「动画」的整页画布条目），空就是硬切之后直接给观众看的。背景那三层归模板、随页面一起出现，所以只要你不铺满幅底（见上面「不铺满幅底」），第一帧至少不是死平的一块色。剩下的解法两条：把**结构底**（坐标轴、外框、分隔带、面板格子）不写进 `director.steps`，让它和页面同时到位，只逐拍长"内容"；或者把第一拍放在 `at_time` 0.1s 量级，让墨在切完立刻落下（与 `references/directing.md`「SVG 动画：两档」末尾讲起始帧的那条同一件事，两处按这一条为准）。

### 部件配方：canvas_kit 各元素的一手量从哪来

整页画布没有模板兜版式，但每个部件该用多大、多粗、什么明度，**脚手架里已经有一套被门禁和成片验证过的量**——`canvas_kit` 的各常量全部派生自模板既有键、不写第二个 px 字面量（「画布几何」那条"尺寸真源在模板"是它的第一原则）。手工画整页 SVG 时照这组配方取值，等于直接借用这套验证过的量；改它们要连带改下面列的每一处，`check_numbers` 会两头盯（下表带 🔒 的数字与代码常量是一份）。

| 部件 | 配方（竖屏 / 横屏） | 真源 | 作用与连带 |
|---|---|---|---|
| 三档字号 title/body/label 🔒 | 64/40/32 px · 62/33/28 px | 模板 `layout.<画幅>.{title,subtitle,tagline}.fontSize` | 画布页没有 HTML 标题层，图内文字是唯一的字，主次靠这三档拉开；竖屏最大/最小档比值恰好 2，横屏 62/28≈2.2 |
| 线宽（轴线/刻度线/rule）🔒 | 4px · 5px | 模板 `layout.<画幅>.progressBar.height` | 画布上的线和页面进度条同一份量；竖屏 4/横屏 5 都够过两画幅缩放与压缩编码 |
| 面板圆角 🔒 | 12px · 12px | 模板 `layout.<画幅>.image.borderRadius` | 局部底板与槽位配图同一倒角语言，别另定一个"看起来差不多"的数 |
| 局部底板明度台阶 | 页底中段往文字色偏 14% | `canvas_kit.PLATE_FRAC` | 浮在页底之上、又不至于像新底色；"面板 < 底板 < 页底"三档明度就靠这一档拉开 |
| 次要文字压暗 | 文字色往页底压 60%，再按 ≥7:1 兜底 | `canvas_kit.DIM_FRAC` / `DIM_CONTRAST_TARGET` | 画布小字还要经两画幅缩放+成片压缩编码，取色表"次要说明 ≥7:1"就是这条 |
| 轴线/刻度线明度 | 比次要文字再暗一档（0.45），可见性下限 ≥3:1 | `canvas_kit.LINE_FRAC` / `LINE_CONTRAST_FLOOR` | 线要的是"在"不是"抢眼"；线比字更经不起缩放压缩，3:1 是底线 |
| 刻度线长 🔒 | label 档字号的一半（16px · 14px） | `canvas_kit.TICK_FRAC` | 刻度短于这一档在成片里几乎看不见；横竖屏同比例 |
| 竖排刻度 label 基线修正 | 字身中线对齐刻度（0.35 档字号） | `canvas_kit.TEXT_BASE_FRAC` | 不修正时竖排 label 相对刻度整体偏上/偏下一截 |
| 圆点判据 🔒 | r ≤ 4px 的圆算"点" | `check_svg.DOT_MAX_R` | 端点落点检查的落点目标：实心圆按圆盘算，圆心在内即根住 |
| 端点落点容差 🔒 | 画幅短边 4‰、至少 2px | `check_svg.END_TOL_FRAC` / `END_TOL_MIN` | "线要结束在某处"的机械判据；有意悬空的装饰线（rule 分隔线/下划线）加 `data-free-ends` 声明豁免 |

两处刻意不给"配方"的事：**坐标与构图**（所有 x/y/w/h 由 spec 给，脚本不做自动布局——那是版式引擎，不是脚手架），以及 **`tier` 只有三档**（取自模板槽位字号；画布档要更大的字就手写 SVG 绕过脚手架，别在 spec 里写不存在的小数档）。

### 数据图的几何自查：库走了，账要自己算

一张手绘的数据图（柱状、折线、饼环、散点、时间轴）里，**长度/角度/坐标本身就是数据**。比例画错一档，屏幕上就在教观众读一份错的数据，而这条错误链上没有任何检查看得到（`gen_hyperframes.py` 只校验文件存在 + 整页画布按文件对账比例与字号，`check` 只量 HTML 文本）。刻度分档、比例映射、数值定位全是自己做完再自查：

- **先定标尺，再画图形**：把数据区间到像素区间的映射写成一行的线性式（`y = y0 - (v - vmin) * (h / (vmax - vmin))`）放在 SVG 注释里，所有柱高/点位都由它反算，不要凭手感逐个调。坐标轴刻度取整档（1/2/5×10ⁿ），别为了对齐图形去改数据。
- **用两端点回算验证每一档**：画完拿最大值的柱顶与最小值的柱顶相减，得数应等于"量程 × 标尺"，对不上就是映射写错而不是画歪了。**pie / 环形先查总和**：各扇区角度相加必须等于 360（`占比 × 3.6`），差一度说明漏了一项或分母取错。
- **量文字，不数文字**：定宽的元素（刻度、数值标签、图例）按实测宽度排版——`text-anchor="end"` 的落点要倒推字宽。两条可跑的量法：SVG 开进浏览器用 `getBBox()` 读元素左右缘，或用 `npx -y hyperframes snapshot` 把摆进项目的图按时刻截一帧看贴边与溢出（命令见 `references/rendering.md`「官方校验命令」）。整页画布的安全边距（竖屏 50px / 横屏 96px）同样按量出来的右缘判，见上一节那两处实测翻车。
- **公式就是图内文字**：`E = mc^2` 这类本体要用 `<text>` 画——上下标靠 `baseline-shift` 或两个 `<tspan dy>`，字体栈照下面「文字与尺寸」自带，下标比正文小的字号同样受 26px 那条下限约束。

公式与数据的**内容**红线（不为好看改数字、不用误导比例、不编造数据点）见本节开头。

### 文字与尺寸

图表、公式、SVG 内部的文字必须按“**进入内容画布后**的最终可读性”设计，而不是按原始文件尺寸设计。

图内只有起指示作用的文字，**没有"标题"这一档**（见本文件「不铺满幅底」）；最大的一档 35–40px 给图例名或底板上的大字，正文级从 35px 起步（槽位按 980×735、整页画布按当前画幅原生尺寸，见本文件「画布几何」）；如果内容很密，优先减少文字、扩大图形，不要继续压字号。**26px 是下限**：再小，两画幅缩放加成片压缩编码后就读不出来了——宁可换行或加长底板，也别缩字号。

底板内还要**估一次宽度**：一行汉字数 ≈（容器宽 − 左右内边距）÷ 字号。980 画布上留 48px 内边距、52px 字号 → 一行约 17 个汉字。溢出时换行或加宽底板。

SVG 以 `<img>` 载入时是独立文档，页面的 `--ctv-font-family` 渗不进去，`<style>` 里要自带中文无衬线字体栈（如 `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", "Noto Sans CJK SC", "Noto Sans CJK JP", sans-serif`——Linux 沙箱里 `Noto Sans SC` 会回落到无 CJK 字形的 NotoSans-Regular，`Noto Sans CJK SC/JP` 才是能匹配上的名字，别省）。
