# 第 4 步深度参考：导演编排 + 画布素材方式 A/B/C

本文件展开第 4 步，顺序是**先编排、后素材**：先决定这一页要不要演（导演层，见「先问要不要演」），再决定观众该看到什么、素材从哪里来。三种方式虽然来源不同，但进入成片后都服务同一个**内容画布**：每个内容段固定一个视觉区域（竖屏居中 / 横屏右侧图栏），素材负责铺满它；画布规格、质量标准、落盘格式与人工验收对三种方式一视同仁。

> **三问按这个顺序回答：这一页要不要演 → 观众应该看到什么 → 素材从哪里来。**
>
> 已经踩过的坑不必重踩：**画面出问题时按症状查「已知翻车速查表」**（在本文末尾），那里列了每个症状的成因与去处。

## 〇、先问要不要演（导演层优先）

导演层 = images.json 给该段写 `director`，那张 SVG 被净化内联成活 DOM，由 GSAP 按 `timing_manifest` 的句子时间轴**逐拍驱动**，逐帧 seek 可复现（写法与原语清单见「SVG 动画：两档」）。它是技能里唯一"画面归你、时间也归你"的能力，所以选型的第一问是它，而不是"这张图放哪个槽位"。

**值得演**（旁白里有顺序、有过程、有"变化本身"）：

- 推导或机制一步步走：公式代入、流程逐格、因果链一节节接上
- 数据在长：坐标轴描出来（`draw`）、柱形升起、数字滚到目标值（`count`）
- 形状之间要"变"而不是"换"：分布从尖到平、同拓扑 `morph`
- 讲到哪推到哪：对 `<g id="cam">` 补间的运镜
- 一句话里多个对象要逐个点名：`stagger` + class 目标

**明确不值得**（老实交给模板，别为"高级感"演）：

- 真实人物 / 产品 / 地点 / 事件现场 → 方式 A 的检索照片；位图进不了导演层
- 抽象概念意象、氛围、场景，且图内不需要可读文字 → 方式 B 一句 prompt 的事，比手画整页便宜一个数量级
- 一句话就能讲清的静态事实 → 图只是装饰，演它等于花时间骗自己

**选了"演"就要一起认领的代价**（这是"导演优先"最容易被略过的一面）：

1. **画布页没有模板兜构图**。槽位页的标题层级、折行、图区比例都由模板管；整页交给一张 SVG 后，及格线变成"暂停一帧还成立"，工作量从"找一张图"变成"画一整页"——判据在「整页画布的密度与层次」。
2. **只有方式 C 的 SVG 能演**。A/B 产出的位图只能作为素材贴进画面，不能被逐拍驱动。
3. **导演层只管"什么时候出现"，不管"讲得对不对"**。字是你画的，几何还是你自己算（「数据图的几何自查」），没有任何门禁替你检查图里画错的东西。
4. 反过来，**槽位 + 一张好图常常是更好的成片**。"搬到首位"指的是先把这一问答一遍，不是把每页都做成画布。

## 一、三种方式先统一：共用规则

### 1. 先选“表现方式”，再选素材来源

不要把 A/B/C 当成三套独立流程。每个 segment 先回答“观众应该看到什么”：

| 内容特征 | 首选方式 | 原因 |
|---|---|---|
| 有明确真实人物、产品、地点、事件、新闻现场 | **A 真实照片** | 真实实体需要真实影像，避免生成图替代事实照片 |
| 画面里**不需要出现可读文字**：抽象概念、原理、机制意象、氛围、场景 | **B ImageGen** | 一句 prompt 出一版，复杂结构它也扛得住，风格还更容易整期统一 |
| 画面里**必须有准确文字/数字**，或必须是精确矢量几何、严谨数据 | **C SVG 矢量示意** | 信息准确性只能自己画，生图的文字不可信 |

**B 与 C 的分界线只有一条：图内要不要文字。** 要（标签、步骤名、数值、图例、公式）→ C；不要 → **选 B，哪怕内容复杂**。两个方向各有一条实测代价：手绘 SVG 返工率高——构图、图内文字对比度、卡片内文字宽度全得靠人肉自查（见下文「图内文字的对比度」的取色表），改一版就是重画；ImageGen 则是**文字崩率高**（见方式 B 统一规则），所以它只接不带文字的活。

数据图和公式也归到 C：**坐标刻度、柱长比例、扇区角度全都自己算自己标，没有任何一道门禁替你检查几何**。这类内容什么时候该从 4:3 槽位换成整页画布（`layout: "canvas"`）、平时又该穿插几段，判据统一在下面「整页画布」一节。

再按**信息结构**细分该画成什么形式。别问“我能画什么”，问“哪种形式最能帮观众理解”：

| 信息结构 | 首选形式 | 路线 |
|---|---|---|
| 数值比较 / 占比 / 趋势 / 双变量关系 | bar / pie / line / scatter（比例自己算） | C (SVG) |
| 时间演进（要标年份） | 时间线 | C (SVG) |
| 步骤 / 机制流程（要标步骤名） | 流程图 | C (SVG) |
| 层级 / 关系 / 系统结构（要标节点名） | 树状图 / 网络图 / 架构图 | C (SVG) |
| 几何 / 空间关系，**不带文字** | 生图（isometric / 3D render 风格词） | **B** |
| 外观、场景、氛围 | 图片 | A / B |

同一张图若能不写字就说清楚，就从中性形式降级交给 B：时间线可以变成"发光节点串成的路径"，架构图可以变成"层叠的节点群"，标注该说的事让标题和 verse 字幕去讲——省掉一次重画，也免掉图内文字的对比度自查。

图只承担**增量信息**：标题和 verse 已经把话说清楚时，不要为填满画布而画，也不要为“高级感”堆 3D、仪表盘、多图拼贴这类不帮助理解的装饰。

### 2. 三种方式统一使用同一个内容画布

- 内容画布：竖屏 980×735，横屏右侧图栏 1067×800（4:3 按整数像素取整）。
- 配图规格只有一条：**按 4:3 出图**。画布是 `cover` 铺满，比例不合会居中裁掉四边。B/C 两条路线本来就能满足（ImageGen 选最接近 4:3 的档位；手绘 SVG 的 4:3 落在根节点 viewBox 上，见「画布几何：根节点必须是 4:3」）；只有方式 A 的真实照片可能比例不合或带烧录水印。**整页画布（段落 `layout: "canvas"`）是唯一例外**：它铺的是整个画面，规格见下面「整页画布」一节。

### 3. 三种方式统一的质量标准

无论来源是什么，都按下面这套标准审：

**内容准确**：画面必须对应当前段落在讲的对象、动作或概念，不接受“气氛类似但事情不对”。

**主体明确**：画面第一眼能看出主角是什么；不要塞过多无关元素。

**可读可看**：如果画面内部有文字、公式、标签，必须在成片观看尺寸下（竖屏与横屏都算）依然清楚；无法保证就不要把关键信息放进素材内部。

**风格统一**：同一期可以混用 A/B/C，但要统一背景明暗、主体尺度、主色倾向和视觉密度。方式不同不等于风格失控。

**来源可追溯**：方式 A 保留来源 URL 等 provenance；方式 B/C 也尽量记录生成工具、来源或生成说明，避免二次整理时丢失来源信息。

### 4. 三种方式统一的制作流程

每个 segment 都走同一条链：选路线 → 得到媒体文件或可渲染规格 → 落 `images/` 并写进 `images.json` → **人工审关键帧**（主体、构图、文字可读性、与这一段旁白的关系）。不要因为方式不同就省略最后一步：**素材正确性和实际观感不能只靠 JSON 或脚本判断。**

### 5. images.json 是唯一统一入口

三种方式最终都映射到同一份 `images.json`。静态图最简单：

```json
{
  "seg1": {"src": "images/seg1.png"},
  "seg2": {"src": "images/seg2.jpg"}
}
```

字段：

- `src`：必填，相对 HTML 输出目录的媒体路径。
- `type`：可选，合法取值 `auto`/`image`；缺省即 `auto`（统一按静态图处理，gif/svg 也走 `<img>`）。视频/动图素材已从本技能移除。
- `director`：可选，**仅 `.svg`**，方式 C 的「时间轴同步动画（导演）」编排块。写了它这张 SVG 才走净化内联、由 GSAP 逐句驱动图内元素；不写就是普通 `<img>` 静态图。结构与语义见下面方式 C「SVG 动画：两档」。
- `stage`：可选，**仅 `.svg`**，目前只认字符串 `"keep"` 一个值——**跨段场景延续**：这一页不从头画，而是接着上一页演完的那幅画面继续演（写在哪一页的条目上就接续哪一页的前一段）。口径与能接住什么/接不住什么见下面「跨段场景延续」。
- `provider` / `source_url` / `license` / `attribution` / `query`：可选，方式 A/B/C 的来源
  记账；二次整理重配时保留旧值不要覆盖。画面不读它们。

值只能是上面这种对象；裸字符串路径（`{"seg1": "images/seg1.png"}`）会在契约层直接报错。

**上面这份键清单就是渲染端读的全部**：写了清单外的键（`alt`、`position`、`fit` 这类
凭空发明的写法）不会生效——归一化配图的 `html_renderer._normalize_images`（由
`gen_hyperframes.py` 在生成 HTML 时调用）会打一条 `[warn]` 点名是哪几个键，
看到就删掉或换路：想改构图改稿件或 SVG 本体，想改文字就写进文案，images.json 不管这些。

## 二、方式 A：真实照片 / 真实素材检索

### 适用

真实人物、真实产品、真实地点、真实事件、发布会、比赛现场、新闻现场、历史照片等，有明确实体且真实影像本身就是信息的一部分。

### 流程

用你可用的**联网搜索 / 图片搜索能力**（能力泛称，见 SKILL.md 第 4 步；本技能不内置检索工具）执行以下流程：

1. 从段落标题和正文提炼检索词；中文实体尽量加英文别名或型号。
2. 检索来源页，不要只看缩略图。
3. **逐张打开原图**，确认不是标题党、截图、带角标或与正文无关的图片。
4. 下载到 `hf-project/images/`，命名 `<sid>.<ext>`。
5. 在 `images.json` 中写映射，并保留 provenance。

### 选图标准

- 主体与段落讲的是同一个人、同一个产品、同一个地点或同一事件。

- 分辨率足够；长边低于约 1200px 时，进入成片后容易发虚。
- **入库前裁成 4:3**，保留哪块主体由看图的人判断。

找不到合适的真实图时，不要为了"覆盖率"凑图，直接改走 B/C。

### 不要做

- 把真实人物的 AI 生图冒充现场照片。
- 用同一张泛化图片反复覆盖多个不相关 segment。
- 为了满足 4:3 裁掉关键人物、产品或场景主体——裁之前先确认主体完整，放不下就换图或换路线。

## 三、方式 B：ImageGen

### 适用

抽象概念、原理、机制意象、情绪意象、无法对应真实照片的内容，以及需要整期视觉风格统一的段落。**只要画面内不出现可读文字，复杂示意图也归这里**：几何/空间关系、节点群、层叠结构、透视与等距视角，这类图常被误派给手绘 SVG，但生图一句 prompt 就能到位，重画成本几乎为零。

### 统一规格

每个 segment 生成一张**横版 4:3**图，尺寸在所用能力支持的档位里选最接近 4:3 的（如 1152×864）。同一批 prompt 保持同一背景明暗与风格词。

### Prompt 原则

Prompt 先描述“讲什么”，再描述“怎么画”。不要先写一堆风格词，最后才补主体。

推荐顺序：

```text
主体 / 场景
+ 核心动作或结构
+ 视觉关系
+ 风格
+ 背景与色调
```

示例：

- AI 模型发布：`Three interconnected AI model nodes, clear causal connections, dark background, blue-cyan digital art, clean composition`
- 反向传播：`Minimal neural network diagram with arrows flowing backward through layers, dark background, flat vector illustration style, no text, no labels`
- 供需关系：`Simple supply and demand diagram with two intersecting curves and highlighted equilibrium point, dark background, clean vector style, no text, no labels`

`diagram / chart / schematic / infographic` 这些词会把坐标轴标签和说明文字一起带进来，末尾补一句 `no text, no labels, no letters, no numbers`。出图后仍看到文字就重新生成——放大裁剪糊弄不过去，缩进画布后那串乱码照样看得清。

### 统一规则

- 一期视频保持同一套背景明暗和视觉语言。
- 讲解类画面优先 `diagram / flat vector / minimal`，不要为了“高级感”做无意义写实场景。
- **不要在图里放文字**（label、数字、公式、招牌、界面文本都算）。生图的文字崩率高：错字、缺笔、乱码、糊成一团，且崩在图里的字改不动。该标注的信息交给标题区、verse 字幕，或改走 C 路线。真带上文字且无法接受崩字风险时，这张图本来就该是 SVG。
- 主体和 accent 色保持同色相倾向，让画面进入主题后不会跳色。
- 生成后统一重命名为 `seg1.png`、`seg2.png`……并写入 `images.json`。

## 四、方式 C：SVG 矢量示意图

方式 C 用于“信息本身应该被画出来”的内容，是三种方式里最偏信息展示的一类。**数据图、公式、示意图现在都走这同一条路线**：原来的 Chart.js 数据图表与公式卡已从技能移除（使用频率低、表现受槽位限制，而整页画布给这类抽象内容开了更宽的表达式；技能也因此少一个第三方依赖）。代价写在明面上——**库替你算的那部分没了**：刻度分档、比例映射、数值定位全变成手工活，而且没有任何一道门禁量得到画错的比例。

**定位：图内必须出现准确文字（术语、步骤名、数值、图例）或必须是精确几何关系时的首选。** 不带文字的画面一律先试 B——SVG 的返工代价见第一节 B/C 分界：改方向就是重画一遍，而生图换一句 prompt 就行。

承担文字示意时它仍是表现力上限最高的一种，**不等于"简笔线框图"**：渐变、光影层次、等距视角、装饰细节都可以把示意图提到成片质感；如果发现自己在画单色方块加直线，就是画得太素了。但别把这份力气花在"画一个 3D 分子结构"上——那不带文字，是 B 的活。

数据与公式的红线——数据必须直接来自信源或可追溯的数据源：

- 不为“好看”改数字；估算值必须在画面或文案里标明，不得画成事实。
- 不使用误导性比例（截断坐标轴、面积失真对比等）；不隐藏或省略单位。
- 不编造不存在的数据点、关系或会改变含义的关键关系。

三条获取路径：

- **手绘 SVG**：按该段内容自己写 `.svg` 放入 `images/`，适合该段特有的机制/结构。
- **SVG 图库 / 现成素材**：品牌 logo、通用图标优先用成熟的开源 SVG 库（如 simple-icons、lucide、tabler）或开放许可素材，而不是凭印象手画一个“长得像”的；同一期用同一套图标库、统一线宽风格，来源与 license 记进 provenance。
- **SVG 动画**：有两档——**氛围循环**（墙钟，`<img>` 载入）和**时间轴同步的「导演」**（净化内联，由 GSAP 逐句驱动）。选型、写法与各自的代价见下面「SVG 动画：两档」。一句话分界：只要”画面得对上某句话”，就用导演，别用墙钟循环。

映射都走普通 `src`：

```json
{
  "seg4": {"src": "images/seg4.svg"}
}
```

外部 SVG 以 `<img>` 载入（内部脚本不会执行），但仍只从干净知名来源获取，不引入来源不明的素材。

#### SVG 动画：两档（氛围循环 vs 时间轴同步的「导演」）

动画分两档，选哪档只看一件事——**画面要不要对上某句话**：

**① 氛围循环（墙钟，默认，走 `<img>`）**：CSS `@keyframes` / SMIL 画的流动虚线、呼吸光效、循环位移。观感提升明显，但内部动画按**页面墙钟**自走，**无法与口播时间轴同步**，逐帧渲染时也不保证可复现。所以只用于"一直在动、动到哪儿都行"的氛围层，不要用于"必须在这句话时变成那个状态"。这一档什么都不用写，SVG 里带上 CSS/SMIL 即可，映射仍是普通 `src`。`check_svg.py` 会对墙钟动画打一条 `[warn]` 提醒它不同步。

**② 时间轴同步的「导演」（净化内联，opt-in）**：要"随旁白逐句推进"的状态变化（讲到第 2 句时高亮某个节点、讲到第 3 句时把箭头画出来、数值随句子跳到目标值），就在 images.json 给这张 SVG 写 `director`。写了 `director` 的 SVG 会：

1. **净化后内联成活 DOM**（`scripts/_svg_sanitize.py`）：删掉 `<script>` / `on*` 事件属性 / `<foreignObject>` / 外链与 `javascript:` href / `@import`，**并剥掉 SMIL 与 CSS animation/transition**（墙钟动画在逐帧 seek 里不可复现，导演档一律由补间驱动运动）。净化让"内联会执行脚本"的风险回到 `<img>` 水位——**这是本节唯一允许内联进交付 HTML 的情形**，且内联前必过净化。
2. **由 GSAP 按句驱动**：`director.steps` 每一步挂在该段旁白某句的起点上，渲染器把它展开成时间线补间（属性补间，逐帧 seek 完全可复现，和标题/配图入场同一机制）。

`director` 结构（键集封闭，写错在契约层直接报错）：

```json
{
  "seg4": {
    "src": "images/seg4.svg",
    "director": {
      "steps": [
        { "at": 0,   "target": "#node-a", "set": { "opacity": 1 } },
        { "at": 0.4, "target": "#curve",  "draw": true, "duration": 1.2, "ease": "power1.inOut" },
        { "at": 1,   "target": "#cam",    "to": { "scale": 2.2, "svgOrigin": "500 360" }, "duration": 1.5, "ease": "power2.inOut" },
        { "at": 2,   "target": "#bar",    "from": { "attr": { "height": 0 } }, "to": { "attr": { "height": 220 } } },
        { "at": 2,   "target": "#spark",  "morph": { "from": "M 0 60 L 40 60 L 80 60", "to": "M 0 60 L 40 10 L 80 60" }, "duration": 0.9 },
        { "at_time": 3.5, "target": "#caption", "from": { "opacity": 0 }, "to": { "opacity": 1 } },
        { "at_time": "+0.4", "target": ".row", "from": { "opacity": 0, "y": 16 }, "to": { "opacity": 1, "y": 0 }, "stagger": 0.12 },
        { "at_time": "+0.3", "target": "#bigNum", "count": { "from": 0, "to": 6.02, "decimals": 2, "suffix": "×10²³" }, "duration": 1.4 },
        { "at_time": "+0.2", "target": "#caption", "type": {}, "duration": 1.8, "ease": "none" }
      ]
    }
  }
}
```

- `at`：**该段内第几句旁白**（0 基句序，不是全片句号），**支持小数 = 句内偏移**。补间位置 = `sentences[⌊at⌋].start_time + (at−⌊at⌋)·duration`，句序部分越界（≥ 该段句数）在生成期报错。

    **整数句序是准的，小数是线性猜的。** 旁白音频逐句拼出来，`start_time` 是算出来的不是估的；但小数假设句内语速均匀，而 TTS 会在标点处插停顿（接口只回整段音频、没有词级时间戳，句内只能估）。

    实测偏差（entropy demo 的 22 拍全部用小数锚，按"silencedetect 量停顿 + 停顿归标点、剩余时间按字数分配"反查）：**平均每拍偏 0.2 个字、最大 1.2 个字（≈0.15s），没有一拍超过 2 字**——因为科普旁白的句子本来就短（1.5–3.3s、每句 ≤2 个停顿）。

    **唯一会放大到 1s 量级的是长句**：一句超过 ~5s 又带两三个标点时，"文本中点"的真实时刻能比线性值晚约 1s。规矩是**别让一句话长到那个份上**（写旁白时就拆成两句），而不是给渲染端加停顿估计——那要靠一张"每种标点停多久"的魔法常数表，还会把已写好的 `frac` 含义悄悄改掉，收益只有 1 个字。

    真要现场确认某拍踩在哪个词上：

    ```bash
    ffmpeg -hide_banner -i audio_output/sentences/s007.wav -af silencedetect=noise=-35dB:d=0.18 -f null -
    ```

    看 `silence_start` 落在句文本第几个标点后，再决定 `frac` 往前提还是往后推。

- `at_time`：**与 `at` 二选一**（两个都写或都不写契约层报错）。从**该段音频起点**排时间线：写**数字** = 绝对秒；写**相对串** `"+N"` / `"-N"` = 上一条 beat 结束后再 N 秒（首条退到段落起点；只有真会占时间的步才推进游标——有 `from`/`to`/`draw`，或 morph/count/type 这类负责整段的原语，纯 `set` 停在原地）。

    **它与语音没有任何绑定，这是"动画和语音不同步"最常见的来源。** 绝对秒是按某一版配音手算的，重配音、改句长、动 `--gap` 都会让它整体错位，**而不会报错**。相对链只保证步与步之间的节奏，同样不保证对上话。

    **所以：跟旁白走的节拍用 `at`；`at_time` 只留给真不跟旁白的那一拍**（相机推镜、纯节奏卡点）。它的正当用途是让导演档脱离"句子分桶"——整页画布的自由编排直接按秒排即可。

    **生成期查三件事**（解析函数 `_timeline.beat_positions` 与渲染端共用，所以门禁算出的落点就是真正执行的那一拍）：

    1. 落在**本页可见窗口之外**（早于本段旁白起点、或晚于下一段起点）→ `[warn]`。引擎按 `data-start`/`data-duration` 硬切 clip 可见性，排在窗口外的补间等于根本没演。
    2. 压在句间静音或段尾静音上的**不报**——那是节奏不是 bug。
    3. **起点在窗内、终点越过下一段起点**的那一拍 → `[warn]`。它被切在半路，作者以为演到的终态在成片里从没出现过。（只判时刻，不去算缓动走了几成——"演到一半"本来就该改节拍，而不是被精确复刻。）这一拍若落在 `stage:"keep"` 的接续页上更要紧：接续烘焙把时间轴折到最后一帧，搬走的正是那个没演到的终态。

- `target`：图内**单个 id 或 class 选择器**（`#`/`.` 开头，后接字母/数字/-/_，字母或下划线起头）。作用域自动收到该段容器 `#img-<sid>` 之下，多段内联 SVG 的同名 id/class 不会串台。**class 选择器专为 `stagger` 开**：一条 step 用 `.row` 命中一组同类元素，配 `stagger` 让它们按递增 delay 逐个演，省掉"三条标记写三个 step"。逗号/后代/伪类一律不收（会拆掉"一条 step 打一个简单选择器"的约束）。**target 指的 id/class 必须在 SVG 里真实存在**——落空不是报错而是静默没动画，所以 `gen_hyperframes.py` 生成期按文件拦成 error。
- `draw`：可选布尔。`true` 时这一 step 做**描边自绘**——渲染端用 `pathLength="1"` 归一化任意 path 长度（不需要量 `getTotalLength`），段起点先把描边收起（`stroke-dasharray:1; stroke-dashoffset:1`，视觉上无形），`at` 到时把 `strokeDashoffset` 补到 0，线"自己长出来"。目标必须是**有描边的形状**（`path`/`line`/`polyline`/带 `stroke` 的圆矩形），否则看不见生长效果（无 stroke 就是空）。
- `morph`：**同拓扑 path 形变**（对象 `{"from": "M…", "to": "M…"}`）。一条 `<path>` 随时间从 `from` 变到 `to`，生成期按渲染帧率的 2 倍把中间态采样成一串 `tl.set(attr:{d})` 关键帧——逐帧 seek 可复现，**不引入任何 morph 库**。

    硬约束三条：`from` 与 `to` 必须**同拓扑**（命令字母序列一致、每条命令的数值个数一致，只有坐标不同）；`target` 必须是那个 `<path>` 的 id；不能叠 `from`/`to`/`set`/`draw`。

    `duration` 决定形变跨度，`ease` 决定形状随时间的**缓动手性**（缺省 `power2.out`；GSAP 不会对 set 再缓动，所以曲线由生成期采样定义，档位见下面 `ease`）。`from` 要和元素在 SVG 里画好的 `d` 一致，否则第 0 帧会有一次跳变。

    **做不了的事**：任意两个不相干形状的互转（拓扑不同）仍需外部 morph 库，本技能刻意不做。

- `set` / `to` / `from`：GSAP 补间变量，`draw`/`morph`/`count` 之外至少要有一个。`set` = 瞬时赋值；`from`+`to` = fromTo；单独 `to`/`from` 各走一路。变量只收 **JSON 可序列化**的值（标量/数组/对象，非 CSS 属性如 `r`/`height`/`d` 走 `attr:{}`），**禁任何 `on*` 回调键**（信源不可信，回调等于在渲染页执行任意逻辑）。

- `count`：**数字滚动**（对象 `{"to": 数字, "from"?, "decimals"?, "prefix"?, "suffix"?}`）。一条 `<text>` 的数值从 `from`（缺省 0）随时间缓动到 `to`，`decimals` 定小数位（缺省 0），`prefix`/`suffix` 裹住数字（如 `"≈"`、`"×10²³"`、`"%"`）。"数字跳到 6.02×10²³""百分比涨到 87%"这类效果靠它，不必手搓逐帧。`target` 要指一个 `<text>`；`duration`/`ease` 决定滚动手感。不能叠 `from`/`to`/`set`/`draw`/`morph`。

    实现是**渲染端生成**的代理补间 + `onUpdate` 写 `textContent`——成片逐帧 seek 会触发回调（和字幕高亮同一条 `onUpdate` 路），故 seek 可复现。这里的回调是技能自己写的、只读校验过的标量，与被禁的信源 `on*` 回调不是一回事。

    **手动在浏览器 console 探针时要写 `tl.seek(t, false)`**——GSAP 的 `seek()` 默认 `suppressEvents=true` 会跳过 `onUpdate`（属性补间照常渲染，唯独 count 这种靠回调写文本的看起来"卡住"，容易误判成坏了；字幕高亮同理）。

- `type`：**打字机逐字揭示**（对象，只认空对象 `{}`）。把 `<text>` 里**现成的整段文本**按进度逐字打出来：运行时读该元素的 `textContent` 作源串，`onUpdate` 写 `slice(0, 已打字数)`。

    所以"打什么字"完全由你在 SVG 里写好的 `<text>` 决定，**这里没有任何参数可配**——刻意如此：要改文字就改 SVG，要改快慢就用 step 级 `duration`/`ease`。`target` 要指一个**直接写文本的 `<text>`**（带子 `<tspan>` 排版的复杂文本会被压平成纯文本，别用在这类节点上）。`ease` 缺省取模板（多为 `power2.out`，打字会前快后慢）；**想要匀速打字的手感就写 `"ease": "none"`**。不能叠 `from`/`to`/`set`/`draw`/`morph`/`count`，且忽略 `stagger`。

    与 `count` 复用同一条 `onUpdate` 代理补间路，所以同样 seek 可复现、console 探针同样 `tl.seek(t, false)`、零 DOM 改写、不引入新净化面。
- `stagger`：可选，**配 class 目标做一组元素的错峰揭示**。数字（`0.12`=每个间隔秒）或对象（GSAP 原生配置 `each`/`amount`/`from`(`"start"`/`"center"`/`"edges"`/序号)/`grid`/`ease`）。`{"at_time":"+0.4","target":".row","from":{"opacity":0,"y":16},"to":{"opacity":1,"y":0},"stagger":0.12}` = 一组 `.row` 依次浮入。只对有补间的 step（`from`/`to`/`fromTo`/`set`）生效；`morph`/`count` 各自负责整段、忽略 `stagger`。
- `duration` / `ease` / `delay`：可选。缺省 `duration`/`ease` 取模板 `animation.director`（视觉真源单一数据源，别在 JSON 里各处写死）。这三个旋钮连同 `stagger`/`repeat`/`yoyo` **只能写在 step 级**：塞进 `to`/`from`/`set` 的补间变量里会被契约层拒——那种写法要么被渲染端覆盖掉、要么让门禁算的跨度与补间真实跨度分家，两种都是静默的。

- `ease`：缓动档。**这张表不是照 GSAP 文档抄的**，是拿技能实际钉固的那份 `gsap.min.js` 逐个 `gsap.parseEase()` 试出来的，所以**认不出的档当场报错**——不会留成"作者以为演的是弹一下落定、成片里是平稳落定"。

    写法：族名 `none` `linear` `power0`…`power4` `quad` `cubic` `quart` `quint` `strong` `sine` `expo` `circ` `back` `elastic` `bounce` `steps`；方向 `.in` `.out` `.inOut`，裸名按 `.out`；带参数写 `back.out(1.7)`、`elastic.out(1,0.3)`、`steps(4,true)`、`steps(4).in`。

    三条例外都实测过：`none` 是直通档、不带方向（`none.in` 解析不出）；`steps` 要带方向就必须给档数（`steps.in` 解析不出）；`rough` / `slow` / `CustomEase` 之类属于 EasePack 与插件，core dist 里没有，写了就是无声退化，所以目录不收。

    **选档的手感**：缺省 `power2.out` 是"慢收"，整期都用它，所有动画就都读成"淡入"。物件**进场**用 `.in`（慢起，像被推进来）、**退场**或落定用 `.out`、来回摆与推镜用 `.inOut`，要弹要跳就 `back`/`bounce`/`elastic`。

    morph 的缓动是生成期采样定义的（GSAP 不会对 `tl.set` 再缓动），用的就是同一族曲线、同一份实现（`scripts/_ease.py`），与补间同手性。

- `repeat` / `yoyo`：可选，让**同一拍演好几遍**（GSAP 的同名补间变量）。`repeat: N` 是"再演 N 遍"，共 N+1 遍；`repeat: -1` 是无限循环，演到这一页被下一页盖过来为止。`yoyo: true` 是来回——第 2 遍倒放、第 3 遍正放，遍数为偶数时正好收在起点。"呼吸/脉动"就是一条步：`{"at": 2, "target": "#halo", "to": {"opacity": 0.35, "scale": 1.08}, "duration": 0.6, "repeat": 3, "yoyo": true}` 让一圈光晕随旁白明灭四次，不必写八条。跟着四条规矩：
  - **跨度按遍数算**（`duration × 遍数`）。相对链 `at_time: "+N"` 的游标、"这一拍会不会被下一页切在半路"的 warn、接续烘焙"最后停在哪儿"读的都是同一个数（`_timeline.beat_span`），不会出现门禁按一拍算、成片演四遍。
  - **只有真会"演"的步能配它**（`from`/`to`/`draw`/`morph`/`count`/`type`）。纯 `set` 是瞬时赋值，重放它在成片里看不出区别，还会让门禁算出的落点变成假时刻，契约层拒。单写 `yoyo`（`repeat` 缺省或 0）也拒：只演一遍时 GSAP 不会回头。
  - **`morph` 不能配 `repeat: -1`**：形变是生成期采样成离散关键帧的，没有终点就无从采样。补间与 `count`/`type` 可以——它们走运行期，GSAP 按时间解析求值，无限循环反而是确定的。
  - **跨段接续按收尾那一头搬**：偶数遍的 `yoyo` 与无限循环各有一套话，见下面「跨段场景延续」的 `repeat`/`yoyo` 一条。

**觉得"动画和语音不太同步"时怎么查**（别急着重渲染一遍用肉眼看）：

`gen_hyperframes.py … --beat-report` 会为每个导演段打一张对轴表，逐拍列出解析后的绝对秒与它踩在哪儿——`in` 句内 / `gap` 句间静音 / `tail` 段尾静音 / `before`·`after` 窗外。**窗外的那两类就是没在成片里演过的。**（同样的判据平时以 `[warn]` 自动打出来，`--beat-report` 只是把没报警的那些也摊开给你看。表按每一拍的**起点**分类，所以"起点在窗内、终点被下一页切掉"那一类只在 `[warn]` 里有。）

`in` 不等于准：句内 frac 是线性假设，偏差量级与"什么样的长句才会偏到 1s 量级"的实测都在上面 `at` 那一条，这里不复述。怀疑某一拍踩错词，照那条末尾的 `silencedetect` 一行命令定位，**别改代码**。词级对轴要么听一遍，要么换带 word timestamps 的配音接口。

浏览器预览里的偏差另算一回事——`preview.js` 是时间线为主、音频跟随（差超过 0.15s 才硬拉一次 `currentTime`），而成片是逐帧 seek，画面时刻与音频时刻严格相等。

**十二个够用的"演"的 pattern**（都在现有确定性/安全范围内，不需要新原语）：

- **逐句推进**：一步挂一句，`set`/`to` 把该讲到的节点点亮、卡片浮起。这是最基本的"讲到哪儿亮到哪儿"。
- **运镜 / 相机（pan·zoom）**：把要动的场景包进一个 `<g id="cam">`，对它补间 `scale`/`x`/`y`（GSAP 会写成 SVG `transform`，逐帧 seek 确定）。不需要专门的相机字段。

    ```json
    {"at": 0, "target": "#cam", "to": {"scale": 2.2, "x": -300, "y": -120, "svgOrigin": "500 360"}, "duration": 1.8, "ease": "power2.inOut"}
    ```

    上面就是"推进局部"，再来一步 `scale: 1` 拉回全景。

    **焦点没写时渲染器替你钉一个**：注入本页 `#cam` 内容并集中心当 `svgOrigin`，于是运行期、跨段烘焙、出画 warn 三方看到的是同一个点。（GSAP 自己的缺省原点是 bbox 左上角，还跟着别的步的 `from` 飘——一个 `from:{x:-420}` 的入场就能把 bbox.x 从 90 拽到 −40。不钉死就会让 warn 报的取景和成片里的不是一幅，见下面 `stage:"keep"` 那条。）**写了 `svgOrigin` 的页面以你写的为准**，那一页什么都不注入。

    **`#cam` 里只放主视觉。** 标题、结论句、公式带、图例条这类"文字带"要留在 `<g id="cam">` **之外**——它们是给观众读的，不该跟着镜头跑；只有被推近的那块图形进相机。真要让某行字跟着推镜，就单独给它一步与相机同步的补间。

    **为什么**：`scale>1` 是以 `svgOrigin` 为中心把整组放大，离焦点越远位移越大。实测一张 1080×1440 画布用 `scale:1.16 svgOrigin:"540 660"` 推镜，页底 y=1362 的标签被推到 1476（画到画面外），页顶标题也贴着边。

    **机器兜住的部分**：生成期 `director_prepare` 会把 `#cam` 里的内容按运镜的**收尾位**投影回画幅，静止时整条被推出画幅的元素、以及切在上下边缘外的文字都会打 `[warn]`（几何在 `scripts/_cam_crop.py`，口径写在它的模块头：只看收尾位，途中出画是合法的入场滑动；只认 `<g id="cam">`；祖先带 rotate/matrix 的子树跳过不猜；满幅底板豁免）。它停在 warn 不上 error，因为"静止位看不见某样东西"也可能是你故意的取舍。

    **机器兜不住的那件事**：它只判"出画"，不判"撞字"——`#cam` 里的图形被推出去以后，可能正好压到 `<g id="cam">` **之外**那行静止的标题/旁白上，这既没出画也没被切。所以**留白要按"推完那一帧"算，不是按 SVG 源码算**：把相机收尾位的 `scale`/平移套一遍坐标，再和静止元素的基线比。实测 `scale:1.16 svgOrigin:"540 660"` 下，源码 y=320 的轴顶投到 266，会顶穿基线 282 的静止旁白；把轴顶挪到 y=400 → 投出 358 才拉开。
- **自绘 + 错峰（draw-on·stagger）**：`draw:true` 让曲线/坐标轴自己长出来；一组元素（`.row`/`.marker`）配 `stagger` 就是**一条 step 逐个错峰揭示**，不必给每条线手写递增的 `at`。多条线要错峰生长也可各给递增 `at`（句内小数最顺手，如 `0.2 / 0.5 / 0.8`）。配合运镜，一段"边讲边画、镜头跟上去"的 3b1b 味镜头就拼出来了。
- **数字滚动（count）**：`count:{from,to,decimals,suffix}` 让一个 `<text>` 的数值"讲到就数上去"——阿伏伽德罗常数跳到 6.02×10²³、百分比涨到 87%、计数从 0 数到 128。这是科普最有说服力的"演"之一，过去只能靠手搓逐帧，现在一步搞定；`suffix`/`prefix` 把单位裹上，`ease` 调滚动手感。
- **逐字揭示（type·打字机）**：`type:{}` 把一条 `<text>` 里现成的整段文字逐字打出来——定义、金句、小标题"讲到才一个字一个字冒出来"。文字写进 SVG，`duration` 决定打完要多久、`"ease":"none"` 要匀速打字手感。它和 count 复用同一条 onUpdate 代理补间路（切片写回，零 DOM 改写），所以同样 seek 可复现、console 探针同样 `tl.seek(t,false)`。
- **自由场景（整页画布 × 导演 = 一整个可编排的画面）**：给段落写 `layout: "canvas"`，这一页的标题层与句子流层连 DOM 都不生成，整屏就是这一张图；再给它写 `director`，于是**整页变成一个你自由编排的舞台**。这是技能里最接近 3b1b"演"的写法，也是它**不需要第四档版式**的原因：canvas 已经把模板网格拆干净，director 负责在上面任意编排。

    文字/图元全画在 SVG 里，要什么时候出现用 `at_time` 按秒排：

    ```json
    {"at_time": 0.6, "target": "#title-line", "from": {"opacity": 0, "y": 20}, "to": {"opacity": 1, "y": 0}}
    {"at_time": 2.4, "target": "#cam", "to": {"scale": 1.8, "svgOrigin": "500 360"}, "duration": 1.6}
    ```

    **代价一：旁白句子默认不上屏。** 需要文字就画进 SVG（大标题、结论句本来就该在图里）。这一档没有"页底字幕带"可以要——模板那一层在画布页根本不生成。

    **代价二：画布页不走模板转场。** 擦除时长被强制归零，整页在自己的音频起点硬切出现，旧页直接被盖住而不被掀走。（理由是擦除/剥离属于图层级翻页语言，和导演在一页内部逐拍揭示抢叙事，见 `references/rendering.md`「动画」的整页画布段条目。）

    跟着来的实操是**第一拍要尽早落子**——切过来的一瞬间画布是空的（导演从 opacity 0 起步），所以把整页的底图/坐标轴/标题放在 `at_time` 最靠前的一拍（0.2s 量级），别让观众盯着空页。
- **形变（path morph·同拓扑）**：`morph:{from,to}` 让一条 `<path>` 随时间改变形状——"柱子长高"用同一个矩形 path 换 y 坐标、"折线被拉直"用同一段折线换点、"示意图 A 态到 B 态"只要保持命令序列一致就能演。它把最缺的那种"演"补上了，且**仍是逐帧可复现的、零依赖的**（生成期把中间态烘焙成 `tl.set(attr:{d})` 关键帧）。约束只有一条：起止**同拓扑**，见上面 `morph` 键。
- **立体感（投影多边形 + morph，不是真 3D）**：SVG 没有 Z 轴，但解说里的"立体"从来只是**把三维点投影到画面坐标**。等距（`x=(u−v)·cos30°`、`y=(u+v)·sin30°−w`）或单点透视都能手算。

    **画法**：同一个物体在 2–3 个姿态下各写一条**同拓扑 path**，用 `morph:{from,to}` 串起来。"立方体翻一面""坐标轴倾斜一下""晶格换个朝向"本质就是逐点 reshape，morph 恰好最擅长这个。

    **为什么走这条路而不是 three.js**：投影出来的仍然是一张可解析的 SVG，所以图内字号、字面色对比度、空带、运镜裁切这些门禁照常生效，逐帧 seek 的可复现性也已经有保证。WebGL 是一块像素缓冲，那些检查在它里面一条都没有判据，交付页还要多背一条离线钉固依赖（600KB 级）。

    **做不了的别硬凹**：连续平滑自转的真透视曲面是真 3D 的活，硬用投影串姿态会抖——那种镜头改成"两个姿态 + 一次 morph"，比"让它转起来"更好读，也更便宜。

- **呼吸 / 脉动（`repeat`·`yoyo`）**：一圈光晕随旁白明灭几次、一条警戒线来回闪、一个数滚上去又滚回来——都只要**一条**步配 `repeat`/`yoyo`，不必为每一遍写一条。收尾停在哪一头由遍数说话（`yoyo` + 偶数遍回到起点），而这个数同时是相对链的游标、出窗 warn 的右界与跨页接续搬走的那个状态，所以"这一拍演完是什么样"在门禁和成片里是同一个答案。想让观众看见"重复"就想让某一拍明显比兄弟短：`duration` 0.4–0.7s 的往复最像呼吸，1.5s 的往复只会读成"它还没演完"。
- **聚光（压暗对照组，而不是点亮主角）**：要"讲到哪儿看到哪儿"，给**其余那组**一步 `to: {"opacity": 0.25}` 比给主角加一步"亮起来"更省——主角本来就看得见，压暗别的才产生亮度差，而且被压暗的那些还留在原位，回到全景时不必重画。配 `stagger` 让一组 `.dim` 错峰暗下去，一句"这三条路里只有中间那条走得通"就是两步。
- **两层视差（推镜时前后景不同速）**：背景那层给 `scale: 1.05`、主视觉给 `scale: 1.3`，同一个 `svgOrigin`，推近时两层错开速度，画面立刻有厚度。运镜自查只认 `<g id="cam">`（口径见相机那一条），所以第二层不在它的视野里——推近幅度要按**收尾位**自己套一遍坐标。
- **歪元素而不是歪相机**：要"这一项被推翻/被审视"的观感，给那个元素一步 `rotation: -4`，别给相机转角度。相机一转，整页连文字带一起斜，读起来是"页面坏了"；单个元素转，读起来是"它在被掂量"。相机只负责推与移，方向感交给元素自己。

导演档的边界：

- **只对 `.svg` 生效**（其它素材没有可被逐帧驱动的图内命名元素）；非 SVG 写 `director` 契约层直接拒。
- **初始状态自己画**：补间只负责"从 A 到 B"，元素在图里的起始样子（比如要最后才亮的节点写 `opacity="0"`）要作者在 SVG 里画好，导演在句子到来时把它推到目标态。`draw:true` 是唯一的例外——dash 的起收它自动配（`pathLength` 归一），作者只要给有 stroke 的形状。
- **墙钟动画会被剥掉**：同一张 SVG 里既写 CSS `@keyframes` 又写 `director`，前者在净化时被删（`check_svg.py` 与生成期都会 warn/告知）。要氛围循环就别写 `director`，走 ① 的 `<img>` 那档。
- **决定性与安全都由净化 + 补间保证**，不需要再退回"交付必须 `<img>`"那条老规矩——那条规矩的前提是"内联=执行未净化脚本"，导演档内联的是净化后的 SVG。

**版式跟着该段内容的逻辑走**，不要每期都落到"两个方块加一支箭头"上：时间演化用时间轴，机制因果用带箭头的流程，层级用树，占比用环形或堆叠条，对照用双栏。骨架类文件只提供画布几何、背景（不铺满幅底）与取色三条约束（见下面三节），具体摆什么图形由旁白决定；同一期里几张示意图长得一模一样，就是没做这个判断。

#### 跨段场景延续（images.json 的 `stage: "keep"`）：下一页接着上一页演

一个舞台上的动作常常一句话讲不完，但段落边界是硬的：每页各自内联一份 SVG、各自从 `opacity="0"` 起步，于是"推进局部"这一页演完，下一页切回去就把全景重画一遍，观众看到的是**回弹**。给接续页写 `"stage": "keep"`，这一页的起点就不再是盘上原图，而是**上一页演完的那幅画面**。

```json
{
  "seg2": {"src": "images/stage.svg", "director": {"steps": ["… 最后一拍是 #cam 推近 …"]}},
  "seg3": {"src": "images/stage.svg", "stage": "keep",
           "director": {"steps": ["… 在推近后的画面上继续演 …"]}}
}
```

机制（口径在 `scripts/_stage_carry.py` 的模块头）：生成 HTML 时按 manifest 段序再走一遍，把上一页所有补间的**收尾态**烘焙进这一页的内联副本——相机姿态折成 `#cam` 内新增的一层静态 `<g data-ctv-stage transform="…">`（**不写进 `#cam` 自己的 transform**，否则本页导演对相机的补间会踩在一份被改写过的起点上），元素级的 `opacity`/`attr` 落到各自节点的起始属性，`x`/`y` 平移折成元素 `transform` 前面的一层外层平移（`translate(dx,dy) 原串`，原串一个字不动地留着当本段补间的基值）。

实测（三段链 1080×1440、12fps 逐帧取样）：**页界那两帧在配图区完全重合**——柱子与坐标轴的边沿在切页前后一字不差（界 1 两帧都是 x=686–829、y=254–1189；界 2 都是 707–859、215–1205），把三段所有 `#cam` 步删掉的对照组同样一字不差（元素态与相机态因此各自被独立验过一次）。**量连续性要按柱子边沿定位，别拿整幅 PSNR 当判据**：每页 `--seg-accent` 不同，模板的氛围光与进度条在切页那一帧整幅换色（实测背景均值 (10,23,26)→(26,21,17)→(16,23,31)），整幅 PSNR 停在 26 dB 是配色差异不是画面没接上（钉原点前同一处只有 15 dB，那才是真阶跃）。

约束：

- **两页的 `src` 必须指向同一张图**（不同路径无从烘焙）。接的是谁、是不是同一张，由 `gen_hyperframes` 按段序判，判不过就是点名到段落的 error。
- **上一页必须写了 `director`**——写了才净化内联，`<img>` 那份没有可读的元素态。接续页**自己可以不写** `director`：一段演完、下一页只是"停在那幅画上说话"是合法演法，那种页 steps 为空，画面照样接续。
- **元素级 `transform` 只接 `x`/`y`**：平移跟原点无关，能精确折成元素 `transform` 前缀的一层外层平移（`translate(dx,dy)` + 作者原串，原串一个字不动地留给本段当基值）。`scale`/`rotation`/`skew`/`xPercent` 仍跳过并打一条 warn——那要以元素自己的 bbox 中心为原点折算，而中心是"占位盒"估的（口径见 `scripts/_cam_crop.py`），宁可少接一样也不悄悄挪位。元素自身写了 `rotate`/`matrix`/`skew` 时连 `x`/`y` 也接不动（平移基值读不准），同样出声。
- **`repeat` / `yoyo` 按收尾那一头接**：`yoyo` 且遍数为偶数的那一拍本来就回到起点，接续页什么都不搬（这是对的，不是漏搬）；写了 `repeat: -1` 的那一拍**没有收尾态**，不搬并点名到 target 出声。相机上有一条无限循环，整台相机的收尾位就不作数（不折 `<g data-ctv-stage>`），因为那一页的镜头根本不停在任何一处——编一个姿态折过去比不折更容易查不出来。
- **接续页不要给 `<defs>` 里的元素写补间**（渐变/滤镜/marker/`<symbol>`，以及任何被 `url(#id)`/`href="#id"` 引用过的 id）：同一张 SVG 内联两份后图内 id 重复，而图里的引用按文档序只认第一份（= 上一页那一幅），这一拍打在本页这份上没有任何图形会去读它。生成期按步报 error，别靠"反正看不见"。要延续渐变/滤镜的状态就在前一段写。
- **相机绕的那一点是渲染器钉的**（这条是"页界不跳"的前提，不是可选项）：作者整页没写 `svgOrigin`/`transformOrigin` 时，渲染器给相机步注入**本页 `#cam` 内容并集中心**当 `svgOrigin`（`_cam_crop.cam_default_origin`），跨段烘焙与上面那条出画 warn 算的就是同一个点。GSAP 自己对没写原点的 SVG 元素绕的是 `#cam` bbox 的**左上角**，那个角还跟着别的步的 `from` 瞬态飘（一个 `from:{x:-420}` 的入场就能把 bbox.x 从 90 拽到 −40），不钉死就在接续页界上留一次纯平移阶跃（三段链实测 24~36px，柱子宽高不变所以只有位置跳）。**写了原点的页面一律以你写的为准**，那一页什么都不注入。

跟着来的两处行为变化（做 `keep` 时才补的，都在渲染端）：接续页**不走擦除**（wipe 强制归零，与画布页同一条硬切路径），也**不生成配图入场补间**（`#img-{sid}` 的淡入 + 上移 40px 正是"页界回弹"的本体）——起点既然是上一页演完的样子，再演一次入场就是穿帮。

#### 画布几何：根节点必须是 4:3

SVG 唯一的一条硬规格，写死在根节点上：

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="980" height="735" viewBox="0 0 980 735">
```

- 内容画布竖屏 980×735、横屏 1067×800 **都是 4:3**，所以照上面的竖屏尺寸画一份就两画幅通用，不必出两张。
- 画布是 `cover` 铺满（见 `references/rendering.md`）：viewBox 不是 4:3 时短边对齐、长边居中裁掉，贴边的图内文字、图例、卡片描边会缺一块，内置动画还会露出位移被切的痕迹。要改就改根节点的画布尺寸再重排内容，**别靠缩内容凑比例**。
- 图库来的图标（simple-icons / lucide / tabler 多为 24×24，即 1:1）**不能整幅当配图**，只能作为 4:3 画布里的一个元素套进 `<g transform="translate(…) scale(…)">`，四周留出与同段其他图一致的边距。
- 这条**管线对槽位 SVG 不检查**：`gen_hyperframes.py` 只校验文件存在，量不到根节点比例。画完跑 `python scripts/check_svg.py images/`——它静态查根节点比例、折算后字号、脚本/外链等不安全构造、字面色对**主题渐变最坏一档**的对比度（槽位判 error/warn，画布只 warn，因为画布上的字可能压着自己画的浅色局部底板）、满幅底 `<rect>`（槽位=色差框、画布=盖掉模板那三层背景）、低透明度文字（整页画布上导演的 `opacity="0"` 起始态除外）、含中文缺字体栈、画布安全边距、整页画布的整幅横向空带（≥25% 页高没东西＝空页，见下面「整页画布的密度与层次」）。图内文字是否真的溢出、数据图的刻度与比例是否画对，它查不到，仍要自己盯，见下面几节。

#### 不铺满幅底：配图直接画在页面上

根节点下**不要写铺满 viewBox 的背景 `<rect>`**。"框"有两处来源：自铺的满幅面板（比页面渐变更亮更蓝，四边那道色差就是框），以及 CSS 给槽位的 1px accent 内描边与外发光——后者 SVG 配图会自动挂 `bare-media` 撤掉。两层都没了之后，透明处透出的是主题渐变和该段 `--seg-accent` 的氛围光（`.seg-card::after`），示意图直接落在页面上，还自动染上本段主色。

- **图内留白从此算版式**。有框时左边距随便留；没框之后图内第一行文字与页面标题的起始轴线直接可比——竖屏槽位左边缘正落在 `segCard.padding` 的 50px 轴上，图内再缩进 60 就是 110px，明显不同轴。要么缩进收到 0（贴边不被裁，靠的是上一节那条 4:3 + `cover`），要么明确当图例、不追求对齐。下笔时就得定，框不再替你兜着。
- **图内文字只在起指示作用时才写**：轴标签、刻度、单位、数值、图例、步骤名，判据是"不写这行字这张图就读不出来"。没有要指示的就不留字。**标题不在其中**——卡片标题就是这张图的标题，框一撤，图内那行大字立刻跟它并排比高低。
- **辉光开始参与配色**：面板本来把氛围光挡死了，透明后 `--seg-accent` 直接压在图区中心（竖屏 15%、横屏 13%）。方式 B 那条"主体与 accent 色保持同色相倾向"从此对 SVG 同样生效，下笔前先看这段用什么 accent；次要文字也要跟着提亮一档，见下一节那张表。
- **局部底板照旧可画**，取消的只是"整幅满铺"这一件事。

**整页画布（`layout: "canvas"`）同一条，而且更吃紧**：画布页过去照例铺一层 `#0b1020` 当底——别再铺了。这一页底下模板本来就画着背景三层（类名与实现见 `references/rendering.md`「画面结构」），SVG 留透明，那三层就从你画的内容背后透出来；实测的差别是：中段不再是均匀一块死色、中景面板从背景里浮出来、导演还没落子的第一帧也读作"打了光"而不是"还没画"。代价与例外：底色从此由 `--theme` 决定，画布页的对比度门禁也照它算（见下面「图内文字的对比度」，画布档只 warn）；确实要把整页换成另一种底色（浅色页、照片感场景）才自己画一张满幅 rect，那等于放弃这三层，`check_svg.py --layout canvas` 会 warn 提醒、有意为之就忽略。进度条与段落底轨已经在这三层之上，不会被盖掉。

#### 图内文字的对比度：定色在前，自查在后

**为什么只能自己盯**：SVG 以 `<img>` 载入，它内部的文字不属于 HTML 文本流，管线里没有任何一道检查会量它。实测把深色底 SVG 的标签色换成与背景几乎同色的 `#1a2536`（对比度 1.2:1，肉眼完全读不出），从生成到渲染全程零报错，一路带到成片才发现是空白。下笔时定错就一路带到观众眼前——所以取色表把"定色"放在自查之前。

**想要一道真门禁：做一次性内联副本，别改产物**。把 `<img src="images/x.svg">` 那一行替换成该 SVG 文件的**内容**，其余一律不动，对这份副本跑 `hyperframes check`——Contrast 就把图内文字当 HTML 文本来量了。

**副本只用来问门禁，绝不能当产物。** `<img>` 载入的 SVG 按 data 处理，浏览器不执行它的 `<script>`：实测往里注入 `document.title="PWNED"`，标题不变。一旦内联进 DOM 它就是同源的活 SVG，脚本照执行——同一注入把标题改成了 PWNED。所以渲染与交付用的 `index.html` 必须保持 `<img>` 形态，内联版只活在 scratch 目录里。

**这一条只约束"未净化的普通 SVG"。** 写了 `director` 的那张 SVG 是唯一例外：它交付时就是内联的活 DOM，但内联前必过 `scripts/_svg_sanitize.py` 净化，`<script>`/`on*`/外链已被删干净，脚本无从执行。见方式 C「SVG 动画：两档」。

**判定线**（WCAG）：正文与标签 ≥ 4.5:1，图内最大字号那一档（≥24px，或 ≥18.66px 加粗；按上面那条，它通常是图例名或底板上的大字，不是标题）≥ 3:1，低于 3:1 重画。4.5:1 只是及格线——图内小字还要经两画幅缩放和成片压缩编码，次要文字按 ≥ 7:1 取色。

**深色主题取色表**（底 = 页面渐变叠上该段 accent 辉光。**页底**列是不叠辉光的区间，**最坏**列是**全部预置 accent**（色板见 `scripts/_theme.py`）× 全部渐变 stop × 竖屏 15%/横屏 13% 全组合里的最低值）：

| 用途 | 取色 | 对比度 |
|---|---|---|
| 图内最大字号 | `#f2f6fc` | 页底 17.7–18.6，最坏 12.7 |
| 主标签 | `#dbe6f5` | 页底 15.2–16.0，最坏 10.9 |
| 次要说明下限 | `#a8bdd6` | 最坏 7.2，刚好守住 ≥7。旧值 `#8fa6c2` 页底有 7.7–8.1，被暖橙辉光吃到 5.5 就不够了 |
| 不要用 | `#6b7c93` | 页底 4.5–4.7、最坏 3.2，两档都越线 |
| 背景深蓝族 | `#0c1320` `#16233a` `#1a2536` | 1.0–1.3:1，出现在 `fill` 上就是瞎字；不铺满幅底之后它们只属于**局部底板** |

**三条最常踩的**：

- **深色文字只能待在明确的浅色底板上**。符号常写成近黑 `#0c1320` 摆到浅色渐变圆盘上（圆盘上 15.1:1，没问题）——可圆盘一挪、一删、或换了渐变，这行字立刻瞎掉。改任何底板颜色，都要同时复核压在它上面的文字；`fill` 能就近写死就别靠 `<g>` 继承。
- **背景色族不得当文字色**（深色主题下）。同一支深蓝只用于背景与面板。判据是"这个色值属不属于背景族"，不是"看起来有没有对比度"——`check_svg.py` 的家族集就是"深蓝族 ∪ 当前主题渐变的各档 stop"，改主题不用改检查规则。
- **半透明按合成后的颜色算**。`opacity` / `fill-opacity` 会真实吃掉对比度：50% 的 `#dbe6f5` 叠在 `#0c1320` 上合成 `#747c8a`，只剩 4.4:1。要弱化文字就换一个更暗的实色，不要用透明度。唯一的例外是整页画布上导演元素的 `opacity="0"`——那是**起始态**不是弱化（终帧才亮，见上面「初始状态自己画」），`check_svg.py --layout canvas` 不对它报，但 `0.1~0.79` 这些中间档照报，因为亮起来的那一帧本身就偏灰。

**这一节能被机械查到什么程度**：`check_svg.py` 对字面 hex 填充一律按**主题渐变的最坏一档**算一次 WCAG 对比度。槽位版式底色确定，所以低于 3:1 判 error、低于 4.5:1 判 warn，背景族当文字色直接 error。**整页画布只 warn，不 error**——画布上的字很可能正压着作者自画的浅色局部底板，按页底算出来的数对它不成立，这条判据在画布档没有判死的资格（背景族那条启发式因此也留在槽位）。渐变底、写在 `class` 里的色、局部底板上的字，它一概管不到：上面这张取色表该自己查还得查，真要量一次照下面那套内联副本 + `check` 的程序办。

#### 整页画布（段落 `layout: "canvas"`，结构性页用顶层 `opening_layout` / `closing_layout`）：这一张 SVG 就是整个画面

**什么时候换整页**（选型判据只写在这一节，别处一律指向这里）：

- **内容装不下 4:3 槽位**：数据关系、长时序、多层系统图——槽位就这么大，硬塞的结果是把字号压到「文字与尺寸」那条 26px 下限以下。
- **这一页本身就该是一张海报**：章首、转折、结论、金句。卡片版式是"标题浮在图外"，画布是"标题和要点作为一个整体被看见"，后者那种分量卡片给不了。
- **这一段只需要画面**：过场、留白、真实场景照片（后果见下面照片那一档）。
- **节奏：主动穿插，别把它当应急开关**。槽位版式每个内容段都是同三层（标题区 + 4:3 图 + 句子流），连放五六段就是同一张卡片重复五六次——观众的眼睛会先于内容疲劳。所以内容段 ≥5 段时给 2–3 段换画布，段数少就 1 段，位置挑在章首或转折。**两条边界**：别连着两段都用（连着满幅就不叫破节奏了，读起来像整套模板换了）；旁白最密、最需要观众逐句跟读的那一段**别换**（画布页连句子流的 DOM 都不生成，换了就是画面上一个字都没有、只有声音）——**这一档节奏纯粹是观感，门禁不看段与段之间的关系**，它唯一量得到的代价是：每穿插一段就多一张要按画幅原尺寸手绘的 SVG。
- **开屏/结尾也可以整页**：顶层写 `opening_layout: "canvas"` / `closing_layout: "canvas"`，那一页走的就是本节这条路。代价是那张投影卡整个不上画面——章节列表、要点总结、`cta` 尾行都没了，标题和该说的话全得画进图里（实测 1080×1440 手绘海报：标题 80px、章节行 44px + accent 序号、旁白两行 40px，四周留 72px，`check` 全绿，但图内对比度它数不到，账照上面那张取色表自己算）。

**什么时候别换**：该段口播要靠字幕跟读（画布不生成句子流层，旁白不会上屏，也没有"页底字幕带"这种兜底）；不想自己把标题画进 SVG（画布不生成标题层，图内标题得你自己画）；一期要出两个画幅却只打算画一张 SVG（画幅各画一张，见下面第一条）。

字段语义见 `references/writing.md` 段落 `layout`；塌成一层之后的版式与门禁变化见 `references/rendering.md`「画面结构」。画这张 SVG 时只有六条和上面的槽位版式不同：

- **几何换成整个画幅，不再是 4:3**：竖屏 `width="1080" height="1440" viewBox="0 0 1080 1440"`，横屏 `1920×1080`。两画幅都要出片就**各画一张**（`cover` 会把不等比那张的图内标题整块裁到画面外，而 `check` 看不见这种丢失，所以 `gen_hyperframes.py` 在生成期按文件验：根标签读不出纯数字 `width/height` 或 `viewBox`、或比例与当前画幅不等比，直接 exit 1）。
- **等比之后还要按画幅原尺寸画，不能靠放大画布凑**：成片把 SVG 按 `画幅宽 ÷ SVG 宽` 整体缩放，图内每个字号都乘这个系数。按 2560×1440 画的 16:9 塞进 1920 画幅，比例对、却缩到 0.75，28px 折算只剩 21px——跌破下面「文字与尺寸」那条 26px 下限就是读不出来，而这一档同样只有按文件量得到（字号写成 px 才能验；写成 `em`/`%`/class 时门禁读不出绝对值，只有图真在被缩小（SVG 宽 > 画幅宽）时才打一条 `[warn]` 让你自己按画幅复核——按画幅原尺寸画时连这条都没有，更要自己盯）。**按画幅原尺寸画就不用猜**。
- **安全边距照页面走**：竖屏四周留 50px、横屏留 96px，图内文字越界就是出血。两处实测翻车值得记住：竖屏一行 `3 h 40 min` 右缘到 1066（上限 1030），横屏一个时刻标签放在 `x=1800` 右缘到 1846（上限 1824）——`text-anchor="end"` 的落点要按量出来的字宽倒推，不是按字符数估。
- **"不铺满幅底"这条在这里更要紧**：留透明才能透出模板那三层背景，自画满幅底板等于放弃它们；理由、例外（什么时候确实该自铺一张）和 `check_svg.py` 的 warn 口径都在上面「不铺满幅底」那一节，这里不复述。
- **图内可以有标题，字号按整页读**（槽位版式那条"图内文字只起指示作用、没有标题这一档"在这里不适用）：实测可用的量级是标题 72–76px、小标题 38–48px、正文 30–40px、kicker/图例 26–28px。字号越大越要自己复查对比度——**这一版的 `Contrast` 门禁数不到你**，取色表照上面那张用。字体名写死（`'Microsoft YaHei','PingFang SC',…`）：SVG 走 `<img>` 载入，读不到页面的 `--ctv-font-*` 变量。也正因如此，生成期会打一条 `[warn]` 报"该段 N 句旁白不会上画面 / 这张 SVG 里有 M 个 `<text>`"：要点有没有真的画进图里，机械判据只有这个数量，剩下的账要自己对。
- **机械劳动可以交给脚手架**：`python scripts/canvas_kit.py --spec spec.json --aspect portrait -o images/seg1.svg` 吃一份元素清单（`{"aspect"?, "accent"?, "elements": [ … ]}`，kind 有 `panel`/`axis`/`polyline`/`bars`/`circle`/`text`/`rule`），吐一张**按画幅原生尺寸画的透明底画布** + 一份能直接塞进 images.json `director` 的 steps 草稿（`--emit-steps` 另存）。

    **它收走的只是机械部分**：画布几何、三档字号取自模板 `layout.<画幅>.*.fontSize`、线宽跟进度条、取色过 `_theme` 的对比度压暗、结构底与内容元素的初始 `opacity` 分档（`draw`/`count`/`type` 那三种"起始态由渲染端自己配"的元素**不会**被写 `opacity="0"`，写了就永远不亮）。

    **构图仍归人**——所有坐标由 spec 给，脚本不做任何自动布局。

    两条刻意的取舍：草稿的节拍只用 `at`（句序）不用 `at_time`，因为绝对秒是按某一版配音手算的、重配音会整体漂移且不报错。产物生成后按 `check_svg` 的 canvas 口径自查一遍（判据不重抄第二份，抄了就会漂），所以画完还要过的空带/对比度/字号三条它已经先替你量了。`--no-check` 只给有意为之的极简页。

**给上 `--sentences <该段句数>`，草稿才是真能直接用的那份**。不给时自动拍按元素顺序一路 `at=0,1,2…`，内容元素比旁白句子多时最后几拍会落到句序之外，生成期按 `error` 整条拒掉（"at=N 越界：该段只有 M 句旁白"）。给了句数，自动拍的游标按它取模回绕，多出来的元素与前面的同拍一起亮，产出的草稿直接塞进 `images.json` 就能生成；它同时替你把**显式钉拍**（元素里写 `beat`）的越界提前打成 `[warn]`——那才是需要你回头改的地方。

照片当画布**不做比例与字号校验**（它们没有"画在里面的字"，`cover` 裁边是正常取景），但也要清楚后果：这一版没有标题层，配一张照片就等于该段整段时间只有画面和旁白、屏幕上不出现任何标题——所以生成期照样给一条 `[warn]` 让你知情。想留标题就得把这一段的要点画成 SVG；确实要一段"只有画面"的过场，忽略那条 `[warn]` 就行。

#### 整页画布的密度与层次：这一页经得起暂停吗

槽位版式的构图有模板兜底（标题区、图槽、句子流各自就位，画得平庸也不会空），画布档把这层兜底整个拆了——**这一页的密度、层次、节奏全是你一个人的责任**。而观众看成片的方式是"扫一眼",所以判据不是"画了多少个元素"，是**随便暂停一帧，画面还成不成立**。用 `npx -y hyperframes snapshot --at <秒>` 把画布页截出来看，比在浏览器里滚时间轴诚实得多。

- **竖向不许有整条空带**（`check_svg.py --layout canvas` 会 warn，阈值 25% 页高）：这是唯一能机械判的一条，因为它对应的失败最典型——entropy demo 的第一版画布，上面两行标题（y≈150–240）、中间一条轴（y≈800），**中间 486px（34% 页高）横着什么都没有**，暂停就是一页空白。分工记法：标题在上 1/4、主视觉占中部并**撑到接近页宽**、注脚与结论压在下 1/4，三段之间用中景元素连起来，别留断带。
- **一页至少三层**：背景层（模板那三层，见上面「不铺满幅底」——它归模板，你别铺满幅底把它盖掉）、中景（主视觉：图、模型、流程，外加它自己的局部底板/面板/分隔带做明度层级）、前景（标注文字、数值、accent 强调）。画布页的常见病不是画错，是**只画了一层**——单层画面在任何时刻都只有一件事可看，观众读完就只剩空白。背景那层归模板不等于中景可以不分层：中景自己也要有"面板 < 底板 < 页底"三档明度。
- **主视觉要有尺寸下限**：示意/数据图占页宽 ≥70%、占页高 ≥45%。缩在角落的一张画布图比放进槽位更难看，因为周围全是它自己的留白，没有版式替它撑。
- **辅助线要敢用亮档**：轴线、网格、分隔线在 dark 页底上不要低于 `#64748b` 一档，线宽 ≥3px（1080 宽画幅经压缩后，`#475569` + 2px 的实测结果是"根本没有画"）。层次靠**明度差与大小差**做，不靠透明度——`opacity` 一低，对比度门禁与观众一起失去它。
- **字号最多三档 + 一档 accent**：量级照上面那条实测数字（标题 72–76 / 小标题 38–48 / 正文 30–40 / 标注 26–28），最大档与最小档的比值 ≥2，观众才分得出主次。一页里每个元素都染不同颜色不叫层次，叫彩色：一个 accent 负责"现在看这里"，其余走中性灰阶。
- **数信息单元**：这一页有几个独立可看的东西（一块图、一行结论、一组标注各算一个）？**少于 3 个就别当画布页做**——那它本质是字卡，按海报的标准重写（金句 + 大字），或者退回槽位版式让模板去承担构图。
- **导演页还要看"起始帧"**：终帧密度达标不等于开头不空。逐拍揭示意味着前 1 秒画面是空的，而画布段现在**没有转场遮这一下**（见 `references/rendering.md`「动画」的整页画布段条目），空就是硬切之后直接给观众看的。背景那三层归模板、随页面一起出现，所以只要你不铺满幅底（见上面「不铺满幅底」），第一帧至少不是死平的一块色。剩下的解法两条：把**结构底**（坐标轴、外框、分隔带、面板格子）不写进 `director.steps`，让它和页面同时到位，只逐拍长"内容"；或者把第一拍放在 `at_time` 0.1s 量级，让墨在切完立刻落下。

### 数据图的几何自查：库走了，账要自己算

一张手绘的数据图（柱状、折线、饼环、散点、时间轴）里，**长度/角度/坐标本身就是数据**。比例画错一档，屏幕上就在教观众读一份错的数据，而这条错误链上没有任何检查看得到：`gen_hyperframes.py` 只校验 SVG 文件存在，外加整页画布那一组按文件的对账（比例 + 图内 px 字号折算，见上面「整页画布」），`check` 只量 HTML 文本。刻度分档、比例映射、数值定位全是自己做完再自查：

- **先定标尺，再画图形**：把数据区间到像素区间的映射写成一行的线性式（`y = y0 - (v - vmin) * (h / (vmax - vmin))`）放在 SVG 注释里，所有柱高/点位都由它反算，不要凭手感逐个调。坐标轴刻度取整档（1/2/5×10ⁿ），别为了对齐图形去改数据。
- **用两端点回算验证每一档**：画完拿最大值的柱顶与最小值的柱顶相减，得数应等于"量程 × 标尺"，对不上就是映射写错而不是画歪了。**pie / 环形先查总和**：各扇区角度相加必须等于 360（`占比 × 3.6`），差一度说明漏了一项或分母取错。
- **量文字，不数文字**：定宽的元素（刻度、数值标签、图例）按实测宽度排版——`text-anchor="end"` 的落点要倒推字宽。两条可跑的量法：SVG 开进浏览器用 `getBBox()` 读元素左右缘，或用 `npx -y hyperframes snapshot` 把摆进项目的图按时刻截一帧看贴边与溢出（命令见 `references/rendering.md`「官方校验命令」）。整页画布的安全边距（竖屏 50px / 横屏 96px）同样按量出来的右缘判，见上一节那两处实测翻车。
- **公式就是图内文字**：`E = mc^2` 这类本体要用 `<text>` 画——上下标靠 `baseline-shift` 或两个 `<tspan dy>`，字体栈照下面「文字与尺寸」自带，下标比正文小的字号同样受 26px 那条下限约束。

公式与数据的**内容**红线（不为好看改数字、不用误导比例、不编造数据点）见本节开头。

### 文字与尺寸

图表、公式、SVG 内部的文字必须按“**进入内容画布后**的最终可读性”设计，而不是按原始文件尺寸设计。

图内只有起指示作用的文字，**没有"标题"这一档**（见「不铺满幅底」）；最大的一档 35–40px 给图例名或底板上的大字，正文级从 35px 起步（画布统一按 980×735 画，见「画布几何」）；如果内容很密，优先减少文字、扩大图形，不要继续压字号。**26px 是下限**：再小，两画幅缩放加成片压缩编码后就读不出来了——宁可换行或加长底板，也别缩字号。

底板内还要**估一次宽度**：一行汉字数 ≈（容器宽 − 左右内边距）÷ 字号。980 画布上留 48px 内边距、52px 字号 → 一行约 17 个汉字。溢出时换行或加宽底板。

SVG 以 `<img>` 载入时是独立文档，页面的 `--ctv-font-family` 渗不进去，`<style>` 里要自带中文无衬线字体栈（如 `"Microsoft YaHei", "PingFang SC", "Noto Sans SC", "Noto Sans CJK SC", "Noto Sans CJK JP", sans-serif`——Linux 沙箱里 `Noto Sans SC` 会回落到无 CJK 字形的 NotoSans-Regular，`Noto Sans CJK SC/JP` 才是能匹配上的名字，别省）。


## 已知翻车速查表

按**看到的症状**查，不按知识点查——出问题时你手里只有一个现象。每条给的是成因与去处，判据和实测数字在去处那一段里（那些数字都带成立条件，脱离语境单看会误用）。

| 看到的症状 | 成因 | 去处 |
| --- | --- | --- |
| 推镜时页底标签不见了、页顶标题贴着边 | `scale>1` 以 `svgOrigin` 为中心放大，离焦点越远位移越大。**留白要按"推完那一帧"算，不是按 SVG 源码算** | 「运镜 / 相机」的「为什么」 |
| 推近的图形压到了旁边静止的标题或旁白上 | 出画 warn 只判"出画"，不判"撞字"；两者都没出画时无人拦 | 「运镜 / 相机」的「机器兜不住的那件事」 |
| `keep` 接续页界上图形**位置**跳一下（尺寸不变） | 没写原点时 GSAP 绕 `#cam` bbox 左上角，那个角还跟着别的步的 `from` 瞬态飘 | 「跨段场景延续」的「相机绕的那一点是渲染器钉的」 |

| 图内标签在成片里看不见，全流程零报错 | `<img>` 载入的 SVG 里文字不属于 HTML 文本流，没有一道检查量它 | 「图内文字的对比度」的「为什么只能自己盯」 |
