# 第 3 步 · 一组元素的错峰：窗口、曲线、锚点

同一拍上有**一组**元素逐个出场时读这一份（标题揭示边的逐字、agenda 行列表、图里 `.class` 目标）。该不该动、动多快、每一拍落成什么 → `motion.md`；这一拍的整体契约与体检 → `motion.md`「二、怎么写这一拍」。

一组元素出场只有三件事可调，按顺序定：**多久演完**（窗口）、**间距怎么分**（曲线）、**从哪一头起**（锚点）。三件都写在同一枚旋钮里：

```json
{"at": 2, "target": ".node", "from": {"opacity": 0, "scale": 0.94},
 "to": {"opacity": 1, "scale": 1},
 "stagger": {"amount": 0.36, "ease": "power2.out", "from": "center"}}
```

## 一、写窗口，不写每项步长

错峰写 **窗口**——最后一项比第一项晚多久——而不是"每项隔多久"。GSAP 原生就有这一枚旋钮：模板侧取 `animation.staggerDistribute.ease` 的形状配 `window`，作者侧写 `stagger: {"amount": 0.3, "ease": "power2.out"}`。两条理由：

- **快慢不该由项数决定**：写"每项隔多久"时总跨度 = 步长 ×（项数−1），同一份模板在 4 字标题上是 0.036s、12 字上是 0.132s——标题越长揭示越拖，而"这一页揭示多久"是这一页的属性。写窗口之后两者都是那个数。
- **间隔不该等差**：等差的边是匀速推进的一条扫描线，读出来是"机器在报数"。曲线取 `power2.out`：分配是先疏后密——最先几个各自站定让人读出来，末尾连成一条线扫过收尾，与本仓库其余入场同族（`.out` 的另一半用法）。

判据两条，由 `tests/test_motion_design.py` 按 GSAP 实采的账算（口径对着钉固 bundle 量过）：相邻间隔的最疏/最密 ≥2 倍且单调递减；最后一项的出发延迟恒等于窗口（项数 2/6/12/40 都是它）。`ease` 写成 `"none"` 即退回等差——旋钮关得掉。

## 二、从哪儿开始动：锚点

窗口定了"多久"，曲线定了"疏密"，还剩一枚：**这一组的边从哪一头起**（`stagger.from`，缺省 `start` = 第一项）。它不改窗口、不改疏密，只改**先后属于谁**——而在屏幕上，先后本身就是一句话："按顺序读"、"从中间长出来"、"从两边合拢"、"从最后一件往回卷"。

| 锚点 | 读出来是 | 什么时候用 | 反例 |
|---|---|---|---|
| `start`（缺省） | 按读序推进 | 文字类目标：标题逐字、agenda 列表、正文条目 | — |
| `center` | 中心先站定，四周随后铺开 | 有"核心"的构图：枢纽图、同心结构、放射状节点 | 一排等权的并列项（中项没有特权） |
| `edges` | 两端先起、在中线合拢 | 对称构图：并置对比的两侧、环形排列、从外向内收 | 一条单向的流程链（会读成两头同时开工） |
| `end` | 从最后一项往回卷 | 回顾/清单收束：先把结论摆出来，再往回补证据 | 正序叙述的段落 |

也可以写一个**项号**（`"from": 2`，非负整数）当锚点：这一组的先后从第 3 项起，常用于"说到哪个就点亮哪个"之后让剩下的往外扩散。项号超出范围时 GSAP 夹到两端，本仓库不另作处理。

**锚点数的是文档顺序，不是画面位置**：不写 `grid` 时，`center` 指的是"这一组在 DOM 里的中项"——枢纽图想让中枢先亮，要么把中枢排在中间那一项，要么直接写它的项号。`edges` 同理数的是头尾两项，画面上一左一右并不等于文档里的首末。

判据（`tests/test_motion_design.py` `StaggerAnchor`，真值是钉固 gsap@3.14.2 的 `distribute` 在 Chrome 里逐项采出来的）：**窗口不变**——不管锚点在哪，最晚那项仍落在 `amount` 上（中心锚点下起点不是 0，但最晚的那一项仍是窗口本身）；**先后按到锚点的距离单调**——离锚点近的先动；`ease` 的形状照旧作用在"归一后的距离"上，所以靠近锚点的几项先各自站定，远端连成一条线收尾。

**两项的组没有中间**：`center` 在 2 项上退化成同时出发（距离相等，归一化后都是 0），`edges` 在 3 项上让中项最后落——锚点要"数得出中间"才有意义，**5 项以下先问一句这组到底是不是一排**。二维排布（图标矩阵、九宫格）按 `grid: [列, 行]` 算距离，此时"中心"是**画面上**的中心，不是下标的中点。

## 三、三条写错就静默失效的（生成期直接拦）

`_images_schema._validate_stagger` 是三处的唯一真源（images.json 与 `canvas_kit` 的 spec 共用）：

- **锚点拼错**（`"middle"`、`"centre"`）：GSAP 不报错、按 `start` 排。成片里那组元素照旧从左扫到右，与作者写的"从中间展开"相反，而且没有任何一处会变红。
- **`each` 与 `amount` 并写**：GSAP 只认 `each`，`amount` 被丢掉。5 项时两者收尾都是 0.4s、看不出破绽；12 项就是 1.1s——"这一页揭示多久"又被项数决定了，正是上一节要消灭的那件事。
- **小数项号**（`from: 1.5`）：算出的是非单调的出发时刻（实测 5 项 → [0.2, 0, 0, 0.2, 0.4]，中间的比两头还晚），读出来是"卡了一下"。项号只收非负整数。

## 四、哪些地方不给锚点

- **字幕换句**：位移只写在列容器上，行自己一条补间都没有（见 `look.md`「字幕：焦点、换句、时钟」）——给行加锚点就是给每句加一条独立的飞行动作。
- **标题的揭示边**：边是一条从左到右连续移动的线，从中心起会把它拆成两段。
- **顺序类目标**：这一段在讲"第一步、第二步"时，先后是**内容**排的，不是排版排的。

写完之后 `run.py --until html` 会把这一拍连同"起点出窗/被切半路"一起体检（见 `motion.md`「体检」）。
