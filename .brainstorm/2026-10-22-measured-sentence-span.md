# 2026-10-22 · 句长改按实测语音：让"换句"与"高声念到哪儿"回到同一个时钟

前两轮（`2026-10-20-emotion-temperature-arc.md`、`2026-10-21-infer-stage-keep.md`）
改的都是"缺省值替作者做选择"。本轮换一类：**数据本身不够准**——时间轴里的"这句话
有多长"一直是个高估的量，代价落在字幕与卡拉OK上。

## 一、现状与前沿案例

| 观察 | 现状（改动前） | 前沿案例在做什么 |
| --- | --- | --- |
| 一句"多长" | `duration` = 该句 WAV 的**文件长度**。TTS 在句尾留的那口气、收尾拖音全算在这句头上 | 字幕系统（BBC 字幕规范、Broadcast 的 EBU-TT）按**说话首尾**切 cue，句后静默归入间隙 |
| 换句时刻 | 下一句 `start_time` = 上一句文件长度 + `gap`。念完还停着，下一句字幕**迟迟不换**；观众以为卡了 | 换句发生在**下一句第一个字出声**的时刻 |
| 卡拉OK进度 | 句内匀速，分母是**文件长度**。长句的最后一个词先亮完、再干等几百毫秒 | 分母是**说话长度**；Apple 歌词、Karaoke maker 都按发声区间归一 |
| 最后一页 | 页末总留一段"已念完但字幕还亮着"的死时间，转场被这段死时间顶后 | 页尾与句尾对齐，转场落在话落的那一刻 |
| 已知误差 | 稿件层面留了一条经验规则："长句（>5s 且带两三个标点）才会放大到 1s 量级" | 误差不该靠写稿规避开，该量出来 |

三处用的是同一份不准确的量（`_manifest_schema` 只认 `start_time`/`duration`），
所以任何一处单独修都会和另外两处打架。

## 二、做不了的那件事，先说清楚

**词级强制对齐（forced alignment）**：最能根治卡拉OK误差的做法是拿到每个字的
时间戳。本轮**不做**，理由不是难，是**手上没有可验的证据**：

- 沙箱里没有 `MIMO_API_KEY`，合不出真实 TTS 音频；
- 没有 ASR / 对齐模型（whisper、MFA）可用，装一个带模型权重的依赖并塞进一个
  "只用标准库"的技能包，代价远大于收益（SKILL.md 的环境表只有三条依赖，这条
  会把它变成第四条且带模型下载）；
- 现有的在线语音样本源要么 5xx、要么只有单词级，**拿不到"多句、带标点、接近
  TTS 语速"的语料**去校准停顿权重。没有校准就上线权重，等于把一个拍脑袋的数
  写进作者文档——上一轮已经吃过"拿假设当判据"的亏。

所以本轮只做**能被现有证据支撑的那一半**：用 `ffmpeg silencedetect` 量出每句
真正的"开口 → 收音"，把 `duration` 从文件长度改成发声长度。这一步的精度我在沙箱里
实测过（见「四、验收」）：合成样本里埋 300ms 前导静音，检出 0.372s（TTS 自身还有
72ms 起音），误差 ≤ 1 帧（20ms）；阈值 −30/−35/−40/−45dB 检出结果完全一致，
不是一个碰巧调出来的数。

**给下一轮的钥匙**：发言长度一旦进了 manifest，句内停顿的位置就成了"可校准的
先验"。下一轮若拿到真实 TTS 语料，只需要在 `_speech._parse_silences` 之上加一层
"标点 × 停顿时长"的权重表，卡拉OK就能从匀速升级成按停顿分段匀速——**契约不用再动**。

## 三、做法

1. **`_speech.py`（新增）**：`measure_voiced_span(ffmpeg, path, file_seconds)`
   读 WAV 头（采样率/位深/单声道），用 `silencedetect=noise=-35dB:d=0.05` 拿
   所有静音区间，返回 `(onset, voiced)`：
   - `onset` = 第一个非静音样本的时刻（前导静音之后）；首个静音段从 0 起算时取
     它的 `end`；
   - `voiced` = 文件长度 − 首尾静音；结构上夹在 `[下限, 文件长度]`。
   - **所有数都对齐到 20ms 帧网格**（静音检测的扫描步长），这样 `onset` 与
     `start_time` 能精确相加，不会因为亚毫秒噪声在契约层撞出"重叠"。
   - **纯函数、可脱离 ffmpeg 测**：`_parse_silences(stderr)` 单独可测；
     读不到 WAV 头 / ffmpeg 失败 / 全静音 → 返回 `None`，调用方退回文件长度。
2. **契约加两个可选字段**（sentence 层，`MANIFEST_SENTENCE_KEYS` 同步）：
   - `onset`：句首静默秒数，`0 ≤ onset`；
   - `voiced`：发声秒数，`0 < voiced ≤ duration`。
   两句同时在场才有意义：只写一个说明手写时漏了另一条，直接判 error（与
   `speaker`/`synth_failed` 那种"可选但写了必须合法"同一口径）。
   `start_time`/`duration` 的语义**一个字不改**——它们是音频块的位置与长度，
   下游（拼接、时长对账、cue 窗口）全依赖它。
3. **pipeline 写入**：在量 `duration` 的同一处把 `(onset, voiced)` 挂到该句上
   （缓存命中/变速重算/新合成三条路径都要经过 `measure_duration`，挂点只有一处）。
   全静音兜底句不写这两个字段——它本来就没有"发声"。
4. **字幕换句**：cue 起点从 `start_time` 改成 `start_time + onset`（有该字段时）。
   `duration` 仍按音频块算，所以**句间 `gap` 自动变长**（gap 的真实含义一直是
   "两句之间没声音的那段"，以前被尾随静默吃掉了）。
5. **卡拉OK**：运行时把进度分母从 `t1 − t0` 换成 `voiced`（经 `data-voiced`）。
   句尾的"干等"变成数字正常停在 100%，而不是提前亮完再僵着。
6. **文档**：`tts_pipeline.md` 的 manifest 字段表、`rendering.md` 的词级强调一条，
   以及 `canvas.md` 里 `at` 小数偏移那条"唯一放大到 1s 量级"的经验规则改写成
   "那 1s 里有多少是尾随静默，现在能量出来了"。

## 四、为什么这样取舍

- **为什么不直接改 `duration` 的定义**：`duration` 是音频块长度，拼接、对账、
  窗口计算都读它；把它改成发声长度就得同步改至少四处消费方，且历史 manifest
  的语义会静默漂移。加字段是**向后兼容**的：老 manifest 没有 `onset` 就退回旧
  行为（cue 起点 = `start_time`），不会有一份产物突然换了时间轴。
- **为什么不用 `astats` 逐帧能量自己算**：`silencedetect` 已经在样本里验证过
  精度（±1 帧）与阈值稳健性；自己写包络要复现它的平滑窗口与判据，等于把一份
  未经校准的算法塞进来。
- **为什么阈值取 −35dB / 最短 50ms**：−30 到 −45 在这个样本上检出完全一致，
  取中间值不是因为它"最对"，是因为它对两侧都不敏感；50ms 下限刚好卡在
  "齿音间隙（<40ms）不当停顿、句尾换气（>100ms）算停顿"之间。
- **新增降级项**：量不出来就退回旧行为，**不进 `degraded`**——这不改变产物内容
  （只是少了精度），而 `degraded` 的语义是"用户显式要的东西没做到"，混进去会让
  正式渲染被一条无关紧要的 warn 拦下（exit 3）。

## 五、验收

- 全量单测通过（本轮新增 `tests/test_speech.py`：解析器 6 条 + 区间夹算 6 条 +
  pipeline 写入 2 条 + 契约 4 条）；三道文档契约全绿。
- `tests/golden/*.html` 逐字节不变：本轮不改模板里任何静态描画，只在

- 合成样本实测：埋 300ms 前导静音 → 检出 0.372s（含 72ms 起音）；阈值
