# 2026-10-25 · 焦点层级的第二个维度：让"远"不只变暗，也变小

上一轮（`2026-10-24-focus-falloff.md`）把三档阶跃改成按离焦距离衰减的曲线，让
句子流有了纵深。本轮接着问：**那条曲线只被用在了一个属性上，够吗？**

不够。那一轮做完，"远"仍然只等于"暗"——同一档里，第 2 行和第 4 行完全一样远。
这轮的活是把第二个属性接进同一条曲线。

## 一、现状与前沿案例

| 观察 | 现状（改动前） | 前沿案例在做什么 |
| --- | --- | --- |
| 层级落在几个属性上 | **一个**：只有 opacity | Apple Music 逐行歌词：spring 动画同时动**缩放与透明度**——active 行更大，past 行缩小，future 行收敛 |
| 同一档内的区分 | 无：d=2 与 d=3 亮度不同但都在"没念到"那一坨里，视觉上是一堵均匀的墙 | AMLL（Apple Music Like Lyrics）的 LyricPlayer：spring physics 同时管**垂直位置、缩放、透明度**三个属性 |
| 焦点的"重量" | 当前句只是更亮，字号与邻行完全相同 | 2026 的 kinetic typography 主线是"排版层级也是动效层级"：大小、字重、字距都参与表达谁是被说的那一句 |
| 定位的克制 | — | 同一批趋势报告的另一半是 *Less Motion, More Meaning*：不是加更多动作，而是让已有的动作承载更多信息 |

值得留意的是，这些案例里**缩放的幅度都很小**。Apple Music 的 active 行与邻行是
24pt 与略小一档的差别，不是 24pt 与 12pt。所以本轮不是"给字幕加动效"，是"给
已有的那条曲线再找一个落点"。

## 二、为什么必须是 transform，不能改 font-size

第一反应是"远处的行字号小一点"，直接写 `font-size` 最省事。它在三处同时塌：

| 改 font-size 的后果 | 为什么塌 |
| --- | --- |
| 折行点变 | 字号变了，一行能装下的字数就变了——行会重排 |
| 滚动锚点漂 | 滚动公式读 `ln.offsetTop`（布局值），重排后它变；首句/尾句的落位跟着抖 |
| **覆盖层重影** | `.verse-ved` 是生成期写死的**整句原文**、靠"与正文共用同一套行盒"保证逐字重合。正文一重排，覆盖层那份不动，两句折到不同位置——正是覆盖层走过的那条弯路（改 `slice(k)` 那次） |

`transform: scale()` 不进布局：`offsetTop`、`clientWidth`、`scrollHeight` 全是
原值，**滚动公式、逐字命中测试、字宽测量一个字节都不用改**。覆盖层是行的子元
素，跟着同一个变换走，重合关系自动保持。

同理，**只写 `scale`、不写 `translate`**：位移归 `.verse-clip` 独占（它的
`translateY` 按 `offsetTop` 算落位），行上再叠位移会把行推离锚点。上一轮淘汰
"字幕层视差"时也量过同一个事实。

还有一个不选 `font-size` 的附带理由：它是**每帧重排**，而 `transform` 是合成器
的事。逐帧抓帧的成片里这个差别会实打实地落在渲染耗时上。

## 三、0.94 是算出来的，不是拍出来的

两个维度用**同一条几何曲线**（每远一档乘一次 ratio），但 ratio 与封顶不同，因为
两个维度的**失效边界**不一样：

- **亮度可以一直暗下去**——暗到看不见就是"退场"本来的意思（0.237 仍可见，只是
  不再有信息）；
- **尺寸不能一直缩下去**——缩到读不出来就不是退场，是把字幕毁了。

于是 ratio 的取值区间被两端夹出来（最小字号是横屏的 33px，可读下限是
`MIN_READABLE_FONT_PX` = 26px）：

- **不能太小**：最深那一档必须守住可读下限。过去侧错位一档后最深是 `s³`，要
  `33·s³ ≥ 26` → `s ≥ 0.924`；
- **不能太大**：`d=1` 那一档要真的看得出来，`33·(1−s) ≥ 1px` → `s ≤ 0.970`。

`s ∈ [0.924, 0.970]`，取 **0.94**：落在区间内偏"衰减更明显"的一侧，但离两端都
有余量。

**封顶也跟着定下来**：尺寸封**两档**（最深 `0.94³ = 0.8306` → 33px 缩到
27.4px，仍在下限之上），亮度封**三档**。反证是现成的——再多封一档就是
`0.94⁴ → 25.8px`，破线。这条不对称写在代码里、也写进文档，因为它看起来像
不一致，其实是从同一个判据推出来的。

> 关于"可感知"：上一轮量过"字幕层视差 3~4px 低于可感知阈"，淘汰了视差。这一
> 次的 2px 是**相邻两行的静态尺寸对比**（并排、直接比），不是**整块相对背景的
> 平移**（需要参照物）——排版层级的辨别阈远低于运动位移的辨别阈。我没有去测
> "人眼能不能看出 2px 字号差"，本轮实测的是数值正确、无回归、无重影；幅度是
> 设计判断。

## 四、换句接力的尺寸分量

焦点那一档只在换句时变，所以新句成为 active 的那一刻，尺寸会从 0.94 直接跳到
1.0——硬切。亮度那边已有 0.32s 的接力，尺寸得接上同一段行程。

两个决定：

- **共用同一个 `p`**：尺寸与亮度必须在同一时刻到位。"焦点"不能在途中分裂成"先
  长大、后变亮"两个动作。
- **起点不同**：亮度从 0.35 起（比 past 档还暗，是"从更深处浮出"的换句信号），
  尺寸从**未来档 0.94** 起。照抄 0.35 会把新句先缩成一小团再撑开，读成形变而
  不是入场。

合成规则与亮度完全同一条，CSS 里就是换了个属性名：

```css
opacity:min(var(--ctv-line-op,.62),var(--ctv-relay,1));
transform:scale(min(var(--ctv-line-scale,1),var(--ctv-relay-scale,1)));
transform-origin:left center;
```

`transform-origin` 锚**左缘**是第三个决定：字幕是左对齐的，绕中心缩放会让行的
左边界在换句时左右抖。那道左缘是句子流里唯一不动的基准线。

## 五、顺手堵上的坑：`--ctv-ved-dx` 是在最小 scale 的那一刻量的

覆盖层要补偿"正文首字因说话人标签往右让开的那一段"（`--ctv-ved-dx`），用
`Range.getBoundingClientRect()` 量。而 `getBoundingClientRect` 返回的是**变换
后**的几何——行此刻正被 scale 缩着。

要的是**布局值**：覆盖层是行的子元素、与行同一个 scale，两边同比例缩放，按布局
值写才对得上。不除回去的后果，实测如下（对话段首句，标签段 68px）：

| | `--ctv-ved-dx` | 覆盖层首字左缘偏移 |
| --- | --- | --- |
| 除回 scale（本轮） | 68px | **0.00** |
| 不除（对照） | 63.9px | **−4.11px** |

4.1px 的横向重影，在 40px 字号上是看得见的。

这个坑有个反直觉的地方值得记下来：**量取几乎总是发生在 `scale` 最小的那一刻**。
覆盖层首次上屏就在换句那一帧，而那一帧正好是接力的起点（`p=0`）——所以量到的
不是"稳态的 0.94 或 1"，而是接力途中某个值（实测 t=7.5 那次是 0.9962，量到
67.7px）。换句话说，它不是"偶尔会错"，是"几乎每次都错一点"。

修法是除以当前 scale，而 scale 是**纯派生量**：变换后宽 ÷ 布局宽
（`getBoundingClientRect().width / offsetWidth`）。不新增状态——这条很重要，上一
轮那个 bug 的全部教训就是"缓存可以清，状态必须能从 t 重推"。

## 六、淘汰掉的四个候选（都推过）

- **模糊做景深（blur）**：Apple 确实给已念的行加轻微模糊。不做，理由是**字幕的
  第一职责是被读懂**——歌词可以模糊（旋律还在，字只是提示），字幕模糊了就只剩
  声音。它还和 `.verse` 的 mask 渐隐抢同一片边缘（边缘行本来就在虚化，再糊一
  层会糊成一团），而且 filter 是逐帧卷积，句子流一屏 3~5 行全带核，抓帧耗时
  实打实地上涨。
- **字距（tracking）当第二维度**：开场 kicker 已有字距舞，下沉到字幕看起来很自
  然。但 letter-spacing 改变字宽 → 改变折行 → 与上面「二」里 `font-size` 同一
  条塌陷路径。而且字距变化会让整行"呼吸"，比缩放抢眼得多，不符合克制那条。
- **位置（translate）当第三维度**：AMLL 的 spring 确实管垂直位置。这里位移归
  `.verse-clip` 独占；上一轮也已量过字幕层视差低于可感知阈。
- **可变字重的字重轴**：字体栈（Microsoft YaHei / PingFang SC / Noto Sans SC）
  没有可变字重轴；而且行上的注释本就写明"字重恒定，避免切换时字形宽度跳变"。

## 八、留给下一轮

- **退场那一档还是硬切**：新句是软的（接力把尺寸从 0.94 推到 1），旧句是硬的
  ——换句那帧从 1.0 直接到 0.8836。亮度那个维度本来就硬切，且同时有滚动位移掩
  盖，12% 的幅度当下可接受。要软退场就得让回缩借用句尾留白，而那段留白已经被
  settle 占满；两个动作挤一段留白需要一条新的分配规则（上一轮也留过类似的
  话：把接力也改成由留白推导，两者按比例分）。
- **尺寸只做到"档位"，没做到"连续"**：`d` 是整句的句序差，而真正的景深应该按
  像素距离衰减——离窗口中心越远越小。行的位置本来就在动（滚动），按像素算就得
  每帧重算，但那也顺带把"正在进入窗口的那一行"的渐入做出来了。
- **覆盖层的测量仍集中在换句那一帧**：本轮除回 scale 让它量得准，但"几乎所有
  测量都发生在 `p≈0`"这件事本身还是脆弱的——任何将来加在行上的入场动作都会再
  次踩到它。
