# 第 3 步 · 拖曳档：让一条链跟着同一个动作落定

`beats` 决定这一页演什么 → `references/motion.md「四职务」`；一拍之内的发力、
形变与落地 → `references/momentum.md`；落位之后怎么留白 → `references/hold.md`。
**这一份只管一组元素：同一个动作怎么沿链传下去，又怎么一起停住。**

## 一、对标：缺的是相位域，不是又一条错峰

已有档位把**一个元素**的运动做透了：行程预算（`references/motion.md「曲线的行程预算」`）、
两轴异缓动的弧线、入场阶梯、受控弹簧、hold 慢推，以及惯性档的预备 / 挤压拉伸 /
跟随。它们共同的上限是**一拍只演一个主体**。要一组元素一起动，此前唯一的办法是
`stagger`（见 `references/stagger.md`）——可 stagger 的语义是「每个元素各自完整
演一遍」：把总窗口按锚点分给各元素，每个从自己的起点走到自己的终点，观众读到的
是**逐个出现**。

动画十二原则里还空着的恰好是最后这一格：

| # | 原则 | 一句话 | 本仓库此前 |
| --- | --- | --- | --- |
| 1 | Overlapping Action 重叠动作 | 主体先动，附属部件晚半拍跟上，动作在时间上交叠 | 无 |
| 2 | Drag 拖曳 | 链上越靠后的部件滞后越大，能量逐节耗散 | 半条：`stagger` 只分起跑时刻，不分相位 |
| 3 | Follow-through 跟随 | 主体停了，附属部件才收干净 | 半条：`momentum` 只管单物体的形变晚半拍 |

2026 年前沿 MG 里的果冻链、柔性尾迹、级联跟随，都是这一档。它们与 stagger 的
差别**不是错峰多少**，而是所有元素共享**同一条位置曲线、同一个终点**：错开的是
相位，不是行程。stagger 排完最后一节才轮到下一个元素落定；拖曳链是全链在**同一拍
终点一起落定**，中间那一截是波，不是队列。

## 二、相位一直是隐含量，只是没被独立消费

`_ease.curve` 早已把钉固 GSAP 的缓动逐点实采下来；`stagger` 分配的是各元素的
**起跑偏移**，`_timeline.beat_positions` 管的是各拍的**绝对落点**，`momentum` 把
`f′(p)` 拿来驱动形变——时间一直被切开，只是每一份都绑在「一个元素」上。

这一档把相位单独提出来：`φ_i` 是链上第 i 节相对主运动的滞后，位置仍走同一条
`f(p)`，过冲幅度按 `decay^i` 逐节耗散。于是「峰值时刻随链序后移」不是调出来的
巧合，是结构上必然单调（判据因此能钉住，见第七节）。

与 `momentum` 正好正交：那一档在**速度域**消费 `f′(p)`，管一个物体的形状；这一档
在**相位域**消费 `f(p)` 的自变量，管一组物体的先后。两档都不改 `f`，都不另写一份
曲线实现——`references/momentum.md「被否掉的五个方案」` 里记过「两份互相对照的
实现一起错，测试照样绿」那笔账，这里照旧不欠。

## 三、链的几何：相位 → 重参数化 → 阻尼波

设链 `chain = [sel_0, …, sel_{N−1}]`，`sel_0` 就是 step 级 `target`。一条拍的总长
恰等于 step 级 `duration`，全部计算都在 `p = t / duration ∈ [0,1]` 上：

```
φ_i = lag · i/(N−1)                          相位，链首 0 → 链尾 lag
u_i(p) = clamp((p − φ_i)/(1 − φ_i), 0, 1)    局部进度
a_i = overshoot · decay^i                     阻尼幅度
h(u) = sin(2πu)·(1−u)²                       过冲核：h(0)=h(1)=h′(1)=0
s_i(t) = D · [ f(u_i(p)) + a_i · h(u_i(p)) ]  D = distance，带符号
```

- **重参数化不是数值修饰**。若只写成 `f(p − φ_i)`，链尾在 `p=1` 时只走到
  `f(1−φ) < 1`，最后一节永远停在半路——那不是拖曳，是没演完。除以 `(1−φ_i)`
  之后 `u_i(1)=1`，所以 `s_i(1)=D` 对每个 i 都成立，**全链同刻落定**。
- `h` 的双根 `(1−u)²` 保证落地时过冲与其一阶导**同时归零**；否则末端元素是带着
  速度撞停的，读成「抽了一下」。前半周为正（越过落位）、后半周为负（回弹），
  配合 `decay^i` 是一条只传一次、能量递减的欠阻尼波，**不需要积分、不需要保存
  上一帧**。
- `f` 只收无过冲、终点速度归零的 `out` / `inOut` 档。`none` / `linear` 的
  `f′(1)≠0` 会让全链撞停；`.in` 档起点慢终点最快，与 `h` 的「先过冲后回弹」
  叠成两次动作；过冲族与弹簧的位移会反号，语义整个翻掉。红线在 `_drag.validate`，
  和 `_momentum.validate` 一样放在**消费侧**——`--set` 能把旋钮调坏，护栏不能指望
  写文档的人记得。
- 位移与过冲共用一条 `f`，所以 `deviation(p, i)`（偏离主曲线的最大量）就是
  `|D|·a_i·max h`，必然随 i 不增。判据读的是这个量，不是配置里写的 `decay`。

**链序必须显式**：`target` 写 `.class` 时 DOM 顺序不是语义，而离散 `tl.set` 没法给
同一选择器的不同命中元素写不同数值。所以 `drag.chain` 收一列有序 `#id`；链序错了
就是导演意图错了，生成期按文件当场拦（第六节）。

## 四、被否掉的六个方案

**A. 用 GSAP 原生 `stagger` 实现。** stagger 把整条拍复制给每个元素、只改
`delay`：每个元素各自完整演一遍，末端不会共同落定；更关键的是它的 delay 在 GSAP
内部，**不进逐帧采样**，判据只能从 Python 侧另写一份「应该生成什么」去对账，
正是这一仓库反复拒绝的「对着另一份实现自证」。

**B. 渲染端 `onUpdate` 每帧做低通滤波。** 最像真物理阻尼链：每节的位置 = 上一节
位置的一阶滞后。可它靠**累计状态**，逐帧 `seek()` 下第 N 帧与直接跳到第 N 帧
对不上；`params` 白名单禁 `random`、弹簧必须闭式解，都是同一条理由。这里走
`morph` / `momentum` 的老路：生成期按帧率采样成离散 `tl.set`，渲染端零脚本、
零回调，每一帧都是时间的纯函数。

**C. 让 `.class` 的 DOM 顺序定链序。** 省事，但 SVG 里同 class 的节点未必同父、
未必按视觉顺序排列；作者换一个节点，链序就悄悄变了，而成片里只表现为「看着有点乱」。
链序是导演意图，必须写在稿里。

**D. 相位平移不重参数化。** 见第三节：`f(p−φ)` 会让链尾永远落不到位。这是本档
最容易「看起来对、判据也全绿、成片短一截」的一类错，所以第七节把「全链末帧
精确等于 `distance`」钉成产物级判据。

**E. 允许 `stagger` / `repeat` / `yoyo`。** 链序已在 `chain` 里、相位已由 `lag`
定，再叠 stagger 就是把一条链拆成几条各自起跑的动作；重放会把「一起落定」演成
「又冲一次」，且采样跨度与 `beat_span` 游标分家，门禁报的时刻与成片差几倍。
契约层直接拒，与 `momentum` 同一口径。

**F. 给每个链元素单独写一条拍。** 手抄同步：改一个 `duration` 或 `distance`，
五处都得跟着改，抄错一条只表现为「这一节慢了半拍」，`look.md` 点名过这类
「手抄同步」的坏法。链的意义就是让它们只有一处真源。

## 五、契约与旋钮

`drag` 是第八种独立「演」，与 `type` / `count` / `morph` / `from` / `to` / `set` /
`draw` / `momentum` 互斥，必配 `target` 且 `chain[0]` 必须等于它。**没有任何新的
稿件键、没有 `--ctv-*` 令牌**：只有写了这一拍的 SVG 元素会演，缺省全片一个字节
都不变（四份 golden 快照照旧）。

```json
{"seg2": {"src": "images/seg2.svg", "animate": {"steps": [
  {"at": 0, "target": "#head", "duration": 1.2,
   "drag": {"chain": ["#head", "#mid", "#tail"],
            "axis": "y", "distance": -160, "ease": "power3.out",
            "lag": 0.22, "overshoot": 0.12, "decay": 0.72}}
]}}}
```

| 旋钮 | 缺省 | 管什么 |
| --- | --- | --- |
| `chain` | 必填 | 有序 `#id` 列表，链长 2~8；链序就是波传下去的方向 |
| `axis` | 必填 | `"x"` / `"y"`：全链沿同一轴位移 |
| `distance` | 必填 | 主轴位移（SVG 用户单位，带符号），非零；**全链共用** |
| `ease` | `power3.out` | 主运动曲线；只收无过冲 `out` / `inOut` |
| `lag` | `0.22` | 链尾相位滞后 / 总时长，相位上限 0.35；0 = 全链同步 |
| `overshoot` | `0` | 链首过冲幅度 / 行程，过冲上限 0.30；0 = 纯位移 |
| `decay` | `0.72` | 逐节阻尼系数（0~1）；1 = 全链同幅，0 = 只有链首过冲 |

`lag=0` 且 `overshoot=0` 仍是一条合法的拍：全链同步的纯位移，等价于给每个元素
写一条同款 `to`。**红线不是模板旋钮**：相位上限 0.35、过冲上限 0.30、链长带、
采样帧数带（12~240）写在 `_drag`，不放进 `_template.py`，`--set` 碰不到。

`duration` 仍在 step 级（`_timeline` 的口径），`at` / `at_time` / `delay` 照旧；
`drag` 属于 `_WHOLE_BEAT_KEYS`，相对链 `at_time:"+N"` 的游标按**整段**推进——
链尾的相位已经吃进这一拍里，游标若停在起点，下一拍会压在还在传的波上。

## 六、生成期会拦什么

| 现象 | 级别 | 怎么消 |
| --- | --- | --- |
| `drag` 与 `from` / `to` / `set` / `draw` / `momentum` 同拍 | error | 两条时间线抢同一条 transform 通道，删掉一边 |
| `chain` 不是 2~8 个 `#id`、含 `.class`、有重复 | error | 链序要显式且唯一；一组同 class 元素没法分别写值 |
| `chain[0] != target` | error | 链头就是这一拍的目标，接续烘焙只认 step 级 target |
| `chain` 里某一节在 SVG 里找不到 | error | 按文件拦：落空一节只会静默少一段跟随波 |
| `chain` 含 `#cam` | error | 相机层收尾由折层负责，给它演拖曳链接续页会静默弹回原位 |
| `axis` 不是 x/y、`distance` 为 0 或非有限数 | error | 位移必须有方向与行程 |
| `ease` 是 `none` / `linear` / `.in` / 过冲族 / 弹簧 / `steps` | error | 换 `power3.out` 一类终点速度归零的档 |
| `stagger` / `repeat` / `yoyo` 挂在 drag 上 | error | 见第四节 E |
| 全链落点不精确、相位不递增、阻尼不衰减 | error（生成期） | `_drag.is_well_formed` 在发射 `tl.set` 前拦下 |

产物形如每个链成员一组等帧距的 `tl.set`：

```js
tl.set("#img-seg2 #head", {"y": 0.0}, 2.40)
tl.set("#img-seg2 #mid", {"y": 0.0}, 2.40)
tl.set("#img-seg2 #tail", {"y": 0.0}, 2.40)
...
tl.set("#img-seg2 #head", {"y": -160.0}, 3.60)
tl.set("#img-seg2 #mid", {"y": -160.0}, 3.60)
tl.set("#img-seg2 #tail", {"y": -160.0}, 3.60)
```

## 七、判据落在哪

`tests/test_drag.py` 一个文件压完，判据全部**从产物里抠补间来读**，不在 Python
侧另写一份「应该生成什么」：

| 判据 | 拦的是什么 |
| --- | --- |
| `state_at` 是纯函数、端点归零、全链 `s_i(1)=D` | 逐帧 seek 下靠累计状态算出的第 N 帧对不上；链尾停在半路 |
| 相位单调（半程时刻随链序严格后移） | 链序被字典序洗掉、或相位根本没写进产物 |
| 阻尼衰减（偏离量随 i 不增）、过冲红线 | 渲染端另写了一份包络；尾部比链首还夸张 |
| 契约层互斥 / 红线 / 白名单 / `chain[0]` | 两条时间线抢通道、`--set` 调坏旋钮、非法曲线混进成片 |
| **产物级对账** | 从 HTML 抠出的 `tl.set` 序列，锚点、帧数、逐帧变量必须与 `_drag.frames` 逐项相等；两画幅各验，两次生成字节相同 |
| 作用域与跨段接续 | 没写 drag 的页零新增补间；接续页**链上每一节**都烘焙出 `translate(0,-160)` |
| 相对链游标 | `at_time:"+N"` 按整段推进，不把下一拍压在还在传的波上 |

跨段接续是最容易漏的一处：烘焙只认 `to` / `set` / `attr` 时，不认新档就只有
链头在场，链尾在下一页第 0 帧会弹回原位。`_stage_carry._settle_step` 为此把
`chain` 逐节折成 `x` / `y` 平移；过冲核 `h(1)=0`，本来就没有姿态可搬。

## 八、什么时候不要

- **只动一个元素**：链长不到 2 就没有相位可传，用普通 `to` 就够。
- **一组元素本就该逐个出现**（清单、agenda 行、逐条结论）：用 `stagger` 或
  `type.decode` 的解码波，别用拖曳链硬把它们读成一根绳上的结。
- **文字、表格、数据图**：它们要按读序逐行落定，相位滞后会把一行字读成抖动；
  这一档适合图形主体（球、卡片、图标、链条节点）。
- **该段已经写了别的拍在动同一元素**：互斥是契约层硬拦，别绕。
- **拍太短**：0.3s 内相位差被压成几帧，读到的是「抖了一下」；这一档至少给 0.8s。
- **整页画布的贴边内容**：链上每一节都会走完整段行程，先按 `references/canvas.md`
  留够安全边距——出画 warn 是按收尾位算的，中途的过冲还要再多一截。

写完跑 `run.py --until html`，产物里应当看到每个链成员一组等帧距的 `tl.set`，
首帧全为 0、末帧全等于 `distance`；两帧之间的同一时刻，链上越靠后的元素位移
越小（波还在传）。全片动得对不对仍要按 `look.md`「交付前四道」翻 contact sheet——
判词只证明「没有明显坏」。
